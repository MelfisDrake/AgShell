# Сообщения об уязвимостях — подготовка

[English](SECURITY.md) | Русский

**Блокер публичного открытия:** работающий приватный канал сообщений не проверен. Этот документ — подготовительный draft. Не публикуйте детали уязвимостей, учётные данные или exploit-вложения в обычных issues. Перед открытием владелец должен включить и проверить GitHub private vulnerability reporting либо предоставить другой проверенный приватный контакт; этот аудит настройку не меняет. Приватный advisory endpoint или email пока не обещаются.

## Область

AgShell — экспериментальный продукт 0.x. Гарантированного срока security-поддержки, ответа и политики backport нет. В сообщении нужны версия, источник поставки, последствия, минимальное воспроизведение и предпосылки с очищенными доказательствами. Чувствительные подробности сохраните для проверенного приватного канала.

CLI и локальный управляющий канал могут читать терминалы и выполнять команды от имени пользователя. Другие процессы того же пользователя не изолированы от этих полномочий. Хуки, плагины, свои команды, SSH-хосты и локальные HTML overlays должны быть доверенными. Кнопки локальной страницы могут вызывать команды AgShell даже без её JavaScript; отключение JavaScript не делает недоверенный HTML безопасным. Browser overlay и его постоянный профиль могут хранить чувствительные веб-сессии. Не запускайте AgShell с повышенными правами только ради терминала.

Действие владельца после создания выбранного публичного репозитория: Settings → Security → Private vulnerability reporting → Enable; проверить форму «Report a vulnerability» из аккаунта без прав владельца. Только после этого заменить подготовительный текст инструкцией проверенного канала.
