# AgShell

[English](README.md) | Русский

Терминал для Windows, рассчитанный на работу с несколькими кодинг-агентами одновременно: сессии сгруппированы в именованные workspace, каждая сессия показывает статус своего агента (работает / ждёт / готово), а всё, что есть в интерфейсе, доступно через локальный API и CLI `agshellctl`, чтобы агенты могли сами управлять терминалом.

AgShell — самостоятельная Windows-реализация на C# по модели и соглашениям команд [umputun/agterm](https://github.com/umputun/agterm) (macOS, MIT), с отдельными адаптированными компонентами, скриптами и тестами. AgShell — отдельный проект и имя; он не связан с agterm организационно и не заявляет его одобрение. Атрибуция — в [third-party notices](THIRD-PARTY-NOTICES.md).

**Статус:** экспериментальный продукт 0.x; репозиторий готовится к публичному открытию. Проверенное использование ограничено Windows 11 x64 при 96 DPI. Перед обновлением сохраните работу шеллов и резервную копию состояния. SLA поддержки и совместимость со всеми системами не обещаются.

## Установка

Технические требования: Windows x64 с ConPTY (базовый API Windows 10 1809+) и Microsoft Edge WebView2 Runtime. Это технический минимум, а не заявление о проверенной поддержке Windows 10. Готовая self-contained сборка не требует отдельного .NET SDK; для сборки исходников нужны .NET SDK 10 и Node.js LTS.

- **Установщик** `agshell-<версия>-setup.exe` со страницы Releases будущего публичного репозитория (адрес ещё не выбран). Ставится на пользователя без прав администратора, добавляет `agshellctl` в PATH. По желанию сразу ставит хуки статуса агентов и скилл для Claude Code и Codex и регистрирует журнал событий AgShell (для этого спросит права администратора).
- **Portable** `agshell-<версия>-win-x64.zip`: распакуйте куда угодно и запустите `agshell.exe`. `agshellctl` в PATH, хуки и скилл ставятся из палитры действий (Ctrl+Shift+P): «Добавить agshellctl в PATH», «Установить хуки статуса агентов», «Установить скилл AgShell для Claude Code и Codex». При первом запуске то же самое предлагает окно приветствия. Повторный запуск безопасен: «Добавить agshellctl в PATH» ещё и убирает другие папки с `agshellctl.exe` из PATH пользователя, а из системного PATH — после запроса прав администратора Windows (только если они там есть; отмена запроса ничего не меняет), чтобы старая копия не находилась первой.

При обновлении с опубликованной 0.3.0 сохраните работу и резервную копию состояния. Закройте старые окна перед явной остановкой их общего `agshell.exe --host`: установщик не может надёжно заменить работающий старый хост. Его live-процессы не переносятся в 0.4.0. Сохранённые старые id панелей описаны в [справочнике](docs/agshellctl.ru.md).

Опубликованная 0.4.0 может удалить web/themes перед отказом заменить занятый файл; закройте AgShell перед повторным запуском этого установщика. Исправление установщика 0.4.1 восстанавливает прежние файлы после штатного отказа или отмены и сохраняет удаление устаревших web/themes при успешном обновлении. Для него нужно временное место под копию существующей установки. Если восстановление не завершилось, установщик сообщает, где сохранена резервная копия.

Черновые команды ниже требуют замены `OWNER/REPOSITORY` на выбранный публичный адрес. Скилл можно поставить и плагином из этого репозитория (только одним способом из двух, иначе непонятно, какую копию возьмёт агент):

```
claude plugin marketplace add OWNER/REPOSITORY
claude plugin install agshell@agshell

codex plugin marketplace add OWNER/REPOSITORY
codex plugin add agshell@agshell
```

Интерфейс на русском или английском: «Настройки» → «Общие» → «Язык», по умолчанию — как в Windows. Вывод `agshellctl` — на английском.

Будущие комплекты должны содержать `LICENSE`, `THIRD-PARTY-NOTICES.md` и `licenses/` с текстами лицензий включённых компонентов. При передаче portable сохраняйте их рядом с файлами программы.

Сборки не подписаны; SmartScreen может предупредить о неизвестном издателе. Перед решением о запуске проверьте источник загрузки и опубликованный digest файла. Перед удалением снимите хуки из `~/.claude/settings.json` (и `~/.codex/config.toml`, расширения Pi и плагина OpenCode, если ставили), иначе агенты будут звать отсутствующий `agshellctl`.

Удаление убирает программу, её ярлыки, пункты Проводника и каталог из пользовательского PATH. Состояние, конфигурация, свои темы, хуки и скиллы сохраняются. Неиспользуемые копии демонов удаляются; занятые копии остаются в `%LOCALAPPDATA%\agshell\live` до удаления после завершения их процессов.

## Статус выпуска и границы проверки

Это локальный кандидат исходников для нового публичного репозитория; адрес и публичные загрузки ещё не выбраны. Прежний частный выпуск 0.5.0 сохранён отдельно, его assets не менялись. В ней появились общий заголовок с нативными кнопками окна, режимы normal/compact/hidden и toolbar для сессий, сплитов, overlays и Quick Terminal. Проверены опубликованный portable и обновление на одном рабочем Windows 11; это не сертификация установщика на чистой машине.

Windows 10, другие и смешанные DPI, IME, accessibility, масштабирование текста, высокая контрастность, несколько мониторов, сон/logoff/reboot и полная матрица графики/прозрачности не проверены. У прозрачности без blur есть известные ограничения. Прежние предосторожности обновления выше сохраняются. Совместимые live-демоны могут сохранить шеллы; несовместимые сборки требуют явного перезапуска, сохранение процессов не гарантируется.

Настройки видимости и прежние действия меню, API и keymap сохраняются.
