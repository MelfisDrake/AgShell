# agshellctl

English | [Русский](agshellctl.ru.md)

`agshellctl` drives a running AgShell over a named pipe. Its commands, arguments and reply format follow `agtermctl` from [agterm](https://agterm.com/commands.html), so agent scripts and skills carry over with minimal changes.

`agshellctl.exe` sits next to `agshell.exe`, and AgShell adds that folder to the `PATH` of every session. From WSL the command is called as `agshellctl.exe`.

## General rules

- **A target** (`--target`, `--workspace`, `--after`, `--before`) is an id, a unique git-style id prefix, or `active`. Targets are never looked up by name. As in agterm, a prefix that fits several ids, in this window or across windows, is the error `ambiguous session prefix '<prefix>' → <first 8 characters of each>` (`workspace`, `window` likewise).
- **`--target` defaults to `active`:** for a session that is the selected session; for a workspace, the one a new session would go to. That is a workspace just created, otherwise the selected session's workspace, otherwise the last one.
- **For a script to act on its own session** rather than the selected one, pass `--target $env:AGSHELL_SESSION_ID` (in bash `--target "$AGSHELL_SESSION_ID"`).
- **A window** (`--window id|prefix|active`) is accepted, as in agterm, by the commands that act in a window's tree; app-wide ones (`version`, `events`, `session wait`, `sidebar` visibility, mode and flagged layout, `quick`, `browser`, `keymap reload|list`, `restore`, `theme`, `config`, `hooks`, `recent list|clear`, `live` except `kill` and `attach`, `install`, `clipboard`) and `window …` refuse it as an unknown option. Without it a command goes to the window that holds its target (a session or workspace id or prefix), otherwise to the front one; `pick`/`ask result|cancel` go to the window where the dialog is open. `--window` is trimmed, and a blank one counts as not given.
- **Output:**
  - `new` and `duplicate` print the id of what they created;
  - batch `session close` and `session move` (two `--target` or more) print the number of sessions changed; as in agterm, a batch moves in sidebar order, and one moved to a workspace leaves out the sessions already there; at `--after`/`--before` the batch lands as one block, as a sidebar drop does;
  - other commands print nothing on success.
- **`--json`** prints the whole reply: `{"ok":true,"result":{...}}` or `{"ok":false,"error":"..."}`.
- **Errors** go to stderr. As in agterm:
  - a refusal from AgShell (`{"ok":false}`) is `error: ...` with exit code 1;
  - a failure of agshellctl itself (the pipe does not answer, the reply cannot be read, the request is too large) is `Error: ...` with exit code 1. A pipe that does not answer reads `connect(\\.\pipe\NAME) failed: <reason> — <hint>`, as agterm's: the reason is that the pipe does not exist (reported at once) or that all its instances stay busy for 2 seconds; the hint, from the state folder's lock (`agshell.lock`, held by the running AgShell, as agterm's flock; checked only for the pipe of this state folder), says that the pipe owner is present but not accepting connections, or that AgShell may be stopped;
  - a usage error (an unknown option, a missing or wrong argument) is refused before anything is sent (for example `--pane must be left, right, or scratch`, `--axis must be vertical or horizontal`, two placements for `session new`/`session move`): `Error: ...`, then the command's `Usage:` line and a `--help` hint, exit code 64. The `Usage:` line is agterm's: options and arguments in agterm's order, `--pipe`, `--json` and `--window` where agterm puts its connection options; with more than 12 only the arguments and required options remain, after `[<options>]`; a command with subcommands is `<subcommand>`, and an error in a command that runs its default subcommand shows that subcommand's line. As in agterm, `--pipe`, `--json` and `--window` belong to the command and go after its name; only in AgShell, `--pipe` and `--json` may also go before the command's name (`agshellctl --json tree`), but not before or after a group's name (`agshellctl session --json new` is an unknown option). An option the command does not take is an unknown option wherever it stands, before an argument or before the command's name too (`agshellctl --json clipboard set x`).

  Success exits with 0.
- **`--pipe NAME`** sets the pipe. Without it `AGSHELL_PIPE` from the session's environment is used, then the default pipe.

## Session environment

| Variable | Value |
| --- | --- |
| `AGSHELL_ENABLED` | `1` inside AgShell |
| `AGSHELL_SESSION_ID` | the session id |
| `AGSHELL_WORKSPACE_ID` | the workspace id when the shell started |
| `AGSHELL_WINDOW_ID` | the window id |
| `AGSHELL_PANE` | the pane when the shell started: `left`, `right`, `scratch` |
| `AGSHELL_PANE_ID` | a stable id of this terminal: it stays with it when panes are swapped and when the split takes the place of a closed left pane |
| `AGSHELL_PIPE` | the name of the control pipe |
| `TERM_PROGRAM`, `TERM_PROGRAM_VERSION` | `agshell` and its version |
| `COLORTERM` | `truecolor`, as Ghostty sets it |

In WSL these variables arrive through `WSLENV`.

**`--pane-id`** (as in agterm) is accepted by `session status`, `session text`, `session restore`, `session restart`, `session hud` and `ask`: the pane is found by `AGSHELL_PANE_ID` wherever the terminal is now, and it overrides `--pane`. An unknown id without `--pane` is the error `unknown pane id`, except for `session status`, which then writes to the left pane. The status hooks pass it themselves. As in agterm, ids (sessions, workspaces, windows, surfaces, events) are written in upper case and read in any case. In `tree --json` a session has `surfaces`: its panes, a scratch that is shown or still running, and the program overlays on screen, with ids of the form `surface:<session>:<pane>`, with the fields `kind` (the pane's name), `active`, `visible`, and `paneID` on panes; panes in live mode also have `lead`: `leader` (this window sets the size the program sees), `unowned` (nobody leads the pane) or `follower` (another window or machine leads it, and the pane is covered here).

## Tree

```
agshellctl tree                 # workspaces and sessions with id, shell and directory; * marks the active ones
agshellctl tree --json          # the same for scripts
agshellctl version                                 # the app's version, then client: <path of this agshellctl>, as agterm
```

As in agterm, the AgShell menu has “About AgShell” (the version, the short commit and a link to the repository), and the Help menu has “Developer Documentation…” (this reference on GitHub, in the interface language).

## Windows

```
agshellctl window new [name] [--minimized]         # a new window with one workspace and session; prints its id
agshellctl window list                             # all windows, open and closed: "id  name [open] [active]", as agterm; frames in --json
agshellctl window select|close|delete|zoom|fullscreen [window]
agshellctl window rename <window> <name>
agshellctl window minimize [window] [on|off|toggle]
agshellctl window resize [window] --width W --height H   # prints the size applied
agshellctl window move [window] --x X --y Y [--display N]
agshellctl window go --to next|prev
```

As in agterm:
- A window is its own set of workspaces and sessions with its own state file (the first window is `state.json`, the others `windows\<id>.json`). The window list is `windows.json`; when it cannot be read, as in agterm, every window file comes back as an open window named “window N” (`state.json` first, then the others by file name), with none of their remembered programs run, and a window file the list does not name keeps its live shells out of `live prune`. An unreadable index is protected from writes until a successful read after restart; a damaged or incompatible index is kept in a unique `.corrupt-…` or `.version-N-…` backup before recovery replaces it. The same read/write protection and backup policy applies to per-window state files; a backup preserves the original for manual recovery, not automatic support for another schema. Recently closed items are shared by all windows (`recent-closed.json`).
- `close` closes a window but keeps it: `select` opens it again with the same sessions (fresh shells; in live mode the same ones). Alt+F4 closes the current main window with its confirmation; in quick it hides only quick, and in Settings it closes only Settings. Closing the last window quits AgShell, and it opens again on the next launch. “Quit AgShell” (Ctrl+Shift+Q, `quit`) asks, as agterm's ⌘Q does, “This closes N windows and M sessions[, ending all running shells].” and quits with every open window kept open, so the next launch opens them all; a Windows logoff or shutdown quits the same way without asking.
- `close` returns success (exit code 0; `--json`: `ok: true` with the window id) after closing the window. For the last window, AgShell sends this reply before stopping its control server and exiting. Other open windows and their sessions stay running. A transport failure remains an error.
- `delete` removes a window with its sessions; the last window cannot be deleted.
- `zoom` maximizes and restores; `fullscreen` is frameless over the taskbar. A minimized window comes back as it was (maximized or full screen too); `minimize` refuses a full-screen window only when it has to change it.
- A saved frame that no longer fits (a monitor was disconnected) comes back whole on the monitor it overlaps most, else on the primary one. `move` keeps an 80-unit strip of the window on the monitor, above its top edge too. `list` gives a maximized window's frame as it is on screen.
- The window in front is saved in `windows.json` and is in front again at the next launch. Closing a window cancels its open `pick` and `ask`: a waiting script gets `cancelled`. Retained results accept the owning `--window` id or prefix after the window closes; another window cannot read or cancel them. On the last window, the control pipe stays up for at most two seconds to deliver pending dialog cancellations, then the app exits; with no pending dialogs it exits immediately. When Windows ends the session, every window opens again next time.
- Sizes and coordinates are in WPF window units (pixels at 100 % scaling), from the monitor's work area without the taskbar. Monitors are numbered from 0: the primary first, the others left to right.
- Settings, keys, hooks, the live daemons and the quick terminal are shared by all windows.
- `tree` prints one window's tree; `--json` has `windowId` and `windowName`.
- As in agterm, the File menu has “New Window” (`new_window`), “Open Window” (all windows; a closed one opens), “Rename Window…” (`rename_window`) and “Delete Window” (`delete_window`); the command palette and the Navigate menu have “Next/Previous Window” (`next_window`/`previous_window`), and the palette an “Open Window: …” per closed window. Only “New Window” has a default key, Ctrl+Alt+N (agterm's ⌘⌥N).
- A named window shows its name in the title after the session name, as agterm's, in the window's own title bar too; the “Window name” switch in the interface settings hides it there.
- The setting “Hide the sidebar in inactive windows” (Interface tab): as in agterm, when another window comes to the front it shows its sidebar and the others hide theirs; this is saved and shows in `window list --json`. Switching to another app changes nothing.

## Workspace

```
agshellctl workspace new [name] [--collapsed]     # prints the id; joins the focus while the filter is on, unless --collapsed
agshellctl workspace rename <name> [--target W]
agshellctl workspace delete [--target W]          # with its sessions; the last one cannot be deleted
agshellctl workspace select [--target W]          # its first session; an empty workspace becomes current

agshellctl workspace move --to up|down|top|bottom [--target W]
agshellctl workspace collapse|expand [--target W]
```

## Sessions

```
agshellctl session new [--cwd DIR] [--name N] [--shell pwsh|powershell|cmd|wsl:<distribution>]
                     [--workspace W | --workspace-name NAME [--create-workspace] | --after S | --before S]
                     [--no-select] [--command "program arguments" [--wait]]   # prints the id; --no-select creates it in the background
agshellctl session duplicate [--target S]            # a new session right after the original, with its shell, in the focused pane's directory
agshellctl session close [--target S]...             # several --target are allowed
agshellctl session select [--target S]
agshellctl session go --to next|prev|first|last|next-attention|prev-attention
agshellctl session rename <name> [--target S]        # an empty name goes back to the name from the directory
agshellctl session move <workspace> [--target S]...  # move to the end of a workspace
agshellctl session move --after S2 [--target S]...   # place after S2 (or --before), in its workspace
agshellctl session move --to up|down|top|bottom [--target S]
agshellctl session reveal [--target S]               # open the directory in Explorer
agshellctl session restart --pane left|right | --pane-id ID [--command "line"] [--target S]   # a new shell in place of the current one
```

Without `--cwd` a session opens in the home directory, and it always has a directory (except WSL, whose home is the distribution's). For WSL the directory is a Linux path (`--cwd /tmp`).

**`--command`**, as in agterm, runs a program instead of the session's shell (in a WSL profile, inside the distribution). As agterm runs it through `/bin/sh -c`, the line goes through a shell: `cmd.exe /d /s /c` (for a PowerShell profile too), and `sh -c` inside the distribution for a WSL profile, so `&&`, variables and redirections work in that shell's syntax, and the exit status is the line's. The same goes for `session scratch --command` and for the program of `session overlay open`. When the program ends, its pane ends, as any shell does, whatever the exit code: the session closes, or a split takes the main pane's place; with `--wait` the pane stays with the last output until any key (or `session type`). As in agterm, a swap takes the command and `--wait` along with the program to the other pane. The command is saved (`command` and `commandWait` in `tree --json`): in rerun mode a restored session (at launch, in a reopened window, from Recently Closed) runs it again unless a `session restore` pin or a program remembered at quit overrides it, even one the denylist drops; in none mode it opens with a plain shell. A split the command was swapped into runs it the same way. As agterm's SpawnPacer, the panes of the restored sessions (the main pane and a shown split, in any restore mode, live and another machine's rows included) start one every 120 ms at launch in sidebar order, the selected session's at once and a session turned to next. In live mode the command is typed into the live shell once at creation, and the session stays open after it. A duplicated session does not get the command.

**`session restart`**, as in agterm, replaces the shell of one pane (`--pane left|right` or `--pane-id`; without them, `session.restart requires --pane-id or --pane`; scratch gives `session.restart does not address the scratch pane`) and runs the line from `--command` in the new shell (up to 4096 bytes; an empty line or one with control characters is an error), after which the shell stays interactive. Without `--command` the new shell runs again the program that runs in the pane now; if the pane holds only a shell (`no replayable foreground program: NAME holds the pane`, NAME the innermost shell, in WSL the one leading the terminal's foreground group, else the pane's own shell, which as agterm's daemon leader is never taken for the program, whatever its arguments), the program cannot be read (`the pane's foreground program cannot be read`), its line has control characters or it is in `restore-denylist.conf`, nothing changes and an error comes back. Unless the pane is being held after a live connection failure, a pane whose shell is not running (it is waited for up to 5 seconds) is refused with `the pane's shell is not running`; a refused replay ends with `; pass --command to name the line. nothing was changed`, as in agterm. The pane keeps its place and `AGSHELL_PANE_ID` and starts with an empty screen. The reply comes once the new shell is up: `restarted left pane: shell OLD -> NEW`, in `--json` a `restart` with `oldPid`, `newPid` and `replayedArgv`. As in agterm, the program run again starts in the directory it was running in; when that cannot be read, `the foreground program's working directory is unavailable`. Before ending the shell the restart notes its foreground program (on Windows the program under the shell and its child processes, in WSL the terminal's foreground group), by id and start time; when the process table cannot be read, `the process table cannot be read, so the old program could not be tracked; nothing was changed`. The new shell starts only once that program is gone: it gets a second after the console closes, then it is killed and gets half a second more; if it still runs, the pane closes with `the old shell ended (pid N) but its program is still running; nothing was started and the pane was closed`. A pane that changed meanwhile gives `the old shell ended (pid N) and the pane changed during the restart; nothing was started`. Difference from agterm: the command works outside live mode too (AgShell manages its own shells in every mode).

A pane held after a live start or connection failure can be restarted explicitly from the menu or with `session restart`. Without `--command` it starts a fresh shell; it does not pretend to restore the lost program. The reply omits `oldPid` when no old shell was observed. An incomplete or conflicting pane inventory refuses the restart; an existing daemon must confirm that its old shell ended before a replacement is started.

## Input and reading

```
agshellctl session type "dir`n" [--target S]         # PowerShell: `n is a newline
agshellctl session type $'make test\n'               # bash
agshellctl session type "x" --pane-id $env:AGSHELL_PANE_ID   # the terminal by its stable token; --select is accepted, as in agterm
echo 'make test' | agshellctl session type --stdin   # stdin must be valid UTF-8 (otherwise a usage error, as in agterm)
agshellctl session text [--target S]                 # the visible screen
agshellctl session text --lines 50                   # the last 50 lines, scrollback included
agshellctl session text --all                        # the screen and all scrollback
agshellctl session copy [--target S]                 # the selected text of the active pane; the clipboard is untouched
agshellctl session select-all [--target S]           # select the whole buffer of the main pane
agshellctl session paste [--pane P] [--target S]     # paste the clipboard, as Ctrl+V; Enter is not pressed
agshellctl clipboard set "text"                      # put text on the clipboard; without an argument, from redirected stdin byte for byte
```

- `type` turns every newline into Enter. The last Enter is sent 10 ms after the text: otherwise Claude Code takes it as part of a paste and does not send.
- `type` into a session whose shell has ended returns an error.
- `text` returns the text as the terminal shows it. Wrapped lines are joined, empty lines at the end are dropped.
- Full-screen programs (vim, htop, Claude Code) have no scrollback, so only the current screen is read.
- `copy` without a selection returns the error `no selection`; for a session not shown yet, `copy`, `select-all` and `paste` answer `session not realized`.
- `clipboard set`, as in agterm: without an argument the text is read from stdin byte for byte, but only when stdin is redirected (when it is a terminal the error is `give the text as an argument or pipe it on standard input`, not a wait); empty text is `nothing to copy`; in base64 the text must fit into 8 MB minus 64 bytes, otherwise `text is too large to copy through the terminal: N bytes encoded, the limit is 8388544`. Pass text starting with `-` through stdin or after `--`. A pane whose daemon no longer keeps its shell is `this pane has no live shell…` with exit code 1; exit code 0 does not mean any terminal accepted the text.
- `clipboard set` sends the text through the pane it runs in, as OSC 52: every terminal that shows that pane sets its clipboard, AgShell on another machine included. As in agterm, the command talks to the pane's live daemon, not to the window, so it works with the AgShell window closed too. Each terminal decides by its own setting “Programs may write to the clipboard” (on by default; it also allows OSC 52 for any program). Outside the main or right pane of live mode (scratch, quick terminal, overlay, the main pane's overlay included, another restore mode) the command refuses: `this pane has no live shell`. The pane is the one whose shell ran the command: its daemon gives the shell `AGSHELL_LIVE_PIPE`, as zmx gives `ZMX_SESSION`, so swapped or moved panes do not confuse it; a value that is not one of this state folder's daemons is refused. The daemon answers whether its shell is there, and a missing one is `this pane has no live shell`. As zmx's inject, the sequence also goes into the daemon's terminal, so `live screen` and a window coming back see it, and while a window shows the pane, ConPTY redraws it as after a size change. As in agterm, it takes no `--pipe` or `--json`.
- **What programs may ask of the terminal** (as Ghostty under agterm): a background set with OSC 11 colors only that pane, at the window's opacity, until OSC 111 gives it its own color back, and `OSC 11 ; ?` answers with the color on screen; OSC 22 sets the mouse pointer to a CSS cursor name (empty for the terminal's own); the Kitty keyboard protocol (`CSI > flags u` and the rest, a stack for each screen) encodes keys as Ghostty does, so Shift+Enter, Ctrl and Alt chords and Esc reach Claude Code and Codex apart from plain Enter and text; `CSI ? 996 n` answers whether the system is dark or light, and after mode 2031 every change is reported; with Transparency effects off in the Windows settings the window is opaque in the theme's color, and the opacity setting is kept for when they come back. Theme files are read as Ghostty reads them: quoted values, `#rgb`, `#rrggbb` and the other forms of Ghostty, `rgb:r/g/b`, X11 color names (Ghostty's rgb.txt, so `green` is #00ff00), an empty value resetting a key, and Ghostty's own background and foreground when a theme sets none. An explicit change of the font or the theme, and reloading ghostty.conf, reset every session's Ctrl+/- size, in closed windows too, as in agterm; the system switching light and dark keeps them.
- **Selection and paste** (as Ghostty in agterm): a mouse selection is copied to AgShell's own selection clipboard, and the middle button pastes it (while a program reads the mouse the button is the program's, and Shift takes it back). Ctrl+C or Ctrl+Shift+C copies to the clipboard and keeps the selection; Ctrl+Shift+A selects everything (agterm's Cmd+A: Ctrl+A belongs to the shell). Files copied in Explorer paste as their paths, quoted for the pane's shell (`/mnt/c/...` in WSL), and a program reading the clipboard gets them the same way; text and links dragged onto a terminal go in as a paste. An IME composition under way is committed before `session type`, a drop or a paste, so the half-typed word does not land after them. As in agterm, the click that brings an inactive window back reaches the terminal only with the left button, so a right click does not paste and a middle one does not paste the selection; with “Hide the sidebar in inactive windows” on, that click only brings the window back. AgShell takes a press that comes within 100 ms of the window coming to the front, with no key between, for that click.
- **Programs and the clipboard** (as agterm's, through Ghostty's rules): OSC 52 writes follow “Programs may write to the clipboard”; an OSC 52 read (`52;c;?`) and a Kitty clipboard protocol read (OSC 5522) ask first: “Allow a program to read the clipboard?” with Allow, Deny and “Don't ask again this session” (remembered until AgShell quits, apart for reads and writes). Prompts of one pane wait behind one. Tab and Shift+Tab keep focus within the clipboard prompt. Esc denies only the current request, ignores the remember box and does not reach the terminal. A denied OSC 52 read gets empty contents, a denied Kitty read `EPERM`. Kitty writes come in chunks with aliases and every MIME type: text goes on the clipboard as text, other types under their MIME name (PNG also as `PNG`); a Kitty read gets only text, and only when it names `text/plain`; asking just for the list of types (`.`) needs no prompt. Mode 5522 turns a paste from the clipboard (Ctrl+V, right click, `session paste`) into a Kitty paste event with a one-time password for one read. OSC 52 `s` goes to AgShell's own selection clipboard, not the system one. As in Ghostty, an OSC 52 answer ends with ST, and a Kitty clipboard answer with the terminator its request came with (BEL or ST).
- **Text from accessibility tools** (as agterm's): a tool that sets the terminal's value through UI Automation types the text in; text with a line break, a tab or another control character goes as a paste, so with bracketed paste on (mode 2004) it does not submit the line nor fire completion.
- **ConPTY**: AgShell ships Windows Terminal's ConPTY (`conpty.dll` and `OpenConsole.exe` next to `agshell.exe`). The system one drops OSC 52 reads, answers DECRQM itself and drops OSC answers on their way to the program, so clipboard reads would not work with it. `AGSHELL_CONPTY=system` makes AgShell use the system one (to compare when something looks wrong); without the two files it is used anyway.

## Session background

```
agshellctl session background image C:\pics\logo.png [--opacity 0.3] [--fit contain|cover|stretch|none] [--position bottom-right] [--repeat]
agshellctl session background text DRIVER [--color #rrggbb] [--opacity 0.2] [--fit …] [--position …]
agshellctl session background color #1e2430
agshellctl session background clear
… [--pane left|right|scratch] [--target S]
```

As in agterm:
- Without `--pane` the background is the session's and survives restarts; with `--pane` a pane has its own (for example DRIVER and PEER for two agents in a split), and `clear --pane` returns it to the session's.
- A pane's background moves with its shell when panes are swapped and when the left one closes; a scratch background lives while the scratch is open.
- An image is PNG or JPEG. From WSL a `/home/…` path is read as a file of the session's distribution, `/mnt/c/…` as `C:\…`. Position: `center`, the middle of a side (`top-center`, `center-left` and so on) or a corner (`top-left` and so on).
- An image or text is drawn under the transparent terminal grid, and the pane becomes opaque. A text is drawn bold into a picture first, as agterm's, so `--fit`, `--position` and `--repeat` act on it as on an image: `contain` stretches the text across the pane. A color honors the window transparency from the settings.
- `tree --json`: `background` and `paneBackgrounds` on a session.

## Splits, scratch, zoom

```
agshellctl session split [on|off|toggle] [--axis vertical|horizontal] [--target S]   # a second shell in the session
agshellctl session split close [--target S]          # close the split and end its shell
agshellctl session swap [--target S]                 # swap the panes; the shells keep running
agshellctl session lead [--pane left|right] [--target S]   # lead a live pane from here: the program gets this window's size
agshellctl session focus left|right|other [--target S]
agshellctl session resize --split-ratio 0.6 [--target S]   # the share of the left (top) pane, 0.05–0.95; prints the applied share
agshellctl session resize --grow-left 0.05 [--target S]    # nudge it: --grow-left|right|primary|split|top|bottom, exactly one
agshellctl session scratch [on|off|toggle] [--target S]    # one more shell over the session
agshellctl session scratch on --command "npm test" [--follow]  # run a program once in place of its shell (an open scratch is replaced)
agshellctl surface zoom [show|hide|toggle]           # the active pane over the whole window
agshellctl surface zoom [show|hide|toggle] --target surface:<session>:<pane>   # exactly this pane, even a hidden one
agshellctl surface cursor [--target active|surface:…|quick | --target S --pane-id ID]   # the cursor column, from 0
```

As in agterm:
- **A surface** is one terminal of a session: `surface:<session>:left|right|scratch|overlay|overlay-left|overlay-right` (the ids are in the session's `surfaces` in `tree --json`). `active` is the one the user works in: the session's overlay, otherwise the scratch, otherwise the focused pane's overlay, otherwise the pane itself.
- **`surface zoom --target surface:…`** zooms exactly that pane — a hidden split, a scratch, a pane under an overlay, or a pane of a session that is not selected, which stays unselected; selection, focus, split and scratch do not change. Any other target than `active`, `quick` or `surface:…` is `invalid surface: …`. `toggle` exits when that very pane is zoomed; `hide` with an id takes down only it. The zoom keeps its pane until it is left: a new selection, overlay, scratch or focus does not move it; it ends by itself when its pane is gone (the session or split closed, the scratch or overlay exited, the overlay hidden). Ctrl+Shift+Enter zooms the active surface and does nothing under a page. Entering a zoom closes the palette and ends the search of the selected and the zoomed session; in the quick terminal it does nothing while the active window holds a pick or an ask. What is zoomed is `zoomedSurface` in `tree` (`quick` when the quick terminal is zoomed); the font keys change the zoomed terminal.
- **`surface cursor`** prints the cursor column (`cursorColumn` in `--json`) without selecting or showing anything. With `--pane-id` the target is the session, and an unknown id is an error with no fallback to another pane.

The split works as in agterm:
- it is one session with two terminals and one row in the sidebar;
- a hidden split keeps running and keeps its focus: the focused pane shows maximized, and `session focus` or the focus keys switch which one;
- `--axis` with the same axis hides the split, with the other axis turns it;
- a new split opens in the main pane's directory and takes focus;
- the session's name follows the active pane's directory.

When a shell ends:
- the split's shell — the split closes;
- the main shell with the split open — the session moves on to the second pane.

The split, its axis, ratio and directory survive restarts.

The scratch opens in the session's directory, keeps running while hidden and does not survive restarts.

`session type` and `session text` take `--pane left|right|scratch`. By default `type` writes to the main pane and `text` reads the pane on screen; `session search`, as in agterm, works on the pane on screen, or on the one its open search is on. A shell knows its pane from `AGSHELL_PANE`.

| Keys | Action |
| --- | --- |
| Ctrl+Shift+D / Ctrl+Shift+E | Vertical / horizontal split |
| Ctrl+Alt+← / → | Focus the left / right pane |
| Ctrl+Shift+J | Scratch |
| Ctrl+Shift+Enter | Zoom |
| Ctrl+Shift+W | Leave zoom, otherwise hide the scratch, otherwise close the session |

The split divider can be dragged with the mouse; a double click evens the panes. As in agterm, the split keys, the title bar button and “Close Split” from the window do not change panes hidden behind a cover: over a shown scratch they only hide it, under a program or page over the whole session they do nothing. `session split` acts behind either cover.

## Overlay, HUD and quick terminal

```
agshellctl session overlay open "<program>" [--cwd DIR] [--size-percent N [--width PT] [--height PT]] [--background-color #rrggbb]
                                            [--wait | --block] [--follow] [--target S]
agshellctl session overlay close | result | text [--target S]
agshellctl session overlay resize (--size-percent N [--width PT] [--height PT] | --width PT [--height PT] | --height PT | --full) [--target S]
agshellctl session overlay hide|show|toggle [--pane left|right] [--target S]   # hide without closing; prints hidden or shown
agshellctl session hud [open] "message" | --file F [--detail T] [--spinner] [--spinner-style bar|braille|circle|blocks|dot|none]
                     [--position top-left|top-center|…|bottom-right] [--hide-after SEC] [--size-percent N] [--markdown]
                     [--background-color] [--text-color] [--font-size 6-72] [--sticky] [--no-frame] [--pane left|right | --pane-id ID] [--target S]
agshellctl session hud update "message" | --file F [the same, except --background-color and --font-size] ; session hud close [--target S]
agshellctl quick [show|hide|toggle] ; quick type "text" | --stdin ; quick text [--lines N | --all]
agshellctl surface zoom [show|hide|toggle] --target quick   # the quick terminal over the whole screen
```

**An overlay** is a program in a temporary terminal over the session, as in agterm (without `--cwd` it starts in the main pane's directory, whichever pane has focus):
- the shell under it keeps running, and when the program ends the overlay goes away;
- the program runs as is, without a shell: wrap shell syntax in `pwsh -c "…"` or `sh -c '…'`;
- in a WSL session the program runs in the same distribution, so `htop` and `lazygit` are found;
- `--size-percent` makes a floating framed panel; `--width` and `--height`, as in agterm, set its content width or height in points (WPF window units) in place of the percent — for example a width by percent and a height that fits the page. Each such axis is at most 80 % of the session, and a page with a strip gets the strip's height on top. On open they come only with `--size-percent` (`session.overlay.open: --width/--height need --size-percent`). In `resize`, with `--size-percent` the panel takes exactly the axes given, points alone change only their axes of a panel already floating (otherwise `... need a floating overlay; pass --size-percent too`), and `--size-percent` without them or `--full` drops them. Points do not apply to a HUD or to an overlay another machine shows. The actual content size is `overlayWidth`/`overlayHeight` in `tree --json`;
- `--wait` keeps the overlay after exit until a key is pressed;
- `--block` waits for the exit and returns the program's code;
- `--follow` switches the user to the session;
- `result` prints `exit N`, the exit code of the last overlay (`exitCode` in `--json`). While the program runs it is the error `overlay still running`; when no code is left (the overlay was closed or never was), `no overlay result`.

**A hidden overlay**, as in agterm: `overlay hide|show|toggle` hides the session's programs and pages (with `--pane`, one pane's) without closing them. `toggle` hides them all while any shows, otherwise shows them all; the reply is `hidden` or `shown`. A hidden program keeps running, `--block` keeps waiting, and `overlay result` still answers. The slot stays taken: opening another overlay or a HUD there fails with `overlay hidden`. A HUD cannot be hidden (`no overlay`), nor an overlay the presenter draws (`overlay is shown on another machine`). In the window: the action “Toggle Overlay” (`toggle_overlay`, Ctrl+Alt+Shift+J), a title bar button and “−” on a page's strip (it hides its pane, or the whole session). Ctrl+Shift+W skips a hidden overlay, and the close question for a session mentions that its hidden overlays close with it. In `tree --json`: `hiddenOverlays` (`session`, `left`, `right`) and `hidden` on pages in `htmlOverlays`.

**An overlay over one pane of a split:** `--pane left|right` on `overlay open/close/result/text`. It covers only that pane, the other stays live, and each pane can have its own. Such an overlay always fills its pane, moves with its shell on swap and closes with the split. For `text` the right pane must be on screen; `open`, `close` and `result` work with a hidden one too. As in agterm, a program overlay whose pane leaves the screen (the split hidden, focus moved on a hidden split, the zoom changed) before its program started closes, its result included; one that already runs keeps running and shows again with its pane, and a page or the overlay the zoom shows stays.

**A HUD** is a panel with a message over the session that does not take focus. As in agterm, a session has one HUD: a new one replaces the old, and `--pane` or `--pane-id` only choose which pane it hangs over; `update` without them puts it back over the whole session, and `close` closes it wherever it is (`no hud` when there is none). `hud` without a subcommand is `hud open`; a message that is literally `update` or `close` is written through `hud open`. `--file` reads the message from a UTF-8 file (CRLF becomes LF, a trailing newline is dropped). The message is up to 256 characters (up to 4096 with `--markdown`), `--detail` up to 256, `--hide-after` up to 86400 seconds, `--font-size` 6–72. The background and font size are set only on open: `update` keeps them. `hud` and `hud update` print nothing on success.

**A page instead of a program:**

```
agshellctl session overlay open --html report.html [--cwd DIR] [--js] [--navigation | --chromeless] [--block]
agshellctl session overlay open --url http://localhost:5173 [--js] [--navigation] [--chromeless] [--persistent] [--browse]
agshellctl browser clear                                   # forget the cookies and logins of --persistent pages
agshellctl browser links [browser|overlay]                 # where Ctrl+click links open; without an argument, the current mode
agshellctl session overlay reload [--current] | navigate back|forward|browser|finder|URL | submit --value V | copy [--pane …]
agshellctl session overlay result --page ID              # {"pageID":…,"outcome":"pending|submitted|dismissed","value":"…"}; ID is the overlayId from overlay open --json
```

Links in the terminal, found in the text or written by a program (OSC 8), are underlined while Ctrl is held and open with Ctrl+click (while a program reads the mouse, only with Ctrl+Shift, so the click stays the program's), as agterm's LinkPolicy decides: http, https, mailto and ftp go to the system (http and https may open over the session in `overlay` mode, from a pane or the scratch: https, or http from a host of this network), a local `file://` is shown selected in Explorer and never run (a Linux path from a WSL pane through `\\wsl.localhost`), and any other scheme, a `file://` of another machine or a network share is ignored. The quick terminal opens links in the browser, and so do a window with a zoomed terminal and a session with a HUD, as in agterm. Over the session a link opens as a browsing page, as agterm's: with navigation, scripts, the saved browser store and other sites in the page (`--navigation --js --persistent --browse`); if it cannot open there (the slot is taken, the store is being cleared), it opens in the browser.

- A page shows under a strip, as in agterm. The name on the strip comes from AgShell, not from the page: the file shown now, or the site (`http://127.0.0.1:8765`; with `--browse`, the site shown now). The page's title follows after “·”. As in agterm, the strip is 28 high in the terminal's colors with its buttons drawn as symbols, the name cut in the middle; a floating page is cut to the panel's rounded corners; the error of a failed load is in the text's color and can be selected. After `navigate --url` the strip names the site the page went to. With `--navigation` the left side has back and forward (off without history) and reload, the right side open in browser, show in Explorer (a file) or copy link (a site). With `--chromeless` there is no strip. When a load fails, a panel “The page could not be loaded” with the error covers the page; reload takes it away.
- A page lives until its session closes for good: after an undone close it comes back as it was. A click on a page over a pane moves the split's focus to that pane, and typing in a page counts as activity and holds off auto-follow.
- As in agterm, every page opens in a browser of its own over the overlay: it has its own history (back, forward), load state and zoom. `navigate back|forward` without history is the error `no page to go back to` (`forward`), and `back`, `forward`, `browser` and `finder` for a page never shown yet give `html overlay not realized`. “Open in browser” opens in the default browser the local page's original file (not the one it moved to) or the web page's current address; “show in Explorer” shows the file open now. `window.close()` on any page closes its overlay. A crashed page process gives the state `failed` with `web content process terminated`.
- **Navigation, as in agterm.** A local page moves only among its own files, a web page within its own site (with `--browse`, to any http(s) address). Frames inside a web page load any site, except on pages with `--chromeless`. An address outside goes to the browser only on the user's click and after a question (Cancel by default; one question at a time, gone when the page leaves the screen; after a Cancel the page asks again only once there was input from the user — the page's own input is not visible to AgShell, so any key or mouse movement counts); a navigation the page started itself is cancelled, and if the page was still loading its state becomes `failed` with `navigation blocked: address`. `alert`/`confirm`/`prompt` dialogs are not shown, camera and microphone are denied, and files cannot be dropped on the page. As in agterm, files are not pasted into a page either (Ctrl+V, Shift+Insert and “Paste” in its menu do nothing while the clipboard holds files; text pastes), and a page opens no file chooser: a file input, a label for it, `showPicker` and the file system pickers are refused. Unlike agterm, a dragged text does not drop on a page either (WebView2 takes external drops or not), and a web page opened without `--js` may still open the chooser from a label (its scripts are off, AgShell's guard among them).
- **The terminal theme, as in agterm.** Every page gets the CSS variables `--agshell-background`, `--agshell-foreground` and `--agshell-color-0`…`--agshell-color-15` (the theme's palette: 1 red, 2 green, 3 yellow, 4 blue, 5 magenta, 6 cyan, 8–15 bright). A local page is also colored by default: the theme's text color and light or dark scheme, over the theme's background; `--background-color` replaces that background. The rule has no weight, so the page's own styles win. When the theme changes, a local page reloads, and a web page gets the new colors at its next load. Use the variables with a fallback: `background: var(--agshell-background, Canvas)`.
- **A local file** is served under a host name of its own, so it sees only itself. With `--cwd` the directory is open to it too: as in agterm, the page's address is its path inside that directory, so links resolve next to the file and `../` reaches what lies above it in the directory. As in agterm, the file must lie inside `--cwd` (`html file is outside cwd`), and the directory cannot be a drive root or the home directory (`cwd must not be a drive root or the home directory`). A file that does not exist opens, and the page reports `failed` with `no such file: path`. A file goes with its type, as agterm takes it from the system: web types (pages, scripts, styles, images, fonts, video and audio such as `.webm`, `.mp4`, `.mp3`, `.ogg`, `.wav`, also `.wasm`, `.pdf`, `.csv`) by AgShell's own table, as a browser types them, any other extension by the type Windows lists for it, and one without a type as `application/octet-stream`.
- **The page's own JavaScript** does not run without `--js`: every response comes with a Content-Security-Policy header that runs none of their scripts, an SVG or XHTML document included. The bridge and the theme are not part of the page: as agterm's user scripts, AgShell adds them to every document as it is created, so the page's files reach it unchanged and the policy does not touch the bridge. The theme sits in a CSS cascade layer, so any style of the page wins over it.
- **The bridge works without `--js` too:**
  - buttons and forms with `data-agshell="<command>"`; a button outside such a form must be `type="button"`, otherwise it submits an ordinary form, and a button inside one is part of the form's submit;
  - `data-agshell-target` is the command's target;
  - `data-agshell-args` is JSON with fixed arguments, and a form's named fields are added to them as in agterm: of the buttons only the one pressed, an empty number is skipped, a non-number and a file field are errors, two values under one name are the error `more than one value for NAME`;
  - `data-agshell-into` is the element the reply goes to: the reply's `text` field when it has one, otherwise the reply as one line of JSON.

  With `--js` there is also `agshell.request(cmd, {target, args})`. As in agterm, a request runs as one from agshellctl would, and what the page left out is filled from where it sits, only when it named no target, targets or window: a session command (and `notify`, `font.*`, `keymap.run`, `ask.open` without `--style gui`) acts on the page's own session, and the page's own overlay commands (`close`, `reload`, `resize`, `navigate`, `submit`, `hide`, `show`, `toggle`) on its pane; a `window.*` command acts on the page's window; app-wide ones (`hooks.*`, `browser.*`, `recent.list`, `recent.clear`) get no window; `live.attach`, `dashboard` and `recent.open` land in the page's window; the rest get the page's window. `overlay reload` from a page keeps what the page shows unless `current` is false.
- **An answer to the script that opened the page:** the page sends a value through `session.overlay.submit` (for example `<form data-agshell="session.overlay.submit"><input name="value"></form>`). `overlay open … --block` prints the result (`{"pageID":…,"outcome":…,"value":…}`). As in agterm, the value is text and must be given, empty being a real answer: `submit` without one answers `session.overlay.submit requires a value`, and `agshell.request` with anything but a string is an invalid request and exits with 0 when a value came, or 2 when the page was closed without an answer; a one-shot `result --page` for a page still open exits with 1. A page closed together with its split, pane or session counts as closed without an answer. As in agterm, a page's outcome is read by its id (`overlay result --page ID`), not by slot, and is kept for the last 32 pages, even after the session closed; an unknown id is `no such page`.
- **A web page** (`--url`) can be any site, and logins on it work. It has no bridge. Its own JavaScript is off without `--js`. As in agterm, `--url` does not combine with `--block` and `--cwd`, and `--chromeless` not with `--browse`. `--chromeless` is allowed only for 127.0.0.1, ::1 and localhost.
- **A web page's data.** Cookies, logins and storage live while the page is open: it has a private profile of its own. With `--persistent` pages share one saved profile, which `agshellctl browser clear` empties. As in agterm, clearing is refused while any `--persistent` page is open (an undoably closed one included): `browser.clear: 1 persistent page still open`, since its login in memory would be written back; and a `--persistent` page does not open here while clearing runs (`session.overlay.open: browser storage is being cleared`), as in agterm; one handed to the presenter is checked there.
- **The palette, a menu, the Ctrl+Tab switcher, a title bar button's list (recent sessions, sessions needing attention, custom commands), a pick, an `ask` or another dialog is drawn over the page, as in agterm:** the page stays on screen and keeps playing under them, dimmed where they dim the window. While one is open, a click on the page closes it or does nothing and does not reach the page; once it closes, the page takes clicks and, if it is where you work, the keyboard again. The palette's frosted background does not blur the page under it: the page shows through it plainly. The dashboard covers the page fully.
- **Keys on a page:** Ctrl+Shift+W and the other AgShell keys work with the focus inside a page too. The font size keys (`increase_font_size`, `decrease_font_size`, `reset_font_size`, by default Ctrl+= / Ctrl+- / Ctrl+0) change the zoom of all pages on agterm's scale from 50 to 300 % — also when the focus is outside the terminal (for example in the sidebar) and a page covers the session. The zoom is a setting (`htmlOverlayZoom`), shared by all windows and kept across restarts.

**A HUD** is a passive panel with a message (in `tree --json` a `hud` node with the message, pane, position, hide time, width `sizePercent` and height `heightPercent`: as set, or as measured where it is drawn; `overlay` is false then (`overlay` is true while a program or a page covers the session); pages in slots are listed in `htmlOverlays` with id, file or address, load state `loading`/`loaded`/`failed` (with `error`), current address and title, `canGoBack`/`canGoForward` and `zoom` (the pages' zoom, one for the app, as in agterm); a floating overlay has `overlaySizePercent`). As in agterm, a HUD is drawn above a page in its pane or session too, and the page under it stays live: the HUD goes in a window of its own over the page, which lets clicks through to it (a Ctrl+click on a link opens the link). `hud open --pane right` needs that pane on screen (`pane not visible`), `update` only that it exists (`session has no split`): the session keeps the focus and can be typed into. As in agterm, a hidden overlay in the slot (`overlay hidden`) and an update with no HUD (`no hud`) are answered before the pane is checked. A HUD over a pane is not drawn while that pane is off screen (the split hidden); it stays 10 % of the pane or session away from the edge it sits at (a pinned one touches it). The text limits count Unicode code points of the precomposed text, as agterm's: an accented letter is one, an emoji joined of several is each of them. As in agterm, a HUD always takes the session-wide overlay slot, and `--pane` only chooses which pane it is drawn over, so a pane's overlay and a HUD do not get in each other's way. A session-wide overlay replaces a HUD, and a HUD over a program or a page is the error `overlay already open`; `overlay open` into a slot held by a program refuses as well (`overlay already open`, for a pane `pane overlay already open`) instead of replacing it. `overlay close` closes a HUD too, and `overlay resize` changes a HUD's width (10–80 %, up to 100 % when pinned to an edge; `--full` is an error). `update` redraws the panel in place, and parameters not given go back to their defaults. `--markdown` renders the message as markdown, as agterm lays it out: headings and bold in bold, italic, strikethrough, code indented by two spaces, quotes behind “│ ”, lists with “• ” or numbers and hanging lines, tables in a frame, rules; a link is underlined and opens with Ctrl+click; raw HTML stays text. As in agterm, the panel is a terminal in the terminal's font (the session's size, or `--font-size`) on the terminal's background (or `--background-color`), with a white border at radius 8 and no shadow (`--no-frame`: neither, the background stays): a plain message wraps at 60 columns, each line centred, the detail dimmed under an empty line; the spinner goes before the first line. The panel is as wide as its text, 10–80 % of the pane or session, and at most 80 % high: rows that do not fit end with “… N more”, a row too wide with “…”.

**The quick terminal** is, as in agterm, one floating panel for the whole app over the other windows, on the screen under the mouse pointer (the front window's when the pointer is on none): 90 % of its work area, but no more than 1100×700 unless the settings give a size (40–90 %). It has one shell, started in the shell of the front window's selected session and in its main pane's directory; it keeps running while the panel is hidden, so every window opens the same one. Pressing the key again, the title bar button or losing focus hides the panel; one opened with `quick show` does not close on losing focus, and showing it again by hand keeps that. As in agterm, it does not open while a `pick` waits for an answer, the global hotkey brings it back at once even right after it hid, and typing in it counts as being busy for auto-follow. `surface zoom --target quick` spreads it over the whole screen (while it is shown). With the keyboard in the panel, as in agterm, Ctrl+Shift+Enter zooms the panel itself and the font keys change its terminal's font, and the other keys of the actions act on the active window, as there, except find; a new shell starts at the resolved font family and size from Settings and `ghostty.conf`. The terminal is created on the first show; after its shell exits the next show starts a fresh shell. This shell has no `AGSHELL_SESSION_ID`.

| Keys | Action |
| --- | --- |
| Ctrl+` | Quick terminal |
| Ctrl+Shift+W | Answer the window's ask or pick, the session's ask, leave the quick terminal's zoom, close the quick terminal, zoom, overlay or HUD, scratch — in that order — and only then the session |

## Dashboard

```
agshellctl dashboard S1 S2 S3 [--font-size N | --auto-size]   # a grid of live sessions, up to 9 panes
agshellctl dashboard S1:left S2:right                          # only the chosen panes of splits
agshellctl dashboard --mru [--auto-size]                       # recently used sessions
agshellctl dashboard S1 --window W                             # in that window (default: the front one)
agshellctl dashboard --close
```

As in agterm:
- **What it is:** the live output of several sessions in a grid, view only. The grid covers the window below the title bar, the sidebar included, with an opaque background in the terminal's color (the window's translucency is gone meanwhile); cells are 12 points apart with rounded frames, the highlighted one outlined in the text color. A cell is a pane: a session with a split takes two.
- **Controls:** the arrows move the highlight, Enter goes to that session and focuses the pane, a click first highlights the cell and goes there 0.18 s later if it still holds the highlight, Esc closes. Other keys do nothing but the app's own; while a pick, an ask, the palette or a menu is over the grid, the keys are theirs. Opening it closes the palette, ends the search and hides the quick terminal; the title bar button needs a selected session.
- **A cell's label** is a capsule on the bottom frame at the right: the session's name (a long one is cut in the middle) and, for a session with a split, a pane marker ◀/▶ or ▲/▼ on its axis. Without a status it takes the theme's selection colors, the name dimmed on a cell that is not highlighted; with an agent status it is painted in that color (`--color` included) with black or white text by its brightness, and with `--blink` a wash pulses over it (except under Windows' no-animation setting).
- **A pane under an overlay** shows a label instead of the terminal.
- **Targets:** `<id>`, `<id>:left` or `<id>:right`; `top` and `primary` also mean `left`, `bottom` and `split` mean `right`, in any case. A malformed one (`:left` with no id, `surface:<id>:left`, another suffix) fails the whole command before any other check of the window. A repeated pane counts once, among those that did not fit too.
- **Cells follow their panes:** when the main shell exits and the split becomes the main pane, its cell stays and follows it. The highlight stays on its cell; when that one goes, on the first.
- **Font:** `--auto-size` makes it smaller as the grid grows, starting from the size in Settings (13 when none is set), `--font-size` sets it exactly as given; without either the cells keep their own size. While the dashboard is open the shells get the cell's size, and the old one after it closes.
- **What does not fit:** the grid holds 9 panes; `dashboard` names the rest in its output (`dropped N pane(s) beyond the 9-cell limit`), and an id that matches no session or `:right` on a session with no split as `unresolved: …`; with every target unresolved it fails (`no dashboard sessions resolved`). `--mru` with no recently used sessions fails with `no recent sessions`.
- **`tree --json`** shows `dashboardMembers` and `dashboardHighlighted` (as `<id>:left` or `<id>:right`), `dashboardFontMode` (`fixed`, `auto` or `untouched`) and `dashboardFontSize`, the size applied to the cells.
- **Zoom** closes the dashboard, and opening the dashboard ends a zoom.
- **A tile under an overlay**, as in agterm, shows what covers it instead of the terminal: an icon and “HTML overlay” with the name as on the page's strip (cut in the middle) and the page's title dimmed, or “Program overlay” with its command. A HUD and a floating overlay do not cover tiles.

Ctrl+Shift+G opens a grid of recent sessions with an automatic font size; pressing it again closes it.

agshellctl session search --close
agshellctl font inc | dec | reset [--pane left|right|scratch] [--target S]   # one terminal's font size, ±1 point (the left pane's by default; the font keys change the one in focus); as in agterm the session remembers the last size set, which a new split, scratch or overlay starts with and the next launch restores

The arrows or Ctrl+J / Ctrl+K move the selection and stop at either end, Tab does not take the focus out of the field, and the mouse only highlights the row under it.

## Agent statuses and notifications

```
agshellctl session status active|blocked|completed|idle [--blink] [--auto-reset] [--sound NAME] [--color #rrggbb] [--shape SHAPE] [--pane P | --pane-id ID] [--target S]
agshellctl session context "PR #42" [--target S]     # what the session is busy with; shown in the title bar
agshellctl session context --clear [--target S]
agshellctl session wait --until completed --until blocked [--timeout 600] [--target S]
agshellctl session seen [--target S]                 # reset the notification counter without going to the session
agshellctl notify "text" [--title T] [--target S]    # a Windows toast and a counter on the session's row
agshellctl events [--kind status,notify,session.created,session.closed,session.selected,pane.split,pane.scratch,pane.focused,tree.changed,app.launched,remote.opened,remote.closed] [--json]
```

- **A status** is drawn as a glyph on the session's row (its tooltip, as in agterm, is “Agent status: Active”, “Blocked” or “Completed”): `active` grey-violet, `blocked` amber, `completed` green; `idle` has no glyph. `--blink` makes it pulse. The color and shape (circle, square, triangle, diamond, capsule, star) are set in the settings for each status; `--color` and `--shape` change them for this call only, and the next status without them goes back to the settings.
- **The context** (`session context`) is one line up to 256 bytes: a PR, a task. It survives restarts, and a duplicated session does not get it. In the title bar it follows the session's name, and in the two-line style it replaces the directory. In `tree --json` it is the `context` field.
- **The title bar** over the terminal, as in agterm: the workspace (turned on in the settings), the session's name, the context and buttons — recent sessions, the attention bell (turned on in the settings), scratch, split, dashboard, quick terminal, custom commands. Its style is one line, two lines or hidden (Interface tab). The Windows window title is the current session's name. As in agterm, while a terminal is zoomed the bar holds only the title and the button that leaves the zoom, and while the dashboard is open only “Dashboard” and the button that closes it; the split button shows the axis and which pane a hidden split leaves on screen, and its hint and the scratch's say what a click does, with the key. An ssh host is cut in the middle, at most 240 units. A pick closes the palette and hides the quick terminal; the palette and the picker dim from under the title bar and center over the terminal.
- **Clearing a status:**
  - `--auto-reset` clears the status when the user goes to the session;
  - `--pane left|right|scratch` records which pane's agent set the status (the hook passes `AGSHELL_PANE`). While one pane is `blocked`, the other can write only `blocked`, otherwise the error is `blocked status owned by pane …`. Typing clears the status only in the pane that set it. Going to the session yourself (a sidebar click, the session keys, the palette, the attention list) opens and focuses that pane, be it the split or the scratch; as in agterm, auto-follow does so only in the active window and not under the zoom, and `session select`, `session go`, the switcher, recent sessions, the dashboard and a notification click only select;
  - typing in the session clears `blocked` and `completed` as Settings ▸ Agent Status ▸ Status reset says, as in agterm: on the first key (the default), on Enter only (a reply you started and walked away from keeps the glyph; Esc or Ctrl+C still clears a `blocked` one, since cancelling the prompt answers it), or never (the status stays until the agent's next hook or Clear Status);
  - Esc (with any modifiers) and a bare Ctrl+C clear `active` whatever the setting;
  - as in agterm, a key press counts, not its bytes: Enter submits only without modifiers (Shift+Enter and Alt+Enter add a line in Claude Code and Codex), and a paste, a drop or the terminal's own reports count as nothing;
  - `session type` counts as typing too: a line break in the text submits, and it never interrupts.
- **Storage:** the status does not survive restarts. In `tree --json` a session has the fields `status`, `statusPane` (only when the write named a pane), `statusBlink`, `statusColor`, `statusShape`, `statusChangedAt` (Unix seconds) and `unseen`; an idle session has none of the status ones but `statusChangedAt`.
- **`session wait`** prints the status it waited for and exits with 0. If the session closed, the code is 2. If the time ran out, 124. The wait follows the event feed, so a status change between checks is not lost. As in agterm, `--target` is looked up in every open window (`active` is the front window's selected session), `--timeout` holds even when AgShell stops answering, and a busy pipe is retried for up to 30 seconds; other failures are `Error: ...` with exit code 1. As in agterm, several statuses are given by repeating `--until`; `--until idle,blocked` is `invalid status: idle,blocked`.
- **Notifications from the terminal:** OSC 9 with text (`ESC ] 9 ; text BEL`) and OSC 777 (`ESC ] 777 ; notify ; title ; text BEL`) show as a toast, except when the user types in exactly that pane with AgShell in front, as in agterm. A repeat from the same pane replaces its toast, `notify` has a slot of its own per session, and a click brings up the session at the pane that fired it (a window closed since opens). Going to the session or focusing one of its panes takes its toasts out of the notification center. AgShell's own toasts (a failed hook or command, keymap.conf, hooks.conf, remotes.conf or ghostty config problems, the live reset) replace their previous one too; as agterm's, they are the app's, so they need no open window, they make no sound, and the problems of those files already present at launch are shown once after the windows open. Clicking one, or a toast whose session is gone, brings AgShell forward. The taskbar button flashes only while no AgShell window is in front, as the Dock does not bounce while agterm is active. `session seen` resets the counter and, as in agterm, leaves the toasts in the notification center. As under agterm, the text is read as libghostty reads it: the ConEmu commands of OSC 9 (`1;`, `10`, `11;`, `12`, `2;` to `9;`, `4;0` to `4;4`, `5`) are not notifications, anything else is, an empty text included; OSC 777 needs both `;` after `notify`, and an empty title becomes the session's name. Only the session's own panes (main and right) notify, not the scratch or an overlay. As Ghostty's, the app shows at most one terminal notification a second and the same title and text once in five seconds; `desktop-notifications = false` in ghostty.conf turns them off. `notify` always shows a toast.
- **The taskbar button's jump list**, as agterm's Dock menu: New Session, New Window, Quick Terminal and Dashboard for the front window, and its Recent Sessions (up to 10, the selected one left out) and Sessions Needing Attention, each titled “session — workspace”. A chosen item brings that window forward and acts in it, as agterm's; an item that cannot run now (a zoomed or covered window, a session gone, the dashboard changed since) does nothing, since Windows cannot show it disabled, an empty category is not shown, and the lists are flat categories above the tasks, as a jump list has no submenus and keeps its tasks at the bottom. The list is saved ahead and kept up to date, as Windows does not ask for it when it opens; it starts `agshell.exe --dock …`, which hands the item to the running instance.
- **`events`** prints events until stopped: as in agterm, one line each “time kind name …” (`status` adds the status, `previous=`, `pane=`, `blink`, `color=`, `shape=`; `remote.*` adds `host=`), and with `--json` lines of JSON. The first read gives what the app already holds. As in agterm, the arguments (`--run` id, `--after` number, `--limit` 1–1000, each `--kind`) are checked before anything is sent, and repeated kinds are sent once. If the pipe is there but does not accept the connection, the stream retries with a growing pause up to 30 seconds and only then ends; a pipe that is gone (AgShell quit) or a refusal ends it at once with `Error: ...`. Status events have `status` and `previous` in `payload`. There is one stream for the whole app: it carries the events of all windows, each with a `window` field holding the window id (`app.launched` has none; it comes once per launch).
- **`pane.focused`**, as in agterm: a session's selection moved to the other pane of its split. The event carries the session's name, `pane` (`left` or `right`) and that pane's `paneID` (absent until its terminal exists). It reports the settled selection after 100 ms: a move and back within that time gives nothing. It follows the terminal, not the position: a click, the focus keys, `session focus`, a new split, closing the selected split and the main shell exiting while selected each give one; a swap, a hidden split shown again and a pane's shell starting do not. A session the window sees for the first time stays silent.
- **Keys:** Ctrl+Alt+Shift+↓ and Ctrl+Alt+Shift+↑ go to the next and previous session needing attention (`blocked` or `completed`).

## Hooks and the skill

```
agshellctl install hooks [--opencode v1|v2|skip]   # status hooks for Claude Code, Codex, Pi and OpenCode (Windows and WSL, wherever the agent is set up)
agshellctl install skill     # the skill folder in ~/.claude/skills/agshell and ~/.codex/skills/agshell (Windows and WSL)
agshellctl hook <state> [args…]                      # the status wrapper: session status for this terminal
agshellctl hook claude <state> [args…]               # the Claude Code adapter
agshellctl hook codex <event>                         # the Codex adapter
```

What goes where, as in agterm:
- **Claude Code** — `~/.claude/settings.json` (on Windows always, in WSL when `~/.claude` exists), with a copy in `settings.json.bak`. For a linked file (dotfiles), the target is updated and the backup stays beside the original link. An invalid shape of `hooks` or an event is rejected without writing; custom flags and wrappers of existing hooks are kept. In WSL, Claude hooks call `~/.config/agshell/agent-status/agshell-claude-status.sh`: the worker guard walks Linux parents there, then the shared wrapper calls the Windows CLI with the session environment forwarded through `WSLENV`. The Windows-only adapter remains `agshellctl hook claude`. The guard follows up to eight parents and fails open if the chain cannot be read; consecutive agent names count once.
- **Codex** — a `[[hooks.*]]` block between the `# >>> agshell agent-status >>>` markers in `~/.codex/config.toml`, when `~/.codex` exists. Installing again updates the block in place and keeps the `[hooks.state…]` trust entries Codex writes inside it. If the file already has hooks of its own (including quoted keys), or TOML is invalid, the install leaves it alone and says so. A legacy single-line `notify` whose parsed value invokes `codex-notify.sh` is removed; foreign notifiers, comments and multiline `notify` are kept. For a symlink, the backup stays beside the original link. In WSL, the hook command forwards the session environment back to the Windows adapter through `WSLENV`. Review and trust new or changed hooks with `/hooks` in Codex.

  **Known limitation of the shared server**, also documented by agterm: Codex can run hooks with the server's session environment instead of the new tab's. AgShell has no automatic Codex conversation-to-pane mapping. In WSL, an expired `WSL_INTEROP` can prevent the Windows adapter from starting at all. Enabled and trusted hooks alone do not prove correct addressing: check the actual hook's session, pane and pipe. Full Access does not replace hook trust. The interactive WSL investigation and remaining checks are recorded in [public verification limits](sanitation-summary.md).

  Launch interactive Codex with `--no-daemon` (keep your existing launcher, such as `codex-proxy`, and append the flag there). This keeps hooks in the tab's own process while the existing shared server and its sessions continue running. That conversation cannot be controlled through the shared server from Codex desktop/mobile. Verified on Codex 0.165.0 in WSL with automatic active/blocked/completed statuses, including a real permission prompt and the right split pane; see [public verification limits](sanitation-summary.md).

  This is a workaround, not a shared-server fix. It does not disable the launcher's network proxy and applies only to new launches. Do not stop the shared server or restart existing conversations to apply it. `--no-daemon` is incompatible with `--remote` and `codex agents`; keep those explicit shared-server commands unchanged. Codex 0.167.0 source/schema inspection confirms that hook input alone does not identify the calling pane; live status delivery on that version has not been verified here. If resume reports that the conversation is open in another app, leave the server and existing clients running; this workaround does not migrate an already loaded conversation.
- **Pi** — the extension `~/.pi/agent/extensions/agshell-status.ts`, when `~/.pi/agent` exists.
- **OpenCode** — the version comes from `opencode --version` in the user's login shell (in WSL an interactive one, so its rc files are read; it gets 3 seconds). OpenCode 1 gets `~/.config/opencode/plugins/agshell-status.js` when `~/.config/opencode` exists; OpenCode 2 gets `plugins/agshell-v2/tui.js` in `$OPENCODE_CONFIG_DIR`, else `$XDG_CONFIG_HOME/opencode`, else `~/.config/opencode`, when that folder exists. When the version cannot be told, `--opencode` picks it (`skip` leaves OpenCode out); without it the OpenCode line says so and the command exits with 2. The palette action that installs the hooks asks then, as agterm does, and shows what was installed in a dialog, as agterm's alert: “Agent Status Hooks Installed”, “— with a warning” when a step failed.
- **The shell integration**, for agents without hooks of their own (gemini, cursor-agent, aider, crush, goose), only in WSL, since Windows has no bash, zsh or fish of its own: the scripts go to `~/.config/agshell/agent-status`, and a block between the `# >>> agshell agent-status >>>` markers that sources `shell/integration.sh` goes to `~/.zshrc` and `~/.bashrc` (`shell/integration.fish` to `~/.config/fish/config.fish` when `~/.config/fish` exists). As in agterm, a command that matches `AGSHELL_AGENT_RE` (by default `^(gemini|cursor-agent|aider|crush|goose)([[:space:]]|$)`, set it before the block to change it) sets `active --blink`, and the next prompt sets `idle`; Claude Code, Codex, Pi and OpenCode are left out on purpose, their own hooks report finer states. In bash it uses bash-preexec when it is loaded, otherwise a DEBUG trap only when no other one is set. A block already in the file is left as it is.
- An extension or plugin file AgShell did not write (no agshell marker at its start) is not overwritten.

The Codex adapter follows agterm: `PermissionRequest` arrives before Codex's auto review decides whether a person is needed, so on its own it does not set `blocked`. A separate process reads the pane's screen twice a second and sets `blocked` only while an approval prompt is visible, and once it closes goes back to `active`. On `Stop` the last answer is checked for a question: if it asks one, `blocked`, otherwise `completed --auto-reset`. The OpenCode and Pi plugins are taken from agterm (MIT, `src/AgShell.Ctl/AgentStatus/LICENSE-agterm`).

The watcher starts without inheriting the hook's handles, so WSL returns from the hook immediately while screen monitoring continues.

Claude Code's events and statuses are the same as agterm's:

| Claude Code event | Status |
| --- | --- |
| `UserPromptSubmit`, `PostToolUse` | `active --blink` |
| `Stop` | `completed --auto-reset` |
| `PermissionRequest`, `Notification` with matcher `permission_prompt` | `blocked` |

**How `hook` behaves:**
- outside AgShell (no `AGSHELL_SESSION_ID`) it does nothing;
- it prints nothing and always exits with 0;
- `hook <state>` is agterm's wrapper: `session status <state>` for the terminal's session, with its pane and pane id (`AGSHELL_PANE`, `AGSHELL_PANE_ID`), and every further argument passed on as it came (`--sound`, `--color`, `--shape`…); a `--pane` or `--pane-id` given by hand wins;
- `hook claude` adds agterm's guard, for Claude Code's hooks only: if there is another agent above Claude in the process tree, the hook stays silent: such a Claude is a worker started from a tool and must not repaint its parent's session. As in agterm, a node, bun, deno or python process counts by the script it runs: its file name, and since npm on Windows starts `node "…\node_modules\PACKAGE\FILE"` rather than a link named after the command, the package's `bin` name for that file. `AGSHELL_AGENT_RE`, as agterm's `AGTERM_AGENT_RE`, adds names (a .NET regular expression; one that does not compile adds nothing). If the process tree cannot be read, the hook sends the status anyway;
- as agterm's `AGTERM_STATUS_WRAPPER`, `AGSHELL_STATUS_WRAPPER` names a program that the Claude Code and Codex adapters and the OpenCode plugins run instead of the wrapper, with the state and its flags;
- the Codex watcher keeps one file per terminal (by `AGSHELL_PANE_ID`, else the pane); as in agterm, `AGSHELL_CODEX_WATCH_FILE`, `AGSHELL_CODEX_WATCH_MAX_CHECKS` and `AGSHELL_CODEX_WATCH_INTERVAL` (seconds) change it.

Running `install hooks` again duplicates nothing, and when the path of `agshellctl` changes it updates the commands in place.

**How `install skill` works**, as in agterm: in Windows and in every WSL distribution the whole skill folder goes to `~/.claude/skills/agshell` when `~/.claude` exists and to `~/.codex/skills/agshell` when `~/.codex` exists; when neither exists, to Claude Code. A previous install is replaced as a whole. A same-named skill AgShell did not write (its `SKILL.md` lacks `<!-- agshell-skill -->`, or the file is missing or unreadable) is left untouched and reported under “Skipped”. The report lists where the skill went, what was skipped and why, and asks to restart running agent sessions when a skills directory was created for the first time; it exits with 0 only when nothing was skipped. With `--json` the report is a JSON object with `installed`, `skipped` and `freshSkillsDirectory`.

## Flags and the workspace filter

```
agshellctl session flag [on|off|toggle] [--target S]...   # flag sessions; toggle flags all unless all are flagged already
agshellctl session flag clear                            # unflag every session
agshellctl workspace flag [on|off|toggle] [--target W]   # flag or unflag all of a workspace's sessions at once
agshellctl sidebar mode tree|flagged|toggle               # the tree or the list of flagged sessions
agshellctl sidebar flagged-layout [flat|plain|tree|toggle] # how flagged sessions show: a list with workspaces, names only or a tree
agshellctl workspace focus [on|off|toggle|add] [--target W]
agshellctl workspace filter on|off|toggle                 # turn the filter on or off; the set is kept; on with nothing marked does nothing
```

As in agterm:
- **A flag** is a working set of sessions across workspaces. A flagged session has a colored icon. The Flagged view (the flag at the bottom of the sidebar, `toggle_flagged_view`) shows them as one list labeled “session : workspace”; `sidebar flagged-layout` and the setting “Flagged sessions” change it to a list without workspaces or a tree by workspace; with nothing flagged it shows a hint on how to flag. “Clear Flagged” (`clear_flagged`) asks for confirmation. `workspace flag` and “Flag All Sessions” in a workspace's menu set one value on all its sessions, those the Flagged view hides included: `toggle` unflags only when all are flagged, otherwise flags them all; an empty workspace does not change, and any other mode is the error `invalid workspace flag mode: …`.
- **The workspace filter** shows only the marked workspaces. A workspace's menu has two items:
  - “Focus” keeps only this workspace; if it is already the only one, the filter comes off (`workspace focus toggle`, action `focus_workspace`);
  - “Add to Focus” / “Remove from Focus” changes only its own mark (`add` / `off`); adding does not turn the filter on, so the set is built with the whole tree on screen, and removing the last mark turns it off.
  The funnel at the bottom of the sidebar (`toggle_workspace_filter`) turns the filter on and off without forgetting the set.
- **The bottom of the sidebar**, as in agterm: on the left “New workspace” and “+”, whose menu has “New Session”, “New session with shell” and “Open Directory…”; on the right the funnel and the flag. The flag is off in the tree while nothing is flagged; their hints say what a click does, with the key.
- **Navigation** goes over what is visible only: `session go`, Ctrl+Alt+↑↓, going to sessions needing attention, the session palette, Ctrl+Tab. The attention palette shows all sessions.
- **Selecting a session outside the filter** (from agshellctl, from a notification), creating a selected session in a hidden workspace or moving the selected session out of the marked ones turns the filter off, keeping the set. If narrowing hid the current session, the most recently used visible one is selected. Selecting an empty hidden workspace (`workspace select`) adds it to the set. `workspace go` steps only through the shown workspaces, not in the Flagged view; from a workspace outside them it enters at the end it comes from.
- **Closing the selected session** selects, as in agterm, the most recently used visible session of its workspace, then of all visible ones, then of the whole tree; without history the nearest visible row. A closed or removed workspace leaves the marked set; its undo and Open Recent mark it again.
- **A folded workspace** opens on screen when a session in it is selected, but stays folded in the state (`collapsed` in `tree --json`); folding the row closes it.
- **`tree`** shows `(flagged)` on sessions and `(focused)` on marked workspaces; `--json` has `flagged`, `focused`, `sidebarMode`, `focusEnabled`. Flags, the set and the mode survive restarts.
- **Keys:** agterm's `toggle_flag` is ⌘⇧F, but Ctrl+Shift+F is taken by search here, so these actions have no default keys.

## Selecting several sessions and folders from Explorer

This is the window only, without agshellctl commands. As in agterm:
- **Selection.** Ctrl+click adds a session to the selection or removes it, Shift+click selects a range of visible rows, a plain click clears the selection. As in agterm, the clicked row becomes the current session when it is selected (otherwise the current one stays, if still selected, else the last selected); every selected row is drawn alike, dimmed while the window is inactive. Choosing a session any other way (keys, palette, `agshellctl`) clears the selection, and so does a filter or the Flagged view hiding its rows. A right click outside the selection narrows it to the clicked row. The context menu on a selected row applies to all of them: clear statuses, mark for attention, flag or unflag, move to a workspace, close. Closing several is undone with one Ctrl+Shift+Z. A context menu is driven by keys as well: arrows, Enter, Right and Left into and out of a submenu, a letter jumps to the next item starting with it.
- **Dragging in the sidebar** (tree only, as agterm). A session goes before or after a row, or to the end of a workspace dropped on its header; a drag from a selected row carries the whole selection as one block. A workspace goes before or after another, or past the last one on the empty space below. A place where nothing would change is not highlighted and takes no drop. A folded workspace the drag rests on opens after 0.65 s and folds back when the drag leaves it or is cancelled; a drop into it keeps it open on screen without saving that.
- **Folders from Explorer.** A folder dropped on the sidebar opens as a new session in that directory: in the workspace of the row it was dropped on; on empty space, in the only filtered or the current one; that workspace is highlighted while dragging. More than 20 folders at a time open none and show a warning, files are skipped, and the Flagged view refuses the drag.
- **Files on a terminal.** Files and folders dropped on a terminal are inserted as paths: quoted for Windows shells, as `/mnt/c/...` for WSL. A drop elsewhere is ignored and the window stays where it is.
- **“Open Directory…”** (the command palette, the workspace menu, action `open_directory`) creates a session in the chosen folder: in the workspace whose menu it was chosen from, otherwise in the current one, in the Flagged view too. In agterm it is ⌘O; here Ctrl+O belongs to the terminal, so there is no default key.
- **“Open in AgShell” and paths on the command line** (agterm's `open -a agterm <path>`): `agshell.exe <path>…` opens each path as a new session in the current workspace of the last active window, selected, and brings the window forward: a folder as itself, a file as its folder, a missing path is skipped. A running AgShell of the same state folder gets the paths; a new one opens its windows first. The installer adds “Open in AgShell” to the Explorer context menu of a folder, the inside of a folder and a drive (on Windows 11 under “Show more options”: the new menu takes only commands of packaged apps).

## Picks and questions

```
printf '%s\n' staging production | agshellctl pick --prompt "Where to deploy?"
agshellctl pick [--prompt T] [--query Q] [--select ID] [--allow-custom] [--follow] [--no-block]   # items from stdin
agshellctl pick result ID | pick cancel ID
agshellctl ask "Deploy?" --button yes=Deploy --button "no=Not now" --default no --hotkey yes=d
agshellctl ask "Message?" --input line|multiline [--value T] [--placeholder T]
agshellctl ask "What to build?" --choice a=Alpha --choice b=Beta [--choice-subtitle b=…] [--multiple] [--checked a] [--other "other"]
agshellctl ask … [--style terminal|gui] [--align left|center|right] [--width 10..100] [--target S] [--pane left|right] [--no-block]
agshellctl ask result ID | ask cancel ID
```

As in agterm:
- **pick** reads items from stdin to its end, as agterm does, even from a terminal (finish with Ctrl+Z, Enter): every line that is not blank (split at any line break) is an item, stdin that is not UTF-8 is a usage error, and text starting with `[` is a JSON array of `{id,label,subtitle?,status?,statusColor?,statusShape?}` (up to 1000). Search matches the label only; while the query is empty the order is the caller's. `--allow-custom` accepts a query nothing matches: as in agterm, the empty list gives way to a row `Use "…"` with the query trimmed, chosen with Enter or a click. Esc or a click on the backdrop around it cancels. Menu chords such as Ctrl+, and Ctrl+Shift+Q remain available in its query field. The answer is one line of JSON: `{"result":"picked","id":…,"label":…,"index":…}` or `{"result":"custom","query":…}` with code 0, `{"result":"cancelled"}` with code 2 (Esc).
- **ask** is a title and one to six buttons (`ID=LABEL` or just a label). With an input field or a list the buttons can be left out: there will be OK and Cancel. Enter presses the highlighted button (Ctrl+Enter in a multiline field), Tab and the arrows move the highlight (with a list, Up and Down move through it and Space checks), and a letter from `--hotkey` presses its button, with a list too: as in agterm, the letter typed on a Latin layout, the key's US place on any other. The hotkey is underlined in the label, or added as “ (X)”; the buttons are as wide as the widest, in a row or, when it does not fit, a column. As in agterm, chords with Ctrl or Alt go to the window, except the one that closes. A click on a terminal question's area selects its pane and gives the question the keys. As in agterm, the terminal style uses the terminal font from the settings and marks the `--destructive` button bold with “! ” (the GUI style tints it red); `--width` is that share of the area under the question, and without it the panel takes its own width up to 90 % of it and 72 terminal cells (a text field all of that). A field holds up to 64 KB (the prefill is cut to it); a multiline one grows with the text, wrapped lines included, from 5 to 15 lines. Esc and the button from `--cancel` give `{"result":"escaped"}` with code 3; an answer is `{"result":"answered","id":…,"label":…,"index":…}` plus `text` for a field and `selected` for a list, code 0; `ask cancel` and closing the session give `cancelled`, code 2.
- **terminal** (the default) is drawn in the terminal's font and colors over the chosen session or pane and does not get in the way of the rest of the window; a session has one such question at a time. It takes the keys while it is on screen and, for a pane's question, while its pane has the focus; Esc closes it only then. As in agterm, Enter and Esc go to an input method while it composes. What is typed and chosen in it stays when another session is selected and back. **gui** is a panel in the middle of what it is anchored to: the terminal area, the session with `--target`, the pane with `--pane`; that part is dimmed, and the rest of the window takes no clicks while it is up. It shares its place with `pick`, and a second dialog answers `pick already pending` or `ask already pending`; it closes the palette. As in agterm, a GUI question over a pane follows the pane when the panes swap or the split takes the main pane's place, and is cancelled when its pane closes or goes off screen (the split hidden while the other pane has the focus). As in agterm, a question with `--target` drawn here needs its pane on screen (`pane not visible`), and a GUI one its session selected and not under a zoom or the dashboard (`session not visible`).
- Without `--no-block` the command waits for the answer; Ctrl+C cancels the dialog. With `--no-block` it prints `{"id":…}`, and the answer is read with `result`. As in agterm, the answers are kept after the dialog closes: the last 8 pickers of each window (and 32 of closed windows), the last 32 questions of the whole app.
- `tree --json`: `pickPending` and `askPending` at the top, `ask` with `id` and `pane` on a session.

## Restoring sessions

```
agshellctl restore mode                 # the current mode
agshellctl restore mode none|rerun|live # change it; live takes effect after AgShell restarts
agshellctl restore capture              # remember the panes' programs now, as on quit (rerun only)
agshellctl restore clear                # forget the remembered programs; pins stay
agshellctl session restore "claude --resume ID" [--pane left|right] [--target S]   # pin a command
agshellctl session restore --none | --clear [--pane left|right] [--target S]       # pin a plain shell or remove the pin
agshellctl live list                    # as agterm's zmx list: the restore policy, then each kept shell with its state, clients and owning pane
agshellctl live screen NAME [--all | --lines N]   # a kept shell's screen as text from its daemon's terminal, shown in a window or not; NAME as live list prints it
agshellctl live prune                   # end the shells no pane claims
agshellctl live reset --force           # as agterm's zmx reset: reset the live sessions that predate the last live daemon update, then quit and reopen
agshellctl live kill --pane left|right --force --target S [--window W]  # end one pane's kept shell and its process; as agterm's zmx kill, no undo, 'active' not accepted
agshellctl live proxy PANE              # a pane daemon's protocol on stdin/stdout, for another PC: ssh PC agshellctl live proxy PANE
agshellctl live tree [HOST]             # sessions that can be attached: of this PC, or of HOST through ssh
agshellctl live attach HOST ID [--window W]   # attach HOST's session as a remote row (ID from live tree HOST); prints the row's id
agshellctl live present SESSION         # a stream of the session's status, context, HUD and notifications as JSON lines, for another PC
agshellctl session overlay run-job JOB  # run an overlay handed to another PC in its ssh terminal (AgShell calls it)
agshellctl session overlay page-serve TOKEN  # carry the channel of a page handed to another PC (AgShell calls it)
```

As in agterm (“Restore sessions” on the General tab):
- **none** (the default): on launch the same layout with fresh shells.
- **rerun:**
  - On quit (closing the last window, “Quit AgShell”, a logoff), the program running in the shell of every main pane and shown split is remembered. A window closed while others stay open forgets its programs. For Windows shells it comes from the process tree, for WSL from the `AGSHELL_*` variables of the distribution's processes.
  - On launch the program is typed into a fresh shell as soon as the prompt appears. Only the app's launch does this, as in agterm: a window opened later and Recently Closed come back with plain shells. The launch takes the programs out of the state file at once, so a crash does not run them a second time.
  - A shell with nothing after it but flags remembers nothing; a shell running a script or a line (`bash ./run.sh`, `pwsh -File x.ps1`, `cmd /c …`) is remembered as the program, as in agterm.
  - Programs from `restore-denylist.conf` in the config folder (`%APPDATA%\agshell\config`) (one name per line, for example `ssh`) do not come back, nor do commands with control characters; the list is read at launch, so a program added after the quit does not come back either.
  - Restarting a session does not repeat the command.
  - `restore capture` is for a quit without closing the window (a crash, a power cut): bind it to a key or run it on a schedule.
  - **A pin** (`session restore`) sets what a pane runs on every start instead of the remembered program; `--none` is a plain shell. A pin does not go away after a launch and is not checked against `restore-denylist.conf`. It works in rerun only; in another mode it is kept for later, and the command warns about it. A pin set during a run applies from the next launch. It shows in `tree --json` as `restoreCommand` and `splitRestoreCommand`. The value is stored in the state file, so keep secrets out of it; if the file cannot be written, the command fails and the previous value stays.
  - Scratch, overlays and the quick terminal are not restored.
- **live** (in place of agterm's zmx):
  - Each shell of a main pane or split is held by a daemon of its own, `agshell-live.exe`, as agterm's zmx holds each pane, so it outlives the window together with the programs running in it. A daemon is named by its pane's id (`AGSHELL_PANE_ID`), which goes with the shell through a swap or a promoted split.
  - On the next launch the window attaches to them again. As agterm's zmx, the daemon keeps its pane's terminal state (ghostty-vt, in `agshell-vt.dll` beside the daemon) and a window coming back gets that state, not the output again: the screen and up to 10,000 lines of scrollback, styles, the cursor and its shape, modes, title and working directory, laid out at the size of the window that leads. A line longer than the pane comes back wrapped as it was, one line, so copying it and a later resize keep it whole (agterm's zmx breaks it into rows). Then it nudges the size a row up and back, and programs that redraw on a resize (`top`, agents) come back as they were; the shell's line stays where the window shows it. The window that started the pane gets the output as it comes. The questions a shell or ConPTY asks the terminal (`ESC [ c` and the like) are not replayed, so a window coming back does not answer them again into the shell's line. While no window shows a pane, its daemon answers DA1 and DA2 itself (`ESC [ ? 62 ; 22 c`, `ESC [ > 1 ; 10 ; 0 c`, as zmx), so a program asking then does not wait for an answer.
  - Text is read from the same terminal, as agterm's `zmx screen`: plain text with wrapped lines joined and trailing spaces trimmed, laid out at the leader's size, without the escape sequences and without what was erased. `live screen` gives the visible screen, `--all` the scrollback too, `--lines N` the last N lines (blank rows at the bottom dropped); no window is needed. For a pane of this machine in live mode `session text --all` and `--lines` and `surface cursor` read the daemon too, and so does a plain `session text` while another side leads the pane or nobody does; a plain `session text` of the leading pane reads the pane itself, including where it is scrolled to.
  - `session type` to such a pane goes through its daemon as well, whether the pane leads or not, as agterm's `zmx type`. The daemon writes the text into the shell and leaves the lead where it is. It encodes each Return for the keyboard mode the program asked for (under the Kitty keyboard protocol that is `CSI 13 u` and its release) and answers whether it took the input. An IME composition under way goes first on the same path and is not sent a second time. A refusal or no answer is `the pane's daemon did not accept the input`. When only the final Return, sent apart from the text, is not confirmed, the error is `text typed, but its final Return could not be confirmed; do not retype the text`. Input over 256 KB is refused, as zmx's. A daemon from before this operation does not answer, so typing into its pane fails until a `live reset`.
  - When there is no daemon (after a reboot, say), a pane starts again with the remembered program, as in rerun; with none remembered, with the session's `--command`. As agterm's replay script, the program is the first command of the daemon's new shell rather than typed at its prompt: PowerShell runs it after its start-up script (`-EncodedCommand`, then `-NoExit`), cmd with `/k`, WSL in the login shell (`$SHELL -lic`), which then becomes the interactive shell. So it waits for no prompt, does not go into the shell's command history (PowerShell's `Get-History` still lists it, the arrow keys do not), and Ctrl-C ends the program and leaves the shell. A daemon that is still there keeps its shell, and nothing runs. As in agterm, a pin is not used in live. `session restart` of such a pane runs its line the same way.
  - A daemon that cannot be started (an antivirus, say) is tried from the install folder. If startup or connection fails, or a running connection breaks without a confirmed shell exit, the pane shows an error and keeps its session, id, directory and claim. It stays stopped after reopening the window until an explicit restart. A confirmed shell exit still closes the pane normally.
  - Daemons and the relauncher of Reset Live Sessions leave the app's job (`CREATE_BREAKAWAY_FROM_JOB`), as agterm's are started apart from the app, so they outlive AgShell started from a terminal that ends its job when it closes. A job that does not allow it keeps them, and they end with it.
  - Whether live can run is checked at every launch, in any mode, as in agterm; when it cannot (`agshell-live.exe` is missing), `restore mode` shows `live unavailable: the agshell-live executable is unavailable`, the active mode is reported as none and main/split panes stay stopped with their sessions preserved; Settings shows the reason under the mode while live is chosen. There is no notification about it, as in agterm.
  - A saved pane id from an older version that is incompatible with live mode is preserved, together with its references. That pane shows an incompatibility error instead of receiving a new id. Its claim keeps the inventory incomplete, so prune and reset refuse to act. Different textual forms of the same UUID refer to one identity; duplicate owners remain a conflict.
  - Scratch, overlays and the quick terminal stay temporary.
  - Closing a session ends its daemons.
  - As agterm's launch reap, each launch in live, before any window opens, ends the daemons that no pane claims and no client shows (left by a crash, say); a closed window's shells stay. When some window's state cannot be read, nothing is ended.
  - As in agterm, a pane gets its id when its session or split is created and saved with it, so a shell started just before a crash goes back to its pane. A saved pane without an id gets one at launch, written to its window's state at once; its old shell, if any, is ended as unclaimed.
  - The mode is chosen at launch. After switching to another mode and restarting, the shells no client shows end together with their daemons, as agterm's.
  - A daemon leaves with its shell.
  - `live list`, `live prune`, `live kill` and `live screen` work in any restore mode, as agterm's zmx commands. `live list` joins the daemons with the panes that claim them (the open windows, sessions in their undo window, closed windows and window files the index does not name): a row per daemon and per claim, `state` `claimed`, `pendingClose`, `orphan` (no pane claims it), `unknown` (unclaimed while some window could not be read) or `conflicted` (two panes claim it), `observation` `running`, `unreadable` (the daemon did not answer) or `absent` (a pane whose daemon is gone). A remote row claims no pane. When the pipes cannot be listed, the commands answer `could not read the live session list`. `live prune` ends only orphans observed running with no clients, lists again just before and spares one a client took meanwhile, and reports each daemon as `killed NAME` or `NAME: not killed (REASON)`; only confirmed kills count. `live kill` refuses `NAME is not running`, `NAME is unreadable; killing it could orphan a live daemon`, `NAME belongs to a session waiting out its undo window`, `NAME is not claimed by that pane` or the incomplete-inventory error; a miss is `no left|right pane daemon for session S`, an unknown `--window` `no such window: W` (resolved among the windows of the claims, closed and unindexed included). As with agterm's zmx, a kill counts only when the daemon says it ended the shell; otherwise `could not kill NAME: REASON` and the pane stays as it is. `live screen` takes a daemon name without whitespace or control characters (`live.screen requires a daemon name`).
  - An update keeps live sessions, as agterm's keeps its zmx daemons: a daemon runs from a copy of its build, `%LOCALAPPDATA%\agshell\live\<build>`, so the installer replaces the program and closes the window without touching it (Windows locks a running program's files, and the installer closes whatever holds the files it replaces). Shells started before the update stay on the old build's daemons, new ones start on the new build; a copy no daemon runs from is removed at the next launch. This applies to compatible per-pane daemon versions. Published 0.3.0 still uses the shared `agshell.exe --host` in the install folder: its live processes must be ended explicitly before upgrading to 0.4.0; otherwise the installer can refuse because the executable is in use. There is no automatic attachment to that legacy host. Legacy `p…` pane ids are preserved and blocked as described above; save your work and back up your state before this transition.
  - Several clients can attach to a daemon at once: this PC's window and AgShell on another PC through `ssh PC agshellctl live proxy PANE` (like agterm's zmx attach; this PC needs OpenSSH Server and AgShell in live mode). Every client showing a pane gets its output. The ConPTY size is set by the leader, the client that attached last. As agterm's zmx, when it leaves nobody leads: the others are told so (“Reconnecting…”) and join again without asking for the lead, the first to come leads, and until then the pane keeps its size. Input from a client that does not lead is dropped; a client that does not say it is a window (zmx's stock `attach`, here none but an older AgShell) takes the lead by typing, though not by its terminal's replies or mouse and focus reports.
  - **Reset Live Sessions…** (the AgShell menu, beside Quit as in agterm; shown only while live is both the configured mode and the mode of this launch) and `live reset --force`, as agterm's Reset Live Sessions and `zmx reset`. Live sessions keep the daemon they started with through updates; the reset ends the processes of the sessions whose daemon started before the first launch with this build of the daemon (`live-build.json` in the state folder: the daemon's build id and when it changed; the id is a digest of the daemon's sources, so an update that does not change the daemon does not move it) and recreates them on the current daemon, typing their remembered programs again where possible. Other work running in them stops, and agent conversations may need to be resumed by hand. The action asks first; `live reset` does not ask and needs `--force`. Both refuse outside live mode or with a mode change waiting for a restart, when the list of daemons cannot be read, when some window's state cannot be read or a pane is claimed twice, and when nothing needs resetting. AgShell then quits without the quit question and reopens itself on the same state folder (`live reset` answers first): the quit writes `live-reset.json` only after every window and the window list saved. The next launch re-checks each pane before any window opens and only ever resets fewer than confirmed: a pane no longer claimed, a daemon whose shell changed, or one started after the cutoff is skipped. A shell that is still running after the reset gets no remembered program at that launch. When the reset covered only part of the sessions, a notification says so. `live list` marks such a daemon `outdated` (`outdated: true` in `--json`). `tree --json` and `live list --json` carry `liveReset`: `pending` (the panes waiting for the quit) and `last` (what this launch's reset did: `panes` confirmed/killed/gone/skipped, `unconfirmed` pane ids, `sessions` affected/reset/partial/unconfirmed, `inventoryFailed`); it is absent when there is neither. agterm also resets sessions whose processes macOS attributes to the app or leaves orphaned (the microphone permission asked again); on Windows a shell is always the child of its own daemon, so there is no such case.

**Remote sessions** (like agterm's remote rows):
- Machines are listed in `remotes.conf` next to `keymap.conf`: one line “ssh-address [label]” each; `#` starts a comment.
- While attaching, a panel “Attach Remote: listing sessions on …” (then “attaching …”) hangs over the session that was current when the action started, as agterm's; an error opens there again for 5 seconds, even when the progress panel has already gone, and becomes a notification when there is no place for it (no session, or a program covers it). The action is unavailable while there is no `remotes.conf` or no machines in it. The address is the line's first word without control characters and not starting with `-` (ssh would take it for an option); the rest of the line is the label. AgShell skips a line with a bad address, with control characters in the label, or with an address already listed above, and says so in a notification, as for an unreadable file.
- ssh runs with `BatchMode=yes` and `ConnectTimeout=5`, and each pane's connection also with `LogLevel=ERROR`. The reason of a reconnect error is ssh's last non-empty line from the last attempt, without control characters, at most 200 characters, and none when ssh said nothing; when the machine has no `agshellctl`, that is what it says. An overlay job's ssh runs with `-tt`. Unlike agterm, AgShell does not add its install folder to the other machine's PATH: the AgShell installer puts `agshellctl` on the user's PATH itself, and Windows OpenSSH gives a session the user's PATH (on macOS sshd has a fixed PATH, which is why agterm extends it); adding to PATH here would need one particular shell's syntax, and the shell on that machine can be cmd or PowerShell.
- `live tree --json` returns `remote`: `host` (the address asked; only for `live tree HOST`), `endpoint.pipe` (the prefix of the panes' daemon pipes), `presentation` (the status protocol version; missing on a too-old AgShell, and then the row attaches without mirroring, `presentation.state: unsupported`) and `sessions`: `id`, `name`, `windowName`/`windowID` and `workspaceName`/`workspaceID` (show the names, group by the ids — names repeat), `cwd`, `split`, `splitAxis`, `status` with `statusColor`/`statusShape` (absent for idle), `context` and `panes` (`pane`, `daemon` — the name on the host, `foreground` — the arguments of the running program, if there is one). `live present` refuses a session whose panes are not all held by the host (`session is not live-backed, so nothing can be attached to it`); a frame over 256 KB is neither sent nor accepted, and a layout that cannot be read is dropped without breaking the stream.
- `live tree` lists only sessions whose panes (and split, if any) are all held by the host. `live attach` looks the session up on the machine again, by id only, so a session gone since the list gives the error `no attachable session ID on HOST`, not a fresh shell under its name. As in agterm, before any row is made the session's panes are checked: each named once as `left` or `right`, a `left` among them, otherwise `HOST reported panes agshell cannot address`; a daemon name a pane cannot join gives `HOST reported a session agshell cannot address`. The row gets a split when the machine reported a `right` pane. As in agterm, the window from `--window` (or the front one) is chosen after the machine answers; with no window, `no open window`; a `--window` that is not open, `window not open — window.select it first`; a window with no workspace, `no window to attach into`. The window does not come to the front. The text `live tree` prints one line per session: `window/workspace/name (split axis)  [id]  directory  context  programs`; an empty answer is `no attachable sessions on HOST`.
- As in agterm, the choices are made in the window's picker, the one `pick` opens: with several machines in `remotes.conf` it first asks which one (with one it does not ask), then, once the machine answered, offers its sessions; it searches by name only. When the machine did not answer or has nothing to attach, the picker does not open: the reason shows on the panel over the session. Otherwise the picker shows all of the machine's sessions, attached ones included; the subtitle is window/workspace, context, directory and the running programs; more than 1000 sessions is reported on the panel. The chosen session is looked up on the machine again under the “attaching …” panel (it opens over a HUD too and hides by itself after 30 seconds); when there is nowhere to show the panel, the error comes as a notification. The action is unavailable without a workspace. `live attach` checks the window from `--window` at once and picks the default window after the machine answers; without a workspace it refuses. A split comes with its direction and with focus.
- `remotes.conf` is read at launch, when the config folder changes, and on every change of the file, of its folder (also one created later) and of the file a link points to (the watch is set again after each change, as in agterm); the address runs to the first whitespace of any kind. Errors come as a notification once, when the file turns from clean to broken while running (a file already broken at launch or in a newly chosen config folder is not reported). The action “Attach Remote…” is available whenever the file lists a machine. ssh is looked up in PATH, as agterm does. Asking the machine and the probe wait 10 seconds for an answer (`the remote did not answer in time`); an ssh answer with a non-zero code is not read as a list: the error is what agshellctl there answered, else what ssh printed, else `the remote command failed on HOST`; an unreadable answer is `the remote did not return a readable session list`. `live tree` takes the host trimmed, and an empty one lists this machine's own sessions. Any network change while the network is up (the network appearing, an address or connection change) starts a reconnect, but the network going away does not.
- `attach_remote` (Ctrl+Shift+R) opens the machine choice (skipped when there is one machine), then the list of its sessions: AgShell runs `ssh -T -o BatchMode=yes machine agshellctl live tree --json`. It needs key-based login, and on that machine OpenSSH Server, `agshellctl` on `PATH` and AgShell in live mode. The user may be an administrator: an ssh login gives them an elevated token, and `agshellctl` still accepts the pipes of an AgShell started without elevation, but only those owned by the same user.
- The chosen session appears in the current workspace as a row marked `@machine`; its panes (and split, if any) attach each through its own `ssh -T machine agshellctl live proxy PANE`, to the daemon `live tree` names for it, as agterm runs one `ssh -tt machine zmx attach` for each pane. Unlike agterm, the ssh has no terminal: Windows OpenSSH would give it a ConPTY, which moves escape sequences ahead of the text, answers or drops queries (DECRQM, `OSC 11;?`) and rewrites others, so the pane's bytes are relayed as they are. A pane's daemon that ended there (or is no longer there) closes the pane here, and closing the row ends its connections. Input and output are shared with that machine.
- When the connection breaks, a pane keeps its last screen; the mouse, focus, paste, theme and size modes the program left on are turned off so their reports do not print over it, and the cursor is hidden. If ssh itself could not connect (code 255, a refused login included), the pane shows the line “Lost the connection · reconnecting…”, and at the bottom of the pane a line “ssh: …” with what ssh said on the last attempt. Each pane waits on its own, as in agterm: a drop of one pane does not touch the other. AgShell, as agterm, checks the machine at once with a short `ssh machine exit 0` and attaches that pane again only once it answers; after a failed check the next one comes in 1, 2, 4, 8, 16, 30 seconds, and after eight failures in a row the delay keeps growing up to 5 minutes, without end. If the connection breaks again within a minute of coming back, the delay keeps growing instead of starting over. A key in a waiting pane checks at once for that pane only; the computer waking up or a network change check every waiting pane; both start the schedule over. With any other exit code the pane keeps what ssh or the other side printed last, plus a line with the machine, session, pane and code; the same happens with code 127 when ssh cannot be started at all (as agterm's attach through its shell); a key (including non-empty `session type` input) closes its pane, like agterm's “press any key” prompt (the main pane gives its place to the split); the row closes with its last pane. Input to the remote row's local split or overlay is not held up meanwhile: only that machine's panes wait. A row closed undoably keeps waiting for the machine; a check that answers meanwhile counts as a failure, so the schedule keeps growing, as in agterm. The screen turning on (as agterm's displays waking) also starts a retry.
- The host shows in the title (a cloud icon and the address; hidden with the “Remote host” switch in the interface settings), in the Ctrl+Tab switcher and in the lists of recent sessions and sessions needing attention. In the sidebar, as in agterm, the row has only the cloud icon, without the address.
- A split that came from the machine is that machine's pane; a split opened on the row later (or after the remote one closed) is an ordinary local shell. The machine's two panes can be swapped here too — that is the local layout, the shells' names do not change there, and the machine's status, HUD, questions and overlays then land on their own pane; the machine's pane and a local one can be swapped too, and the machine's pane stays its pair. When the only pane there ended and the row has a local split open, the split becomes the main pane; the row, as in agterm, stays remote (the mark, the icon, not saved): the status stream goes on while the row is visible, and it has no panes waiting to reconnect any more. If the local split has not started yet, the main pane is not closed, so as not to lose it. A remote row has its own icon (a cloud, with a bar when the split came from the machine).
- When the machine no longer has a pane (the session was closed there), its copy here closes without a key press: the split closes; if the main pane ended there and the split is alive, the split here, as there, becomes the only pane; the row closes with its last remote pane unless it has a local split. Which pane left the row learns, as in agterm, from the pane ids the machine sends in the layout frame: if the split was closed there and the panes are swapped here, the local main pane leaves (it showed that split), and the other takes its place. An AgShell older than this version sends no ids, and then the close waits 1.5 seconds for the pane's own exit report. If the row was closed undoably and the pane ended there meanwhile, the undo brings the row back without it. An overlay handed here opens over the row's HUD too (the HUD closes), as in agterm. One session can be attached into two rows: each further row gets its own connection.
- While the status stream is not up, the row's cloud is crossed out, and its tooltip says why — as in agterm, how the bridge ended (`exit N`, what ssh printed goes to the log), a frame it could not read, or 30 seconds of silence; there are no notifications about it, as in agterm. As agterm's bridge, a line over 256 KB ends the read, at most 64 frames wait for the window, and a bridge that stops taking input is ended. Right after a key press under a cover and when a covered pane reattaches, the cover says “Taking over…” until the lead answer comes; while nobody leads the pane, it says “Reconnecting…”. A machine with a too-old AgShell (`unsupported`) has no mark: nothing can be done about it here.
- A context sent over that fails the local check (one line up to 256 bytes) is not shown; neither is a HUD whose time ran out on the way, and one already shown comes down, as in agterm. A sound that does not exist here is replaced by the system beep.
- A status set there by a pane that has no pair here (the machine's scratch, or a split closed on the row) belongs to the row as a whole: key presses here do not clear it.
- Remote rows are not saved in the state (neither themselves, nor their place in the recent order, nor the selection of a closed workspace) and do not go to recently closed: the machine keeps the session. Next to `session.created` and `session.closed` such a row sends `remote.opened` and `remote.closed` events with the machine's address in `host`. `remote.opened` follows `session.created` right away. As in agterm, `session.closed` (and `remote.closed`) comes when the row leaves the tree, that is right at an undoable close, and the undo sends `session.created` (and `remote.opened`). While a closed row waits for the final close, its status stream is stopped: the presenter role is released, questions handed to it are returned, and the undo starts the stream again.
- `agshellctl live tree HOST` and `live attach HOST ID` refuse an address that is empty, contains spaces or control characters, or starts with `-` (ssh would take it for an option). `session restart` on a remote row refuses as a whole, as in agterm, the local split included.
- In `tree --json` a remote row has `remoteHost` and `presentation`: `state` (`connecting`, `connected`, `failed` with the reason in `error`, `unsupported` for a machine with a too-old AgShell) and `mode` (`presenter` or `mirror`); `connected` speaks of the status stream only, not of the panes. A session other machines read has `presenters`: `mirrors` (how many machines only mirror) and `presenter: true` when one presents it. A remote row's pane waiting to reconnect has `reconnect`: `failures` (failures in a row) and `reason` (what ssh said on the last attempt).
- A duplicate of a remote row and a new session “in the current session's directory” are an ordinary shell of this machine (the default profile) in the focused pane's directory if it exists here, otherwise in the home folder. The machine's Linux path is not used for WSL here. If a remote row is selected on quit, the selection of this machine's last session is saved; a recently closed workspace's session count does not count remote rows. The `attach_remote` key is not taken by default if keymap.conf already gives it to another action or command (as agterm does for configs written before the action).
- A remote row's directory is the machine's directory. Local launches (scratch, an overlay without `--cwd`, a split, custom commands, the quick terminal) start in it when the same directory exists here, otherwise in the home folder.
- A context set on the remote row here wins over the one sent; after clearing it the sent one shows again.
- If `ssh -G` with the same connection options says `serveraliveinterval 0` (not set in the config), AgShell adds `ServerAliveInterval=5` and `ServerAliveCountMax=2`, so a dead connection is noticed in about 15 seconds. A value of your own in the config turns this off; if `ssh -G` did not answer, no options are added. As in agterm, `ssh -G` is asked on every attach, so an edit of the ssh config takes effect without a restart.
- The agent status, context, HUD and `agshellctl notify` notifications of that session show on the row. For this each row runs a separate `ssh machine agshellctl live present ID`: it sends a snapshot first, then changes, and a ping every 10 seconds. OSC 9/777 notifications are not forwarded: they arrive as bytes in the pane itself and fire here on their own. If the stream breaks or is silent for 30 seconds, everything it put on the row is taken off, and the stream restarts with the same delay as the panes. A snapshot after a reconnect does not clear a status set on this machine. As in agterm, AgShell on that machine pushes each change as the session changes: `live present` holds a connection to it and only relays it, and when the connection closes the presenter role goes back at once.
- **The leader** (like agterm's lead): each pane has one leader, and the program sees its size. Attaching takes the lead of all the session's panes, and the same panes on the machine where the session runs get a cover “In use from another machine” (on the attached machine the covered pane says “In use on the machine it runs on”), with an icon and the hint “Press any key to use it here”. A key pressed in a covered pane (it is not typed itself) or `session lead` takes the lead and covers the pane on the other side. As in agterm, taking the lead is a fresh attach: the pane lets go of its daemon, which keeps the shell, and joins it again with a new terminal laid out from the daemon's snapshot at this window's size, under “Taking over…” until the daemon answers; a pane already on its way is not taken again; a click on the cover only moves the focus into the pane. The take-over key “latches”: its auto-repeat does not reach the program until it is released; the same goes for a key that retries an attach. A covered pane keeps the leader's size, so its screen and what scripts read from it match what the program draws. Dashboard tiles have the cover too. As agterm's `covered`, a pane is covered while another side leads it, while nobody leads it, and while it joins again and has no lead answer yet. Terminal replies to the program's queries and focus reports do not take the lead and are dropped while the pane is covered. On the machine where the session runs, `session type`, `session text` and `surface cursor` work with a covered pane too: they go through the session itself, and the text and the cursor come from its daemon's terminal, laid out at the leader's size; `session paste`, `copy`, `select-all` and `search` (except `--close`) act on the terminal itself and refuse: `pane is covered while another machine leads it; take the lead first (session lead)`. On the attached machine a covered pane refuses them too (`pane is in use on the machine it runs on; take the lead to drive it from here`) until it becomes the leader. When the leader leaves, nobody leads: the remaining panes say “Reconnecting…” and join again without a claim, as agterm's, so the first back leads. A pane back after a break does not take the lead: if the other side leads already, it comes back covered; if nobody leads, it becomes the leader, as in agterm an attach “without a claim” leads until someone takes the lead. A window's own pane opening on its daemon (at launch, or when the window comes back) joins without the claim too, so a pane another machine leads comes back covered. A pane joining again never starts a shell: if its daemon is gone, the pane ends with `agshell: session is gone`.
- The remote row's attached panes follow the machine's split: the direction, hiding and showing, swapping the panes (the daemons keep their names, the layout says where each now stands, and the row swaps its terminals together with their scrollback, without reattaching). The row does not open a new pane: a split opened there after the attach needs the row attached again. A split closed there closes here too. Its own panes, ratio and focus stay local.
- **The presenter** (as in agterm): one of the attached rows presents the session — the first whose `live present` stream asked for the role while it was free. As in agterm, the stream opens with a hello both ways: this machine names the kinds it speaks (questions with fields and choice lists, pages) and asks for presenter mode, the session's machine answers with what both speak, and the stream then asks for the role once (`presenter.acquire`, answered granted or refused); the others mirror and ask again only on their own reattach. A closed stream gives up the role at once, and so does one that has not answered the ping sent every 10 seconds for 30. A question with a text field, a choice list or a cancel button goes only to a presenter that speaks forms, and one with a free-form row only to one that speaks that too. As in agterm, a stream that sends no hello within 10 seconds is closed, and so is one whose first frame is not a hello, whose hello has no version 1 or later, or that sends a frame it cannot read. Frames are agterm's: one JSON line each, with `kind`, `gen` (the stream's generation on the session's machine) and `rev` (counting its frames), and the body under the key of its kind; a viewer takes nothing before the answer to its hello and drops frames of another generation or out of order. Panes travel by their stable id (`AGSHELL_PANE_ID`), never as left or right, so a swap on either machine cannot misroute a status, HUD, question, overlay or page; the layout names the panes, the one in the main place and the axis, and a layout that does not hold together is logged and skipped while the rest of the frame stands. AgShell before this version cannot show this machine's statuses, and the other way round: update both machines. A new `agshellctl ask` question in this session goes to the presenter (where the user sits) if all the panes it needs are followers here: the question's pane, or all panes for a session-wide question. Otherwise the question stays here; a question already open does not move when the leader changes. As in agterm, while the session has a presenter, a question for `--pane right` of a session without a split answers `session has no split`, even one that would stay here. On the presenter the question is drawn on the remote row, and the answer goes back to the calling program as usual. If the presenter cannot show it (the slot is taken, a GUI question for a session not selected), the question was cancelled there or the stream went away, the question comes back here and waits as an ordinary one. The presenter's answer is checked against the question's form, as in agterm: a known button, field text within 64 KB and without forbidden control characters, list choices in its order (exactly one for a single choice), text for the “other” row only with it; an answer the form could not give is rejected, and the question keeps waiting. A handed-over question waits here in its session's slot, not the window's, even a GUI one, and the session need not be selected to hand it over: it is not drawn here. A GUI question that came back here needs the window's slot and a selected session; without them it ends `cancelled` with `reason: presentation-lost`. The GUI copy of a question on the presenter also waits in the session's slot and refuses when the session is not on screen (not selected, hidden by another pane's zoom or covered by the dashboard). A question that, together with the largest allowed answer, does not fit into a 256 KB frame stays here. `--follow` on a handed-over question does not raise the window here. A HUD for the right pane that the row does not show (the split is hidden or opened here) covers the whole session; the presenter does not accept a question or an overlay for it.
- An overlay with a program (`session overlay open COMMAND`) goes to the presenter by the same rule. No panel opens here, and `session overlay result` waits for the result. The presenter opens an overlay with `ssh -tt machine agshellctl session overlay run-job JOB`, and the program runs once here, in that ssh's terminal, in the session's directory and environment. The exit code comes to `session overlay result`; a job that ended without a code is the error `overlay ended: launch-failed` (or `canceled`, `unknown`), which `overlay open --block` prints too. If nobody took the job within 30 seconds or the presenter cannot show the overlay, the result is `launch-failed`; if the helper's connection closed before it reported how the program ended, `unknown`. As in agterm, the helper claims the job and keeps that one connection: the app sends it what to run and, on a cancel, a request to stop, and the helper reports the start and the end on it. While the job runs, and with `--wait` while the presenter shows the result screen, its slot here is reserved: another overlay will not open in it, but a HUD will (nothing covers the session here); handing the overlay over takes the HUD out of the slot by itself. If the copy was closed on the presenter while the program runs, the slot is held until the helper's report. If the presenter left, a job nobody took becomes `canceled` at once. The last 32 finished jobs are kept. The slot follows its pane when the panes are swapped and when the split moves into the main pane's place. `session overlay close` here cancels the job (the program ends, the result is `canceled`) or takes away the result shown; the overlay on the presenter closes. `session overlay resize` here resizes the overlay on the presenter; `--follow` selects the session on the presenter. `session overlay text` for an overlay the presenter draws answers `overlay is shown on another machine`, and opening another overlay in its slot `overlay already open`. If the slot holds a HUD now, `session overlay result` answers `no overlay result: the slot holds a hud`. A link that cannot open over the session because of the presenter or a taken slot opens in the browser. An overlay cannot be handed into a slot where a local overlay is open (`overlay already open`). If the stream went away, the running copy on the presenter closes together with its ssh, even with `--wait`. In `tree` a session shows the slots reserved for the presenter (`remoteOverlays`), and a question `remote` (handed to the presenter) or `replica` (handed here). A job also ends when its session is closed here (an undoable close included: the undo does not give the slot back), the right pane it was in, or the main pane whose place the split took: the slot is freed at once, and the result is `canceled`. Restarting a pane's shell cancels the job of its slot, but the slot is held until the helper's report, and the result is whatever the program ended with. `open`, `close` and `result` with `--pane right` work with a hidden split too. With a page in the slot, `result` answers `no overlay result: the slot holds an html page`. A HUD's text is limited as in agterm: 256 characters (4096 with `--markdown`), the label 256. The helper runs the program with the directory, environment and command it had when the overlay opened; if the directory is missing or the program did not start, the result is `launch-failed`, and the helper exits with 127. Losing the connection to the app does not stop the program: the helper waits for it. Losing the terminal (ssh closed) cancels the job. A cancel, as agterm's SIGTERM and SIGKILL after 3 seconds: the helper's console gets Ctrl+C (the helper itself ignores it), and whatever of the program and the processes it started is still running 3 seconds later is ended; the result is `canceled` only after all of them are gone. `session overlay resize` refuses when the stream the job was handed to has left. When the overlay is closed on the presenter, this side learns at once: a job nobody took, as in agterm, waits for its deadline and becomes `launch-failed`, a running one holds the slot until the helper's report, and a result shown frees the slot. Closing the session here (an undoable close included) drops the presenter role at once.
- **A web page** (`--url`), as in agterm, opens on the presenter by the same rule if that machine shows pages itself (AgShell of this version or later): it loads there with that machine's network and storage (`--persistent` is that machine's profile). Here the slot is taken, `overlay open` returns the page's id, and `overlay result --page ID` waits for its outcome; on the presenter the page has `replica: true` in `htmlOverlays`, here `remote: true` with the state, address and title the presenter reported, and `pageID` in `remoteOverlays`. A loopback address (127.0.0.1, ::1, localhost) names this machine and is not handed over (`a loopback url names this machine, so the machine presenting the session cannot load it`); `--width`/`--height` are not supported for it. From here `close`, `resize --size-percent`/`--full`, `reload [--current]`, `navigate back|forward|browser` and `hide|show|toggle` (the reply does not wait for that machine) reach the presenter; `navigate finder` and an address in `navigate` answer `page is shown on another machine` (`navigate finder` for a web page, `show in Finder requires a file page`, as in agterm), and `submit` answers the page here and closes it there. The page closing on the presenter, the presenter refusing to show it, or the presenter leaving close it here unanswered (`dismissed`). If this machine leads the panes itself, the page opens here, like a program. An older presenter that does not show pages gets the old refusal (`a viewer presents this session: an html overlay would open where nobody sees it`).
- **A file page** (`--html`) goes to the presenter by the same rule. The presenter reads its files from here over a page channel, `ssh machine agshellctl session overlay page-serve TOKEN`: the file itself, and with `--cwd` the files inside that directory, with links and junctions followed before the check, so one leading out of the directory is refused (`file is outside the page's folder`). As in agterm, AgShell here holds the channel and reads the files, `page-serve` only relays it; a file comes in 64 KB chunks with its type, at most 8 requests are in flight at once (the rest wait on the presenter), and a load the page stops is cancelled here. On the presenter the page loads from its own address under `localhost` (`http://r<secret>.localhost:<port>/`), served by AgShell on the loopback interface: WebView2 hands an intercepted response to the page only once it is whole and does not report a stopped load, so the page is served over a socket, which streams each chunk as it arrives. Only that page's secret name is served, and only while the page is open. As in agterm, the token is single-use: the presenter starts the channel when the page opens, and a page whose channel was not claimed within 30 seconds closes unanswered; the channel then serves only while the page is open and its presenter is the one it was handed to, and when the channel ends the page closes on both sides. In `htmlOverlays` here it has `file` and `cwd`; on the presenter only `file`, as in agterm, and a file the channel did not bring shows as the load's error with the reason that machine gave. As in agterm, `htmlOverlays` lists pages by slot (the session's, the left pane's, the right pane's), whichever machine shows them; a presenter refusing a page tells the session's machine why, and that machine logs it. On the presenter its strip has no “Open in browser” and “Show in Explorer” buttons, as in agterm, and `navigate browser` here answers `page is shown on another machine`. Its bridge (`data-agshell` buttons, `agshell.request`) works as on a page shown here: as in agterm, its requests go back over the same channel and run here, with the page's session and pane filled in where the page left them out, and the answer reaches the page as sent; `session.overlay.submit` from the page answers it here and closes it there. Requests that hold a stream or serve a helper (`session.overlay.job.run`, `session.overlay.page.serve`, `live.present`, `live.presentation`, `live.answer`), and `live.reset`, whose work comes after its answer, as in agterm, are refused from any page (`... cannot be sent from a page`).
- A sound without a name on the presenter is its own blocked sound, and when there is none or that sound does not exist on this machine, the system beep.
- The blocked sound from the settings plays only on the change to blocked; a repeated blocked is silent; `--sound NAME` sounds on every write; `--sound ""`, as in agterm, counts as no name, so the blocked sound plays on the change to blocked. As in agterm, the same sound again within 200 ms stays silent (a burst of writes does not stutter); a different sound always plays, and the settings' preview is never held back. As in agterm, NAME is `default` or `beep` (the system alert) or a sound of `C:\Windows\Media`; an unknown one is refused (`unknown sound: …`, with the list) and the status stays as it was.
- A status sound (`--sound` or the blocked sound from the settings) plays on the presenter, not here, when another machine leads the pane that set the status and the presenter's hello listed sounds (as in agterm; otherwise it plays here). The blocked sound then comes from the presenter's settings.

## Undoing a close and recently closed

```
agshellctl recent list                 # recently closed sessions and workspaces, newest first, with ids
agshellctl recent open [ID]            # reopen (the last one by default); an id or a unique prefix
agshellctl recent clear
```

As in agterm:
- **Undoing a close.** A session or workspace closed from the window (Ctrl+Shift+W, a menu, the palette) leaves the tree at once, but its shells live 3 more seconds. An “Undo” bar shows at the bottom. Ctrl+Shift+Z (`undo_close`) brings them back to their place alive, with their output. The `session.closed` event goes out at once, and an undo sends `session.created` again. After 3 seconds the close becomes final. An undo selects the session that was selected before the close; the sessions keep their place in the Ctrl+Tab order until the close is final. The undo can be turned off in the settings (General). `session close` and `workspace delete` from agshellctl close at once.
- **Recently closed.** Every close is remembered in `%APPDATA%\agshell\recent-closed.json` at once, as in agterm (an undo takes the entry out again): the last 20 entries, one per session or workspace. Until the undo bar goes, the state file still holds what was closed, so a crash in those seconds loses nothing. Ctrl+Alt+Shift+T (`reopen_recent`, as agterm's Reopen Last Closed Item) brings back the latest entry at once; the whole list is the File ▸ Open Recent menu, as agterm's: the sessions first, then the workspaces, a workspace with its number of sessions. An entry comes back with fresh shells: the directory, name and split; a session to its place in the tree, a workspace, as in agterm, last. A session still inside its undo window comes back alive, and one already open is only selected. A workspace first takes back its sessions still inside their undo window; if it is open, it gets only the sessions it lacks. If every session of a closed workspace is already open, one of them is selected instead. The list ends with “Clear Menu”, as agterm's Clear Menu (`recent clear`). Ctrl+Shift+Z (`undo_close`) works only while the undo bar is up; otherwise, as in agterm, the key goes on to the terminal, and in a text field of the interface it stays the field's own undo.
- **Windows.** The list is one for the whole app, and all windows write to it. `recent open` brings an entry back into the window from `--window`, which must be open (otherwise `window not open — window.select it first`), otherwise into the front one; as in agterm, the window is checked before the entry. `recent list` and `recent clear` are app-wide: a target or `--window` sent over the pipe is refused with `<cmd> takes no target or --window`. An id prefix that fits several entries is refused as any other target is: `ambiguous recent item prefix '…' → …`. As in agterm, the window that holds the session itself (open or inside its undo window) comes first, then the one that holds its workspace; the window is not raised. Sessions another window holds are never rebuilt under the same id. The entry stays in the list if some session of it ended up nowhere; `complete` in the reply says whether it left the list. If nothing came back, the error is `could not reopen <id>`. If the list could not be written, `recent clear` answers `could not clear recent items`, and the list stays as the file holds it. From the palette and with Ctrl+Alt+Shift+T, into its own window by the same rule, and if the entry went to another window, that window comes to the front. The 3-second undo is separate for each window.

## Themes and settings

- **Window title bar (first 5.8 slice).** The shared native frame shows read-only workspace/session/custom window identity, using the selected session's workspace and focused main/split details. Normal shows context instead of the detail; compact puts context after the identity/host. Existing Interface toggles and toolbar mode settings apply, with unchanged defaults. Hidden keeps native top frame plus a 3 DIP drag strip in normal windows (7 px total at 96 DPI), and 3 DIP when maximized. Normal/compact retain system caption buttons. Existing toolbar actions/popovers remain on the page below the menu; commands and shortcuts keep their previous paths. Fullscreen retains the product menu reveal.

```
agshellctl theme list                              # "default ghostty" and the installed themes; the one in force is marked *
agshellctl theme set "Gruvbox Dark"                # the theme; the dark one, if set, is kept
agshellctl theme set --dark "Dracula"              # a dark theme: the terminal switches with the Windows mode (with no theme, the light one becomes Builtin Light)
agshellctl theme set --dark none                   # stop following the Windows mode
agshellctl theme set                               # no theme: Ghostty's colors ("default ghostty"); the dark one is cleared too
```

- **Themes** are in Ghostty's format, as in agterm. About 800 themes from [iTerm2-Color-Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes) are built in, plus AgShell's own `agshell` theme, which a fresh install starts with. As in agterm, there can also be no theme: "default ghostty", the terminal's own (Ghostty's) colors; it is not offered while the terminal follows the Windows mode, since the pair needs two themes. A `settings.json` without a theme means "default ghostty". Your own themes go as files into the `themes` folder of the config folder (`%APPDATA%\agshell\config\themes`); a theme with the same name replaces the built-in one. A theme that does not load (no such file, a relative path) leaves the terminal in Ghostty's own colors, as Ghostty does, and is reported among ghostty.conf's problems in Ghostty's words: `theme "X" not found, tried path "…"`. As in agterm, the list is sorted alphabetically without regard to case, and `theme set` takes a name exactly as `theme list` prints it: `dracula` is not `Dracula`; spaces and tabs around it are dropped, line breaks are not.
- **`theme.list` and `theme.set` over the pipe**, as agterm's: `theme.list` returns `themes` (the names, without “default ghostty”), `theme` (the single theme; absent for “default ghostty”), `sync` and, while following the Windows mode, `light` and `dark` — `theme` is absent then, the state is in those three fields. `theme.set` takes `name` (or `light`, its alias) and `dark` (`none` stops following) and always answers with the full state, without `themes`. An unknown name is `unknown theme: NAME`; a name together with `--light` is `theme.set takes either a name or --light, not both`. Over the pipe this is the commit: there is no preview, unlike the palette.
- **The window's colors** come from the theme: the sidebar background is the terminal background darkened or lightened by a setting, and the selected row is the theme's selection color. The light or dark scheme of the window and title bar follows the background's brightness; the workspace chevron, like AppKit's disclosure triangle in agterm, is the system gray, light or dark by the brightness of the sidebar with its tint. As in agterm, the Windows accent color (Settings → Personalization → Colors), not the theme's, tints the selected row of the palettes and the session switcher, the highlighted button, the row under the cursor and the checked marks of a gui ask, the switches and sliders in Settings, the drop indicator in the sidebar and the keyboard focus ring, and follows it when it changes; toggle buttons show their state by a filled icon only, and the highlighted dashboard cell is outlined in the theme's text color; the title bar and sidebar footer icons are in the theme's text color too; the highlighted destructive button of a gui ask is the system red with white text, as agterm's; a terminal ask has its field in a thin frame without a background and inverts the row under the cursor (the text color behind the marker and the label, the background color on them); an unavailable palette entry has its title in the Windows 11 disabled text color.
- **“Select Theme…”** in the command palette (`select_theme`) opens on the current theme and shows a theme as you move through the list (as in agterm, 70 ms after the last step, so a held arrow key does not repaint the terminal for every theme). The list has a "default ghostty" row (in alphabetical order, as in agterm), and the current theme is badged `current`. Enter keeps it, Esc goes back to the previous one. If the terminal follows the Windows mode, the theme of the mode on now changes.
- **The settings window** opens from AgShell ▸ Settings… or with Ctrl+,: as agterm's, one window for the app, 540×680, opening on General each time; Ctrl+W closes it. Tabs: Menu shortcuts also work while Settings has focus: Minimize affects Settings, Quit exits the app, and menu-bound keymap actions use the active main window. The default Close Session chord closes Settings; custom commands and leader/monitor bindings do not run there, as in agterm. After focus returns, Windows key state reconciles shortcut ownership: a key released in another application no longer swallows the first new text or shortcut; keys still held keep ownership across AgShell windows.
  - **General:** the interface language (as in Windows, Russian or English); Mouse — scroll speed, right-click paste, where links open (Ctrl+click: the browser or over the session), whether a click on a workspace row folds it (as in agterm, after the double-click interval, so a double click only renames); Sessions — where a new session opens (the home directory, the current session's directory together with its shell, a chosen directory), where it is added, how sessions come back (fresh shells, with their programs, live; applies after a restart), close confirmation, undo of a close, the Flagged layout, and whether programs may write to the clipboard.
  - **Appearance:** the terminal's font and its size (8–32), the cursor shape and blink (as in agterm, “Default” sets nothing: a program's DECSCUSR and DECSET 12 decide; an explicit blink choice holds against DECSET 12), the theme of the current Windows mode and, while following Windows, the other mode's; then the toolbar style, background opacity 0–100%, background blur, the sidebar tint (“None”, “Lighter N”, “Darker N”), the font sizes of the sidebar and of the palettes and switcher, the inactive pane and backdrop mute. Below 100% opacity the Windows 11 system backdrop shows through the window (Mica, with blur Acrylic); Windows does not offer a blur strength, unlike agterm, so blur is a switch, off at 100%. Without blur agterm's window shows what is under it; Windows draws black under the page when there is no system backdrop, so Mica, the wallpaper's tone, stands in. As in agterm, the title bar is part of the translucent surface, and a window in full screen is opaque, the saved opacity left as it is. Needs Windows 11 22H2 or later.
  - **Interface:** which title bar elements and sidebar buttons show (two to a row, as in agterm), hiding the sidebar in inactive windows, and the quick terminal's size: Default (90 %, but no more than 1100×700) or 40–90% of the screen.
  - **Notifications:** the toast, counters on rows and, as agterm's Dock badge, their total over the open windows on the taskbar button (an overlay, up to 99; the same switch hides both, since Windows draws no count on the icon of an app that is not packaged), flashing the taskbar button (by default it does not flash, like the Dock in agterm), the toast's sound (silent, the default as in agterm; default, message, mail, reminder, SMS; a sound plays as it is chosen) and the attention bell in the title bar.
  - **Agent statuses:**
    - each status's color and shape on one row;
    - which key clears `blocked` and `completed`: any, only Enter (then Esc and Ctrl+C clear `blocked` too) or none;
    - the sound on `blocked` from `C:\Windows\Media` (it plays as it is chosen);
    - auto-follow, as in agterm. When the user has not pressed or chosen anything for so many seconds, the window moves to the session that has waited longest for an answer (`blocked`). If the current session is `blocked` itself (or `active` with “Auto-follow away from a running session” off), the window stays on it. It does not pull a second time to a session it already moved to and the user left, until that session becomes `blocked` again. While a palette, a title bar list, the dashboard, a pick or an ask is open or a rename is going on, auto-follow waits; a jump that falls due then is dropped until the next key or status change.
  - **Key Mapping:** the keyboard layout, the config directory (`configDirectory`, as in agterm; its path is always shown): “Choose…” moves the reading of `keymap.conf`, `hooks.conf`, `ghostty.conf` and `remotes.conf` to another folder (into dotfiles, say) and reloads them at once, an empty folder gets starter files, “Use Default” goes back; the path of your themes folder; then Diagnostics (the problems of `keymap.conf`) and Hooks (those of `hooks.conf`), each with “Reload”, which reads that file only. As in agterm, the files open from the menu and the palette (“Edit Keymap”, “Edit Hooks”), not from here.
  - The labels are agterm's, with Windows for macOS and the taskbar for the Dock; the Russian interface translates them. Picking “Custom directory” for new sessions sets it at once, with “Not set” until a directory is chosen. Turning “Follow system appearance” off keeps the theme on screen (in dark mode the dark one becomes the theme). The opacity slider shows as you drag and saves 0.3 s after it stops or on release; with transparency effects off in Windows the sliders stay usable and the saved values apply once the effects are on. An explicit change of anything the settings write into the terminal's config (font, size, theme, following Windows, cursor shape and blink, opacity crossing 100%, scroll speed, right-click paste) or of the config directory resets every session's Ctrl+=/Ctrl+- size, as in agterm.
- **Storage:** the settings live in `%APPDATA%\agshell\settings.json`, apart from the session tree. As in agterm, only changed fields are written, keys in alphabetical order; a field set back to its default is removed. A file that cannot be read gives temporary defaults, but writes stay blocked until it is successfully read after restarting. A file that does not parse is kept as a unique `settings.json.corrupt-<time>-<id>` before defaults can be saved; a failed backup blocks writes too. A failed write is logged and reported by a notification when notifications are enabled; the next change retries it. `restore mode`, `theme set`, `browser links` and `sidebar flagged-layout` report an error and keep their previous values when they cannot save. Values are taken as written: the terminal font size and scroll speed as they are, a quick terminal size outside the list means Default. The names AgShell 0.1 wrote (`activeStatusColor`, `notificationSound`, …) are read once into agterm's (`activeStatusColorHex`, `notificationSoundName`, …).
- **Log:** as agterm writes to the macOS system log, AgShell writes to the Windows event log, under the AgShell provider, with agterm's category and level: error, warning and notice go to the `AgShell/Operational` log, info and debug to `AgShell/Debug`. The Debug log is off until an administrator turns it on (`wevtutil sl AgShell/Debug /e:true`), as macOS keeps info and debug only when asked. Read them in Event Viewer ▸ Applications and Services Logs ▸ AgShell (the Debug log shows under View ▸ Show Analytic and Debug Logs), or with `Get-WinEvent -LogName AgShell/Operational` (`-Oldest` for `AgShell/Debug`); the message is `[category] text`, and the category is also the event's first field. Windows keeps each log, 1 MB by default, overwriting the oldest. The provider has to be registered once, which takes administrator rights: the installer does it, and Help ▸ Register Event Log… does it for a copy run without the installer (the folder it is registered for is the one whose `AgShell.EventLog.dll` holds the messages; run it again after moving the folder). Registration grants the Windows Event Log service read access to that DLL only, so Windows can decode events from a per-user installation; it preserves other file permissions and inheritance and does not change folder permissions. Until it is registered, error, warning and notice go to the Application log under the source AgShell, and info and debug are dropped. `wevtutil um AgShell.man` beside `agshell.exe` unregisters it; uninstalling does it for the installed copy. Live daemons log as agterm's zmx does, every level from debug: each daemon into `%TEMP%\agshell-USER[-HASH]-live\logs\<its pipe>.log`, and the window and `agshellctl live proxy` reaching them into `live.log` beside, zmx's `zmx.log`. As zmx's, a daemon follows its shell's working directory by what the terminal last reported with OSC 7, or with OSC 9;9 as AgShell's shell integration does (`set cwd=… path=…`; the path is empty for a directory on another machine, such as one reported from inside ssh); `live list` does not show it, as agterm's does not. Past 2 MB such a file starts empty again. zmx never removes its logs, they live in `/tmp`; here each launch of the window removes those written before Windows last started.

## Menu bar

As in agterm, the window has a menu bar: below the Windows caption, in the theme's colors. Menus open on a click. The menus themselves are the system's, dark or light with the theme, as macOS menus are with the appearance; an open menu does not take the keyboard from a field being edited. The arrows, Enter and Esc work in an open menu, Left and Right move to the next menu, and hovering another title opens it. Alt and F10 do not open the menus: they are the terminal's keys, and agterm's menus have no access keys. An item is enabled exactly when its action can run from the palette or its keys, and shows its keymap.conf chord (when that is a single chord).

Settings…, Quit AgShell and Minimize have fixed chords, as agterm's stock macOS menu items: Ctrl+, (⌘,), Ctrl+Shift+Q (⌘Q) and Ctrl+Shift+M (⌘M; Ctrl+Q and Ctrl+M belong to the terminal). As in agterm, Ctrl+Shift+Q and Ctrl+Shift+M give way to a keymap.conf `map` on the same chord (the menu then drops the label), and Ctrl+, does not.

- **AgShell:** “About AgShell”, “Settings…” (Ctrl+,), “Reset Live Sessions…” (only in live mode), “Quit AgShell” (Ctrl+Shift+Q).
- **File:** windows (“New Window”, “Open Window” — every window, the open ones checked, “Rename Window…”, “Delete Window”), workspaces (new, rename, delete), sessions (“New Session”, “Open Directory…”, “Attach Remote…”, “Open Recent” — sessions and workspaces under their titles, with the time they were closed, and “Clear Menu”, “Reopen Last Closed Item”, “Rename Session”, “Duplicate Session”, “Show in Explorer”, “Close Session”, “Reopen Closed Item”, “Clear Status”), edit and reload keymap.conf, hooks.conf and ghostty.conf, “Close Window”.
- **Edit:** “Cut”, “Copy”, “Paste”, “Delete”, “Select All” — on the field being edited, else on the terminal (cut and delete do nothing there); “Emoji & Symbols” opens the Windows emoji panel.
- **View:** the font size and “Select Theme…”; the sidebar (hide or show, expand and collapse the workspaces, collapse the current one); flagged sessions; workspace focus (focus and unfocus, add to focus, the filter, clear focus); the splits, swapping panes, the scratch, overlays, “Find…”, the quick terminal, the terminal zoom; “Toggle Full Screen” (F11).
- **Navigate:** the session, command and custom command palettes, attention, the dashboard; the previous and next session, attention session, the first and last session, the previous and next workspace and window; focus on the left (top) and right (bottom) pane.
- **Window:** “Minimize” (Ctrl+Shift+M), “Zoom” (maximize or restore), “Bring All to Front” and the open windows, the current one checked.
- **Help:** “Developer Documentation…”, installing agshellctl, the agent status hooks and the skill, and “Register Event Log…” (see Log above).

In full screen there is no menu bar, as on macOS: it appears over the window when the pointer reaches the top edge of the screen and hides when it leaves.

## Keys, custom commands and event hooks

```
agshellctl keymap reload                      # reload keymap.conf only, print the number of problems
agshellctl keymap list                        # the keys in force, custom commands, global-hotkey, errors
agshellctl keymap run "Name" [--target S]     # run a custom command for a session
agshellctl hooks reload | list                # the same for hooks.conf; list shows run and failure counters
agshellctl config reload                      # reload ghostty.conf, print the number of problems
```

Both files live in the config folder, as in agterm apart from the state: `%APPDATA%\agshell\config` (with `AGSHELL_STATE_DIR`, its `config` subfolder; the folder chosen in the settings wins). Files an older version kept in `%APPDATA%\agshell` move there once on launch; a file already in the config folder stays. On first launch starter files with commented examples appear there. A saved file applies at once; if it has errors, a notification comes. From the command palette the files open with “Edit Keymap” and “Edit Hooks”: in the editor from `VISUAL`/`EDITOR` over the session (an empty `VISUAL` gives way to `EDITOR`, as in agterm), otherwise in Notepad. As in agterm, with an editor nothing opens without a session or while a program or page holds the session's slot, and a hidden one beeps.

**ghostty.conf** is agterm's AgShell-scoped Ghostty config, beside `keymap.conf`: keys in Ghostty's syntax for the terminals (`key = value`, `#` comments, an empty value resets a key, a later line wins, `config-file = path` includes a file, `?path` one that may be missing). AgShell's terminals are xterm.js, so only these keys take effect, and any other one is reported as a problem: `copy-on-select = true|false|clipboard` (true: a mouse selection goes to the selection clipboard; clipboard: to the clipboard as well), `clipboard-read = ask|allow|deny`, `clipboard-write = ask|allow|deny` (the setting “Programs may write to the clipboard”, once changed, wins, as agterm's settings win over the file), `mouse-hide-while-typing`, `title` (a fixed title in place of the titles programs set), `cursor-click-to-move` (Alt+click moves the cursor; off by default, as in agterm), `desktop-notifications` (false drops the notifications programs send with OSC 9 and 777), `window-padding-x` and `window-padding-y` (one number, or two separated by a comma; 8 and 6 by default), `scrollback-limit` (bytes, as Ghostty's; about 1000 bytes a line, 10 MB by default), `theme` (as Ghostty takes it: a theme name, an absolute path such as `C:\themes\mine`, `~\` or `~/` for the home folder, or `light:NAME,dark:NAME` switching with the Windows mode; it applies while the settings have no theme, “default ghostty”, as agterm loads the file before its settings). The starter file is comments only. With `VISUAL`/`EDITOR` set, the file is reloaded when its editor overlay closes, only if the contents changed; saving while the editor stays open does not apply it. With Notepad or external edits, apply changes with `config reload` or “Reload ghostty.conf” in the palette; problems come as a notification with their number, as agterm's: “N issues in ghostty config — see Event Viewer, then Reload ghostty.conf” (each problem is in the event log, as agterm's are in Console), and `config reload` prints their number.

For the other supported scalar keys, direct lines are read first, then includes in breadth-first order, so an included value overrides a direct line even when the include directive appears earlier. An empty `config-file =` clears the pending include list. Invalid values are reported and keep the last valid value; an empty scalar resets its default.

For `font-family`, `font-size`, `cursor-style` and `background-opacity`, the order follows agterm: direct lines in ghostty.conf, then Settings, then `config-file` includes (breadth first). An unset font size or cursor shape inherits the file; an explicit choice, even the default 13 or block, overrides its direct scalar value and survives restart. Font families accumulate as a fallback list: the file's families come before a family picked in Settings; an empty `font-family =` clears the list. `cursor-style` accepts block, bar, underline and block_hollow. With no font size anywhere the size is 13. These resolved values are applied without copying them into settings.json; reloading recomputes them and clears session zoom.

`background-opacity` is the renderer's opacity (0–1), separate from Settings' window opacity. With no window setting, or at 100%, the window underneath stays opaque and the file controls the renderer. A window setting below 100% makes the renderer transparent and the window supplies the tint; an include can override that renderer value too. As in agterm, moving the window slider to 100% clears its saved setting; a manually saved JSON value of 1 is preserved on save. Existing explicit settings are kept; no settings migration is needed for these keys.

**keymap.conf**, in agterm's format:

```
map ctrl+shift+l  toggle_split                       # rebind an action
map ctrl+a>ctrl+n --repeat  next_session             # a leader sequence; --repeat: repeat the last chord within 0.5 s
command "Open in VS Code"  ctrl+alt+o  code "{AGSHELL_SESSION_PWD}"
command "Build"  ctrl+a>b --error-hud [--error-position top-right] [--error-pane left|right]  build.cmd
global-hotkey ctrl+alt+space                         # a system-wide key: shows and hides the quick terminal
```

- **Chords** are written as `ctrl` (`control`), `alt` (`opt`, `option`), `shift`, `super` (`win`, `cmd`, `command`, the Windows key) and a key joined with `+`; modifiers may follow the base key. Keys: letters, digits, `` `-=[]\;',./ ``, `tab`, `space`, `enter`, `backspace`, `delete`, `home`, `end`, `page_up`, `page_down`, the arrows `left right up down`, `f1`–`f20`, `kp_0`, `kp_add`, `kp_subtract`. A key counts by its physical position, so the keyboard layout does not matter. Alternatives are separated with `|`, the steps of a sequence with `>`. As in agterm, `map CHORD [--repeat] ACTION`: the first single-chord alternative may go without a modifier (not a bare arrow), the others need one on their first key, and each one breaking a rule is dropped alone with a note in `keymap list`. In a `command` line, a first word that reads as chords but has no modifier keeps the command in the palettes only, the word staying part of the shell line. A `#` after a space, outside quotes, starts a comment.
- **Conflicts** are resolved as in agterm. First, one menu chord per action is resolved: an unchanged default beats a remap, and two remaps onto one chord both lose and return to their defaults. All other alternatives share validation with custom commands: a menu chord shadows the start of a sequence; cross-target conflicts drop both sides in one pass, independent of file order. Within one target, the shorter prefix stays. An action losing every alternative gets its default back unless another binding took it. For one action the last `map` line wins. Explicit old uses of the later horizontal split, dashboard, attach remote and overlay defaults stay unless the new action is mapped explicitly.
- **Diagnostics:** `keymap list --json` separates `actions[].chord` (one menu chord) and `alternates` (other chords/sequences); `overridden` compares the menu chord alone with its default. `menu` reports applied items with `menu`, `title`, `chord`, `selector` (AgShell's dispatch id), and `enabled: false` for disabled items. After a reload, the menu may update slightly later than the model. Human output also shows `menu:` and `(disabled)`. `keymap list/reload` are app-wide and ignore target/window in the protocol.
- **Sequences and repeat:** a leader waits 1.5 seconds for the next chord. `--repeat` keeps its prefix while the tail is held and for another 0.5 seconds after release: any repeatable command under that prefix can fire by its tail alone. Ordinary custom/monitor commands do not fire again on autorepeat. Escape cancels and consumes a pending leader; after repeat it closes the repeat window and passes to the terminal. A text field resets leader/repeat and keeps its input; custom commands never fire there. Reload resets the matcher, menu tracking and app deactivation close repeat, and switching between AgShell windows preserves it.
- **The Windows key:** Win is an independent modifier, not an alias for Ctrl. Windows may take system shortcuts. The global chord checks registration conflicts and follows physical position on US, Russian and Dvorak layouts; a layout change is accounted for before the key. The terminal input-source setting confirms the actual switch and restores the earlier layout when disabled.
- **Custom commands** run through `cmd.exe /c` without a window, in the directory of the pane they were run from (the split's own, otherwise the main pane's), which is also `{AGSHELL_SESSION_PWD}`. A keybind uses the terminal surface that actually has focus, including scratch and overlay selection; an overlay supplies the role of the pane it covers. Palette, popover and API runs use main or the focused split, with that terminal’s selection. Palette/popover commands wait while zoom, dashboard, pick or ask holds the UI; keybinds keep their independent route. Detached stdin/stdout and uncaptured stderr go to NUL. With `--error-hud`, stderr uses a temporary file; the last 16 KiB are captured at process exit and the file is removed without stopping background writers. If capture is unavailable the command still runs with stderr at NUL. The line gets the tokens `{AGSHELL_SESSION_ID}`, `{AGSHELL_SESSION_NAME}`, `{AGSHELL_SESSION_PWD}`, `{AGSHELL_SESSION_HOST}` (the ssh address of a remote row's machine, empty for a local session), `{AGSHELL_WORKSPACE_ID}`, `{AGSHELL_WORKSPACE_NAME}`, `{AGSHELL_WINDOW_ID}`, `{AGSHELL_WINDOW_NAME}`, `{AGSHELL_PANE}`, `{AGSHELL_PANE_ID}`, `{AGSHELL_SELECTION}` (the selected text), `{AGSHELL_PIPE}`; the same values are there as environment variables too. Tokens expand in one pass, so a value holding `{...}`, such as a selection, stays as it is; an unknown `{...}` stays too. As in agterm, with no session (an emptied window) a command naming `AGSHELL_SESSION`, `AGSHELL_WORKSPACE` or `AGSHELL_SELECTION` in any form does nothing, since an empty directory there could aim the command at the drive's root; one naming only the pipe, the window or the pane runs. `agshellctl keymap run NAME` needs a session (`no custom command named NAME` for an unknown one), and a command that does not start answers `NAME did not start: …`. `agshellctl` is on `PATH`. When a command ends with a non-zero code a notification comes, and with `--error-hud` also a HUD for 10 seconds, as in agterm: “name: exit N” (or the launch error), with the last non-empty line of stderr without escape sequences under it, all cut to 256 characters. `--error-pane left` always draws it over the left pane, `right` while the split is on screen, otherwise over the whole session. An overlay with a program does not push this HUD out.
- **The palette:** Ctrl+Shift+O opens the list of custom commands (empty when there are none); in the command palette they are marked `custom`. Actions show all their current keys next to them (leader steps joined by `>`, alternatives side by side), and custom commands, as in agterm, their keys as written in keymap.conf (without dropped alternatives, joined by `|`); the title-bar command popover and `keymap list` show them the same way.
- **Copy/paste, Ctrl+Tab and Ctrl+1/Ctrl+2** cannot be rebound: as in agterm, Ctrl+1 and Ctrl+2 focus the left and right pane and are never passed to the terminal; a `map` or `command` naming Ctrl+Tab or Ctrl+1/Ctrl+2 is refused as a reserved shortcut. As in agterm, Esc in the open Ctrl+Tab switcher closes it without switching; with Ctrl still held this is Windows' Ctrl+Esc, and while the switcher is open and the window is in front AgShell takes it, so Start does not open.

**hooks.conf**:

```
on status          C:\scripts\on-status.cmd
on session.closed  echo %AGSHELL_SESSION_ID% >> %TEMP%\agshell-closed.log
```

- **Event kinds** are the same as for `events`: `status`, `notify`, `session.created`, `session.closed`, `session.selected`, `pane.split`, `pane.scratch`, `pane.focused`, `tree.changed`, `app.launched`, `remote.opened`, `remote.closed`. `tree.changed` comes at most once per 100 ms and only says the tree changed.
- **Running:** the line runs through `cmd.exe /c` without a window. The event arrives as one line of JSON on stdin. The variables `AGSHELL_EVENT_KIND`, `AGSHELL_EVENT_STATUS`, `AGSHELL_EVENT_HOST`, `AGSHELL_SESSION_ID`, `AGSHELL_WORKSPACE_ID`, `AGSHELL_WINDOW_ID`, `AGSHELL_PIPE` are set, empty where the event has none, and `agshellctl` is on `PATH`.
- **Queue:** each line has its own queue, and events are handled one at a time. Only the hook process exiting and its stdin closing free the slot; output is discarded through NUL, and a descendant holding stdin does not block cancellation. `hooks.list` and `hooks.reload` reject a target or `--window` before acting. The additional `runs`/`failures` counters are kept across reloads for unchanged hooks. When the queue holds more than 256 events, the oldest are dropped. A failing hook brings one notification; the next comes only after a successful run.

## Sidebar

```
agshellctl sidebar [visibility] show|hide|toggle      # visibility is the default subcommand, as in agterm
agshellctl sidebar width 300                         # in points, clamped to the drag range (160–560), as agterm; prints the width applied. A stored width out of the range is clamped on start
agshellctl sidebar expand                            # expand all workspaces, those hidden by the filter included
agshellctl sidebar collapse                          # collapse all but the current one
```

As in agterm, in the flat list of flagged sessions `expand` and `collapse` do nothing. Full screen is `toggle_fullscreen` (F11).

## Encoding

`agshellctl` writes UTF-8 and gives the console its old code page back on exit. For PowerShell 5.1 to keep non-ASCII text right when saving output to a variable, run `[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)` first.
