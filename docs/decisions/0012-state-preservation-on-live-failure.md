# 0012. Сохранение панели при несовместимом id и отказе live

Статус: принято, 2026-10-29, по решениям пользователя в поручении R1–R3.

## Решение

Старый непустой id панели сохраняется буквально. Если он несовместим с live, затронутая панель показывает явную ошибку и не запускается. Её claim остаётся в inventory; обход неполный, prune и reset запрещены. Автоматической миграции `p…` в UUID нет. Разные записи одного корректного UUID сравниваются как одна идентичность без изменения сохранённых строк; несколько владельцев остаются конфликтом.

Отказ запуска демона, отсутствие исполняемого файла и потеря транспорта без сообщения демона о завершении процесса сохраняют строку, раскладку, id, cwd и claim. Подтверждённый выход шелла штатно закрывает панель. Отказ хранится в необязательном поле `SessionSnapshot.liveFailedPanes` схемы 1; отметка следует за идентичностью при swap и повышении сплита. Повторное открытие окна не запускает замену автоматически.

Запись отметки во время паузы undo сохраняет снимок с pending-строками: ошибка связи не должна превращать ещё отменяемое закрытие в окончательную потерю строки на диске.

Явный Restart сохранённой остановленной панели разрешён через меню и CLI. Без `--command` это новый шелл, без автоматического повтора потерянной программы. Требуются полный inventory и единственный ожидаемый владелец. Если демон ещё существует, он должен подтвердить завершение старого шелла; отказ оставляет панель и отметку. Ответ не содержит `oldPid`, если старый шелл не наблюдался.

Обычный cold restore без ранее зафиксированного отказа сохраняет модель agterm: отсутствующий демон может быть создан с новым шеллом. Такой опыт не считается доказательством сохранения живого процесса.

## Альтернативы

- Выдавать UUID вместо старых id: отвергнуто пользователем, однозначное соответствие старых ссылок и claims не установлено.
- Закрывать строку при ошибке attach как agterm: отвергнуто пользователем для отказов запуска и транспорта.
- Автоматически возвращать новую программу как прежнюю живую панель: отвергнуто пользователем.

## Последствия

Сохранённая строка не означает сохранённый процесс: после смерти демона живой шелл может быть утрачен. Это явно показывается пользователю. Старые сборки, не понимающие отметку отказа, не обеспечивают новую политику; downgrade этой проверкой не подтверждён. Политика целиком повреждённых файлов, неизвестной версии и неверных id сессии/окна этим решением не меняется.
