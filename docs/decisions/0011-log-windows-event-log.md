# 0011. Лог: журнал событий Windows

Статус: принято, 2026-10-27. Заменяет [ADR 0010](0010-log-file-rotation.md).

## Решение

AgShell пишет лог туда, где agterm пишет в системный журнал macOS (`Logger` с subsystem и category, `NSLog`): в журнал событий Windows, поставщик `AgShell` (`AgShell.Protocol.LogEventSource`, класс `Log`). Каналы:

- `AgShell/Operational` — error, warning, notice; включён, как macOS хранит notice и выше;
- `AgShell/Debug` — info и debug; выключен, пока администратор не включит (`wevtutil sl AgShell/Debug /e:true`), как macOS хранит info и debug только по запросу.

Категория — category agterm (поле события и `[категория]` в тексте), уровень — уровень agterm, `NSLog` — notice. Хранение и ротацию ведёт Windows.

Поставщика регистрирует `wevtutil im AgShell.man /rf:/mf:AgShell.EventLog.dll`. Манифест — вывод `EventSource.GenerateManifest`, тест сверяет его с классом. Ресурсную DLL собирают `mc.exe` и `rc.exe` из Windows SDK, `.res` встраивается в пустую сборку `AgShell.EventLog`. Регистрирует установщик (галочка, запрос UAC) и пункт «Справка ▸ Зарегистрировать журнал событий…» для копии без установщика, тоже через UAC, как А82. Удаление снимает регистрацию своей копии. Пока регистрации нет, error, warning и notice пишутся Win32 `ReportEvent` в журнал «Приложение» под незарегистрированным источником `AgShell`; info и debug пропадают.

Файловый лог демонов `agshell-live` (`LiveLog`) остаётся: в agterm демоны zmx тоже пишут свой файл (`log.zig`).

## Альтернативы (проверено опытом 2026-10-27, обычный пользователь)

- **Журнал «Приложение» без регистрации.** Работает без прав, но только Error/Warning/Information, без debug и категорий. «Просмотр событий» пишет «описание не найдено», текст лежит только в данных события. Журнал общий для всех программ. Оставлен запасным путём.
- **Классический источник в своём журнале** (`New-EventLog`, UAC один раз). Текст виден, но уровней debug/info и категорий нет.
- **ETW-сессия или TraceLogging без журнала.** Без слушателя ничего не сохраняется. `logman create trace` обычному пользователю отказывает: «Access is denied».
- **Свой файл с ротацией** (ADR 0010). Не системный журнал, а довод за него опровергнут.

## Почему

Уточнение реализации 02.11.2026: перед регистрацией своей копии службе `NT SERVICE\EventLog` выдаётся чтение только `AgShell.EventLog.dll` (service SID, право `R`), без изменения ACL папок и соседних файлов. Иначе служба LocalService не читает ресурс из закрытого профиля: publisher metadata возвращает Access denied, а Debug — `ProcessingErrorData` 15003 вместо полей/описания. Причина проверена на установленной 0.4.0 сравнением до/после единственного файлового разрешения; пользователь отдельно разрешил это исправление. Порядок важен: доступ к ресурсу должен быть готов до `wevtutil im`. Уровни, поля, каналы, способ хранения и политика снятия своей регистрации сохраняются.

Уточнение ACL 02.11.2026: runner CI41443370266 доказал, что icacls при legacy/noAI ACL сохраняет explicit FullControl и добавляет inherited копии при переходе к AI. Пользователь разрешил заменить этот механизм: обе регистрации читают FileSecurity существующей DLL, добавляют точный service SID Read через AddAccessRule и сохраняют изменённый ACL через SetAccessControl в существующем Windows PowerShell. Ошибка чтения/сохранения прекращает выполнение до wevtutil um/im. Намеренные explicit allow/deny, защита, owner/group и наследование сохраняются; нельзя оправдывать дополнительные explicit права прежним inherited FullControl. Модель системного журнала и UAC регистрации не меняется.

Решение пользователя (2026-10-27): вариант с манифестом и каналами Operational/Debug и запасным журналом «Приложение». Регистрация — установщиком и пунктом меню через UAC, без запроса при запуске.
