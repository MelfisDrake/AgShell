# 0014. Доставка отмены ask/pick перед выходом последнего окна

Статус: принято, 2026-11-02, явное решение пользователя в S6 перед 0.4.0.

## Причина

Blocking ask/pick опрашивают результат отдельными запросами. На собственном стенде закрытие последнего окна уничтожало pipe до следующего опроса: оба клиента получали ошибку соединения и код 1 вместо `cancelled`/2. Это отличается от закрытия одного из нескольких окон, когда процесс и сохранённые результаты остаются доступны.

В agterm e0b4844 `ControlServer+Ask.swift:withAskResult` и `ControlServer+Pick.swift` читают сохранённые результаты с проверкой окна-владельца, включая закрытое окно. `AppDelegate.applicationShouldTerminateAfterLastWindowClosed` разрешает выход после закрытия последнего окна; отдельной гарантии доставки отмены перед завершением в этих путях не найдено. Живой опыт на macOS не проводился: результат Windows не объявляется доказательством поведения macOS.

## Решение

При обычном закрытии последнего окна запоминаются id незавершённых ask/pick. Окно и его терминалы закрываются обычным порядком, формы получают `cancelled`. Управляющий сервер остаётся доступен максимум две секунды, чтобы опрашивающие CLI получили эти исходы. Приложение завершает ожидание раньше, когда ответы обо всех таких отменах действительно записаны в pipe. Ответ `pending`, чужой id, ошибка и сам запрос cancel доставкой исхода не считаются.

Клиент без опросов не задерживает выход бесконечно: по таймеру процесс завершается. Если незавершённых диалогов нет, дополнительного ожидания нет. Появившееся за это время новое окно запрещает завершать приложение старым callback. Уже существующая защита ответа `window.close` сохраняется. Общий Quit и завершение сеанса Windows этим решением не переопределяются.

Сохранённые результаты остаются ограниченными существующими лимитами. Явный `--window` разрешает прочитать исход только своего окна; другой id не получает чужого результата. EOF/ошибка соединения не подменяются отменой на стороне CLI.

## Альтернативы

- Считать потерю pipe отменой в CLI: отвергнуто, потому что авария приложения и штатная отмена неразличимы.
- Оставлять сервер без окна постоянно: отвергнуто, потому что изменяет принятую модель выхода и оставляет процесс.
- Ждать опроса без ограничения: отвергнуто из-за `--no-block` и пропавших клиентов.
- Перенести случай последнего окна в S7: пользователь выбрал исправление в S6.

Корень отступления: [решение пользователя 2026-11-02: до двух секунд для выдачи исходов после закрытия последнего окна]. Это ограниченная гарантия доставки исправному опрашивающему CLI, а не обещание ответа зависшему клиенту после истечения срока.
