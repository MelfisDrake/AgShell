# 0004. API для агентов: named pipe + JSON

Статус: принято, 2026-10-16

## Решение

Приложение поднимает named pipe, доступный только текущему пользователю. Протокол — JSON, одна строка на запрос и одна на ответ. Набор команд повторяет `agtermctl`: сессии, ввод, чтение текста панели, статусы, overlay, окна, уведомления.

## Альтернативы

- **Unix-сокет (AF_UNIX).** Есть в Windows 10, протокол был бы как у agterm на macOS, но для .NET и Windows-инструментов named pipe привычнее.
- **HTTP или gRPC на localhost.** Удобно отлаживать, но порт могут занять, и нужна своя защита от чужих локальных процессов и браузера.

## Почему

Named pipe — родной механизм Windows, в .NET есть `NamedPipeServerStream`, доступ ограничивается ACL без дополнительного кода авторизации.

## Детали (этап 3, 2026-10-17)

- Канал `\\.\pipe\agshell-<пользователь>`, создаётся с `PipeOptions.CurrentUserOnly`. Для другого каталога состояния (`AGSHELL_STATE_DIR`) имя получает хеш каталога, так тестовый экземпляр не отвечает за основной.
- Одно соединение — один запрос `{"cmd","target","args"}` и один ответ `{"ok","result"|"error"}`, строки JSON, лимит запроса 1 МБ. Формат и имена команд и аргументов взяты у `agtermctl`.
- Цель — id, уникальный префикс id или `active`, по имени не ищется.
- Типы протокола, клиент и сервер лежат в `AgShell.Protocol`, выполнение команд — в `ControlDispatcher` в `AgShell.Core`, чтобы их можно было тестировать без окна.
- Справочник команд: [docs/agshellctl.ru.md](../agshellctl.ru.md).

Подтверждено пользователем 2026-10-25 (аудит отступлений): named pipe и ключ `--pipe` остаются, переход на AF_UNIX не делаем.
