# 0002. Эмулятор терминала: xterm.js

Статус: принято, 2026-10-16

## Решение

Эмулятор терминала — xterm.js с аддонами WebGL (рендер), fit (подгонка размера), search и web-links. Текст панели для API читается через buffer API xterm.js, cwd и уведомления ловятся обработчиками OSC.

## Альтернативы

- **Microsoft.Terminal.Wpf** (контрол из Windows Terminal, его использует Visual Studio). Рендер нативный, через DirectX, но:
  - официального пакета нет, на NuGet есть только `CI.Microsoft.Terminal.Wpf` (две версии на октябрь 2026, без документации и гарантий совместимости);
  - публичный API маленький: подключение, тема, размер, `GetSelectedText()`. Прочитать текст экрана и истории нельзя, а для агентов это ключевая функция, пришлось бы держать второй парсер вывода;
  - контрол — `HwndHost`, поэтому поверх него нельзя рисовать WPF-элементы (airspace).
- **alacritty_terminal / wezterm-term.** Rust-библиотеки, только парсер и буфер, рендер пришлось бы писать самому.
- **libghostty** (движок agterm). Целиком под Windows не работает.

## Почему

xterm.js закрывает всё, что нужно agterm-подобному терминалу, из коробки: буфер доступен из кода, есть поиск, ссылки, хуки OSC. Проверен в деле (терминал VS Code), живой и документированный.

## Последствия

- Рендер через WebGL внутри WebView2, а не нативный DirectX.
- Каждая сессия — экземпляр xterm.js на странице; для дашборда с десятками живых сессий понадобится следить за производительностью.
