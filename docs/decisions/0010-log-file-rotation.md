# 0010. Лог: свой файл с ротацией по размеру

Статус: заменено [ADR 0011](0011-log-windows-event-log.md), 2026-10-27. Довод против журнала событий («регистрация источника только через установщик») опытом опровергнут: регистрация делается и из запущенной программы через UAC, а без регистрации Win32 `ReportEvent` пишет в журнал «Приложение» без прав.

## Решение

Что пошло не так, AgShell пишет туда, где agterm пишет в системный журнал macOS (`Logger`, `NSLog`): в файл `agshell.log` в каталоге состояния (`%APPDATA%\agshell` или `AGSHELL_STATE_DIR`). Live-хост пишет свой `agshell-host.log`, поэтому два процесса никогда не делят один файл. Когда файл больше 1 МБ, перед следующей записью он переименовывается в `<имя>.1.log` вместо прежнего: на процесс не больше двух файлов, около 2 МБ. Как в системном журнале, который по умолчанию хранит только notice и выше, пишутся только error, warning и notice. Если запись в лог не удалась, она молча пропадает. Класс — `AgShell.Core.Log`.

## Альтернативы

- **Журнал событий Windows.** Ближе всего к системному журналу macOS, и ротацию делает Windows. Но источник событий регистрируется с правами администратора, то есть только через установщик, а Debug-сборка и запуск без установки остались бы без лога.
- **`OutputDebugString`.** Виден только в отладчике или DebugView, у пользователя ничего не остаётся.
- **Serilog или другая библиотека.** Даёт ротацию готовой, но это зависимость ради нескольких десятков строк кода.

## Почему

Решение пользователя (2026-10-24): лог должен работать без установщика, ротацию делаем сами.
