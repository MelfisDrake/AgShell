# 0001. Интерфейс: WPF + один WebView2 на всё окно

Статус: принято, 2026-10-16

## Решение

Приложение на WPF (.NET 10) — тонкая оболочка: окно, меню, трей, жизненный цикл. Весь интерфейс (боковая панель, палитры, дашборд, overlay и сами терминалы) — одна страница внутри одного WebView2 на TypeScript, сборка Vite. C# и страница общаются сообщениями WebView2.

## Альтернативы

- **Electron.** Зрелый, но тащит свой Chromium (~100 МБ) и Node; бэкенд не на C#.
- **Tauri.** Лёгкий, тоже на WebView2, но бэкенд на Rust.
- **Чистый WPF / WinUI 3 / Avalonia.** Полностью нативно, но палитры, overlay и дашборд в стиле agterm делаются заметно дольше, а нативного терминального контрола с нужным API нет (см. 0002).

## Почему

- Бэкенд остаётся на C#, который знаем.
- WebView2 уже есть в Windows, размер установщика небольшой.
- Один WebView2 на всё окно снимает проблему airspace: WPF не умеет рисовать свои элементы поверх встроенных Win32-окон (`HwndHost`), а WebView2 в WPF — именно такое окно. Если всё внутри одной страницы, наложения и полупрозрачность работают без ограничений.

## Последствия

- Нужен фронтенд-тулчейн (Node, Vite) в сборке.
- Большой поток вывода терминала надо передавать в страницу пачками, а не по байту.
