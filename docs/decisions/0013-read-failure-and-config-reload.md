# 0013. Защита файлов при отказе чтения и reload редактора Ghostty

Статус: принято, 2026-10-29, два явных решения пользователя в остатке S1 (R4/R9).

## Решение о файлах

Ошибка чтения существующего state/settings/windows index не равна отсутствию файла. Разрешено показать временное пустое/default состояние, но запись затронутого файла блокируется до успешного повторного чтения или перезапуска, который прочитает исходник. Само снятие внешнего отказа не разрешает сохранить defaults поверх источника. Сохранение возвращает отказ, индекс отмечается несохранённым. Миграция конфигов при непрочитанных settings не выполняется: выбранный configDirectory пока неизвестен.

Перед заменой повреждённого или несовместимого файла исходник перемещается в уникальный соседний backup без overwrite. Корректная неизвестная версия получает отдельный `.version-N-…`, порча — `.corrupt-…`. Timestamp дополняется случайным уникальным суффиксом. Если сохранить исходник не удалось, запись блокируется тем же образом. Backup сохраняет исходные данные для ручного восстановления, а не обещает совместимость будущей схемы. Формат и версия основных файлов не меняются.

В app успешное повторное чтение обеспечивается перезапуском; stores поддерживают повторный Load. Автоматический merge временной default-модели с исходником не вводится. Ошибку записи настроек нельзя выдавать за успешное сохранение; restore mode откатывает прежнее значение и возвращает error, как setRestoreMode agterm.

## Решение о редакторе

Для ghostty.conf при заданном VISUAL/EDITOR используется существующий editor overlay: запоминается содержимое после успешного открытия, при закрытии именно этого overlay выполняется reload только если содержимое изменилось. Save во время открытого редактора не применяет файл. Выход программы и явное закрытие overlay обрабатываются одинаково; замена файла по тому же пути учитывается чтением содержимого. Неизменённый файл не сбрасывает session zoom.

Без заданного редактора сохраняется выбранный ранее Notepad (О71); применение правок — явный Reload Config. Внешние изменения ghostty.conf также требуют явного reload. FileSystemWatcher ghostty.conf удаляется. Watcher keymap/hooks этим решением не меняется.

## Альтернативы

- Делать backup при отказе чтения и затем сохранять пустое/default состояние: пользователь выбрал блокировку записи до чтения.
- Сохранить watcher для Notepad/внешних правок, подавляя его для overlay: пользователь выбрал явный reload.
- Менять Notepad на другую программу или предполагать его lifecycle по WaitForExit: не выбиралось.

## Модель agterm и основания

Проверен локальный agterm e0b4844: PersistenceStore.load/loadChecked, SettingsStore, SettingsModel.setRestoreMode; WindowLibrary+Index/bootstrap/recoverOrphanedWindows; AppActions.reloadGhosttyConfigIfEdited, WindowContentView on overlay close, документация внешних изменений.

- Блокировка writes после read failure и уникальный backup → сохранность исходника вместо дальнейшей записи defaults → [решение пользователя 2026-10-29: R4, первый предложенный вариант]. agterm load возвращает defaults; эта часть сознательно усилена после воспроизведённой потери на собственных fixtures.
- Notepad и manual reload вместо fallback vi → сохранение выбранной программы → [решение пользователя 2026-10-28: О71; решение пользователя 2026-10-29: R9, первый предложенный вариант].
- Reload заданного editor overlay при изменении на close совпадает с agterm; Windows препятствие для этого пути не найдено. Прежнее объяснение watcher через «закрытие Notepad никто не видит» не считается техническим корнем.

R1–R3/ADR0012 и порядок четырёх appearance-параметров Т27 не меняются. Доказательства и предел покрытия: [публичные границы проверки](../sanitation-summary.md).
