# agshellctl

[English](agshellctl.md) | Русский

`agshellctl` управляет запущенным AgShell через named pipe. Команды, аргументы и формат ответов повторяют `agtermctl` из [agterm](https://agterm.com/commands.html), чтобы скрипты и навыки агентов переносились с минимальными правками.

`agshellctl.exe` лежит рядом с `agshell.exe`, и AgShell добавляет этот каталог в `PATH` каждой сессии. Из WSL команда вызывается как `agshellctl.exe`.

## Общие правила

- **Цель** (`--target`, `--workspace`, `--after`, `--before`) — id, уникальный префикс id в стиле git или `active`. По имени цель не ищется. Как в agterm, префикс, подходящий к нескольким id в этом окне или в разных окнах, — ошибка `ambiguous session prefix '<префикс>' → <первые 8 символов каждого>` (так же `workspace`, `window`).
- **`--target` по умолчанию `active`:** для сессии это выбранная сессия, для workspace — тот, куда попадёт новая сессия. Это только что созданный workspace, иначе workspace выбранной сессии, иначе последний.
- **Чтобы скрипт работал со своей сессией,** а не с выбранной, передавайте `--target $env:AGSHELL_SESSION_ID` (в bash `--target "$AGSHELL_SESSION_ID"`).
- **Окно** (`--window id|префикс|active`) — как в agterm, у команд, которые работают с деревом окна; общие для приложения (`version`, `events`, `session wait`, видимость, режим и раскладка `sidebar`, `quick`, `browser`, `keymap reload|list`, `restore`, `theme`, `config`, `hooks`, `recent list|clear`, `live`, кроме `kill` и `attach`, `install`, `clipboard`) и `window …` отклоняют его как неизвестный ключ. Без него команда идёт в окно, где есть её цель (id или префикс сессии или workspace), иначе в переднее; `pick`/`ask result|cancel` — в окно, где открыт диалог. Пробелы вокруг `--window` обрезаются, пустое значение считается не заданным.
- **Вывод:**
  - команды `new` и `duplicate` печатают id созданного;
  - пакетные `session close` и `session move` (два `--target` и больше) печатают число изменённых сессий; как в agterm, пакет переносится в порядке боковой панели, а при переносе в workspace уже стоящие там сессии пропускаются; при `--after`/`--before` пакет встаёт одним блоком, как при перетаскивании в боковой панели;
  - остальные команды при успехе молчат.
- **`--json`** печатает ответ целиком: `{"ok":true,"result":{...}}` или `{"ok":false,"error":"..."}`.
- **Ошибки** печатаются в stderr. Как в agterm:
  - отказ AgShell (`{"ok":false}`) — `error: ...`, код выхода 1;
  - сбой самого agshellctl (канал не отвечает, ответ не читается, запрос слишком большой) — `Error: ...`, код выхода 1. Если канал не отвечает, текст — `connect(\\.\pipe\ИМЯ) failed: <причина> — <подсказка>`, как в agterm: причина — канала нет (сообщается сразу) или все его экземпляры заняты 2 секунды; подсказка по замку папки состояния (`agshell.lock`, его держит запущенный AgShell, как flock в agterm; проверяется только для канала этой папки состояния) говорит, что владелец канала есть, но подключений не принимает, или что AgShell, возможно, не запущен;
  - ошибка использования (неизвестный ключ, нет нужного аргумента или он неверный) отклоняется до отправки (например, `--pane must be left, right, or scratch`, `--axis must be vertical or horizontal`, два способа размещения у `session new`/`session move`): `Error: ...`, затем строка `Usage:` команды и подсказка про `--help`, код выхода 64. Строка `Usage:` — как в agterm: ключи и аргументы в порядке agterm, `--pipe`, `--json` и `--window` там, где у agterm ключи подключения; если их больше 12, остаются только аргументы и обязательные ключи после `[<options>]`; у команды с подкомандами — `<subcommand>`, а ошибка в команде, которая выполняет подкоманду по умолчанию, показывает строку этой подкоманды. Как в agterm, `--pipe`, `--json` и `--window` относятся к команде и пишутся после её имени; только у нас `--pipe` и `--json` можно писать и перед именем команды (`agshellctl --json tree`), но не перед именем группы и не после него (`agshellctl session --json new` — неизвестный ключ). Ключ, которого у команды нет, неизвестен, где бы он ни стоял: перед аргументом и перед именем команды тоже (`agshellctl --json clipboard set x`).

  При успехе код выхода 0.
- **`--pipe NAME`** задаёт канал. Без него берётся `AGSHELL_PIPE` из окружения сессии, затем канал по умолчанию.

## Окружение сессии

| Переменная | Значение |
| --- | --- |
| `AGSHELL_ENABLED` | `1` внутри AgShell |
| `AGSHELL_SESSION_ID` | id сессии |
| `AGSHELL_WORKSPACE_ID` | id workspace на момент запуска шелла |
| `AGSHELL_WINDOW_ID` | id окна |
| `AGSHELL_PANE` | панель на момент запуска: `left`, `right`, `scratch` |
| `AGSHELL_PANE_ID` | постоянный id этого терминала: остаётся с ним при обмене панелей и когда сплит занимает место закрытой левой |
| `AGSHELL_PIPE` | имя канала управления |
| `TERM_PROGRAM`, `TERM_PROGRAM_VERSION` | `agshell` и его версия |
| `COLORTERM` | `truecolor`, как у Ghostty |

В WSL эти переменные попадают через `WSLENV`.

**`--pane-id`** (как в agterm) принимают `session status`, `session text`, `session restore`, `session restart`, `session hud` и `ask`: панель находится по `AGSHELL_PANE_ID`, где бы терминал ни оказался, и перебивает `--pane`. Неизвестный id без `--pane` — ошибка `unknown pane id`, кроме `session status`, который тогда пишет в левую панель. Хуки статуса передают его сами. Как в agterm, id (сессий, workspace, окон, поверхностей, событий) пишутся заглавными буквами, а читаются в любом регистре. В `tree --json` у сессии есть `surfaces`: панели, scratch, который показан или ещё работает, и overlay с программой на экране, с id вида `surface:<сессия>:<панель>` с полями `kind` (имя панели), `active`, `visible` и `paneID` у панелей; у панелей режима live ещё `lead`: `leader` (размер, который видит программа, задаёт это окно), `unowned` (панель никто не ведёт) или `follower` (ведёт другое окно или машина, панель здесь закрыта покрышкой).

## Дерево

```
agshellctl tree                 # workspace и сессии с id, шеллом и каталогом; * — активные
agshellctl tree --json          # то же для скриптов
agshellctl version                                 # версия приложения, затем client: <путь этого agshellctl>, как в agterm
```

Как у agterm, в меню «AgShell» есть «О программе AgShell» (версия, короткий коммит и ссылка на репозиторий), а в меню «Справка» — «Документация для разработчиков…» (этот справочник на GitHub, на языке интерфейса).

## Окна

```
agshellctl window new [имя] [--minimized]          # новое окно с одним workspace и сессией; печатает id
agshellctl window list                             # все окна, открытые и закрытые: «id  имя [open] [active]», как в agterm; рамка — в --json
agshellctl window select|close|delete|zoom|fullscreen [окно]
agshellctl window rename <окно> <имя>
agshellctl window minimize [окно] [on|off|toggle]
agshellctl window resize [окно] --width W --height H   # печатает применённый размер
agshellctl window move [окно] --x X --y Y [--display N]
agshellctl window go --to next|prev
```

Как в agterm:
- Окно — свой набор workspace и сессий со своим файлом состояния (первое окно — `state.json`, остальные — `windows\<id>.json`). Список окон — `windows.json`; если его не прочитать, как в agterm, каждый файл окна возвращается открытым окном «window N» (сначала `state.json`, затем остальные по имени файла) без запуска запомненных программ, а live-шеллы файла окна, которого нет в списке, `live prune` не трогает. Недавно закрытые — общие для всех окон (`recent-closed.json`). Непрочитанный индекс защищён от записи до успешного чтения после перезапуска; повреждённый или несовместимый индекс сохраняется в уникальный backup `.corrupt-…` или `.version-N-…` до замены при восстановлении. Та же защита чтения/записи и backup действует для state-файлов окон; backup сохраняет исходник для ручного восстановления, а не обеспечивает автоматическую поддержку другой схемы.
- `close` закрывает окно, но сохраняет его: `select` откроет снова с теми же сессиями (шеллы свежие, в режиме live — те же). Alt+F4 закрывает текущее главное окно с подтверждением; в quick прячет только quick, в Settings закрывает только Settings. Закрытие последнего окна завершает AgShell, и при следующем запуске оно откроется снова. «Выйти из AgShell» (Ctrl+Shift+Q, `quit`), как ⌘Q у agterm, спрашивает «Закроется окон: N и сессий: M[, все работающие шеллы завершатся].» и выходит, оставляя все открытые окна открытыми, так что следующий запуск откроет их все; выход из сеанса Windows и выключение выходят так же без вопроса.
- `close` возвращает успех (код выхода 0; `--json`: `ok: true` с id окна) после закрытия окна. Для последнего окна AgShell отправляет этот ответ до остановки control server и выхода. Другие открытые окна и их сессии продолжают работать. Ошибка транспорта остаётся ошибкой.
- `delete` удаляет окно вместе с сессиями; последнее окно удалить нельзя.
- `zoom` — развёрнуто во весь экран и обратно, `fullscreen` — без рамки поверх панели задач. Свёрнутое окно возвращается каким было (и развёрнутым, и полноэкранным); `minimize` отказывает полноэкранному окну, только если его надо менять.
- Сохранённая рамка, которая больше не помещается (монитор отключили), возвращается целиком на монитор, с которым больше всего пересекается, иначе на основной. `move` оставляет на мониторе полосу окна в 80 единиц, в том числе за верхним краем. `list` у развёрнутого окна даёт рамку, какая она на экране.
- Переднее окно сохраняется в `windows.json` и при следующем запуске снова впереди. Закрытие окна отменяет его открытые `pick` и `ask`: ждущий скрипт получает `cancelled`. Сохранённые исходы доступны по id или префиксу своего `--window` и после закрытия окна; другое окно не может их прочитать или отменить. После последнего окна control pipe работает не более двух секунд для выдачи отменённых исходов, затем приложение выходит; без ожидающих диалогов оно выходит сразу. Когда Windows завершает сеанс, в следующий раз открываются все окна.
- Размеры и координаты — в единицах окна WPF (на 100 % масштабе это пиксели), от рабочей области монитора без панели задач. Мониторы нумеруются с 0: основной первый, остальные слева направо.
- Настройки, клавиши, хуки, живые демоны и quick terminal общие для всех окон.
- `tree` печатает дерево одного окна; в `--json` есть `windowId` и `windowName`.
- Как в agterm, в меню «Файл»: «Новое окно» (`new_window`), «Открыть окно» (список всех окон, закрытое откроется), «Переименовать окно…» (`rename_window`), «Удалить окно» (`delete_window`); в палитре действий и в меню «Навигация» — «Следующее/Предыдущее окно» (`next_window`/`previous_window`), в палитре ещё «Открыть окно: …» для каждого закрытого окна. Клавиша по умолчанию есть только у «Нового окна» — Ctrl+Alt+N (у agterm ⌘⌥N).
- Названное окно показывает имя в заголовке после имени сессии, как в agterm, — и в собственной строке заголовка окна; там его скрывает переключатель «Имя окна» в настройках интерфейса.
- Настройка «Прятать боковую панель в неактивных окнах» (вкладка «Интерфейс»): как в agterm, когда впереди оказывается другое окно, у него панель показывается, у остальных прячется; это сохраняется и видно в `window list --json`. Переход в другое приложение ничего не меняет.

## Workspace

```
agshellctl workspace new [имя] [--collapsed]     # печатает id; при включённом фильтре попадает в фокус, кроме --collapsed
agshellctl workspace rename <имя> [--target W]
agshellctl workspace delete [--target W]         # вместе с сессиями; последний удалить нельзя
agshellctl workspace select [--target W]         # первая сессия, а пустой workspace становится текущим
agshellctl workspace go --to next|prev
agshellctl workspace move --to up|down|top|bottom [--target W]
agshellctl workspace collapse|expand [--target W]
```

## Сессии

```
agshellctl session new [--cwd DIR] [--name N] [--shell pwsh|powershell|cmd|wsl:<дистрибутив>]
                     [--workspace W | --workspace-name NAME [--create-workspace] | --after S | --before S]
                     [--no-select] [--command "программа аргументы" [--wait]]   # печатает id; --no-select создаёт в фоне
agshellctl session duplicate [--target S]            # новая сессия сразу после исходной, с её шеллом, в каталоге фокусной панели
agshellctl session close [--target S]...             # можно несколько --target
agshellctl session select [--target S]
agshellctl session go --to next|prev|first|last|next-attention|prev-attention
agshellctl session rename <имя> [--target S]         # пустое имя возвращает имя по каталогу
agshellctl session move <workspace> [--target S]...  # перенести в конец workspace
agshellctl session move --after S2 [--target S]...   # поставить после S2 (или --before), в его workspace
agshellctl session move --to up|down|top|bottom [--target S]
agshellctl session reveal [--target S]               # открыть каталог в проводнике
agshellctl session restart --pane left|right | --pane-id ID [--command "строка"] [--target S]   # новый шелл вместо текущего
```

Без `--cwd` сессия открывается в домашнем каталоге, и каталог у неё есть всегда (кроме WSL, чей домашний каталог — в дистрибутиве). Для WSL каталог задаётся путём Linux (`--cwd /tmp`).

**`--command`**, как в agterm, запускает программу вместо шелла сессии (в WSL-профиле — внутри дистрибутива). Как agterm запускает её через `/bin/sh -c`, строка идёт через шелл: `cmd.exe /d /s /c` (и для профиля PowerShell), а в WSL-профиле — `sh -c` внутри дистрибутива, поэтому `&&`, переменные и перенаправления работают в синтаксисе этого шелла, а код выхода — код строки. То же для `session scratch --command` и для программы `session overlay open`. Когда программа завершится, её панель закрывается, как у любого шелла и при любом коде выхода: закрывается сессия, или сплит занимает место основной панели; с `--wait` панель остаётся с последним выводом до любой клавиши (или `session type`). Как в agterm, swap уносит команду и `--wait` вместе с программой в другую панель. Команда сохраняется (`command` и `commandWait` в `tree --json`): в режиме rerun восстановленная сессия (при запуске, в снова открытом окне, из недавно закрытых) запускает её снова, если её не перебивает закрепление `session restore` или запомненная при выходе программа, даже отсеянная чёрным списком; в режиме none открывается простым шеллом. Сплит, в который команду унёс swap, запускает её так же. Как SpawnPacer у agterm, панели восстановленных сессий (основная и показанный сплит, в любом режиме восстановления, в том числе live и строки другой машины) при запуске стартуют по одной раз в 120 мс в порядке боковой панели: выбранной сессии — сразу, а сессия, в которую перешли, — следующей. В режиме live команда один раз набирается в живой шелл при создании, и сессия после неё остаётся открытой. Дубликат сессии команду не получает.

**`session restart`**, как в agterm, заменяет шелл одной панели (`--pane left|right` или `--pane-id`; без них — `session.restart requires --pane-id or --pane`, scratch — `session.restart does not address the scratch pane`) и запускает в новом шелле строку из `--command` (до 4096 байт; пустая и с управляющими символами — ошибка), после чего шелл остаётся интерактивным. Без `--command` новый шелл снова запускает программу, которая работает в панели сейчас; если в панели только шелл (`no replayable foreground program: NAME holds the pane`, NAME — самый вложенный шелл, в WSL — тот, что ведёт группу переднего плана терминала, иначе собственный шелл панели: как лидер демона у agterm, он не считается программой, какие бы у него ни были аргументы), программу не прочитать (`the pane's foreground program cannot be read`), её строка с управляющими символами или она есть в `restore-denylist.conf`, ничего не меняется и приходит ошибка. Кроме панели, удержанной после ошибки связи в live, панель, где шелл не работает (его ждут до 5 секунд), отклоняется: `the pane's shell is not running`; отказ повторить программу заканчивается на `; pass --command to name the line. nothing was changed`, как в agterm. Панель сохраняет место и `AGSHELL_PANE_ID` и начинает с пустого экрана. Ответ приходит, когда новый шелл появился: `restarted left pane: shell OLD -> NEW`, в `--json` — `restart` с `oldPid`, `newPid` и `replayedArgv`. Как в agterm, повторная программа запускается в каталоге, где она работала; если его не прочитать — `the foreground program's working directory is unavailable`. Перед остановкой шелла restart запоминает его программу переднего плана (в Windows — программу под шеллом и её дочерние процессы, в WSL — группу переднего плана терминала) по id и времени старта; если таблицу процессов не прочитать — `the process table cannot be read, so the old program could not be tracked; nothing was changed`. Новый шелл запускается, только когда эта программа ушла: ей дают секунду после закрытия консоли, затем завершают принудительно и ждут ещё полсекунды; если она всё ещё работает, панель закрывается с `the old shell ended (pid N) but its program is still running; nothing was started and the pane was closed`. Если панель за это время изменилась — `the old shell ended (pid N) and the pane changed during the restart; nothing was started`. Отличие от agterm: команда работает и вне режима live (своими шеллами AgShell управляет в любом режиме).

Панель, удержанную после ошибки запуска или связи в live, можно явно перезапустить через меню или `session restart`. Без `--command` запускается новый шелл; потерянная программа не выдаётся за восстановленную. Если старый шелл не наблюдался, в ответе нет `oldPid`. Неполный или конфликтующий обход заявок запрещает такой перезапуск; существующий демон должен подтвердить завершение своего старого шелла до запуска замены.

## Ввод и чтение

```
agshellctl session type "dir`n" [--target S]         # PowerShell: `n — перевод строки
agshellctl session type $'make test\n'               # bash
agshellctl session type "x" --pane-id $env:AGSHELL_PANE_ID   # терминал по его постоянному токену; --select принимается, как в agterm
echo 'make test' | agshellctl session type --stdin   # stdin должен быть корректным UTF-8 (иначе ошибка использования, как в agterm)
agshellctl session text [--target S]                 # видимый экран
agshellctl session text --lines 50                   # последние 50 строк вместе с прокруткой
agshellctl session text --all                        # экран и вся прокрутка
agshellctl session copy [--target S]                 # выделенный текст активной панели; буфер обмена не трогается
agshellctl session select-all [--target S]           # выделить весь буфер главной панели
agshellctl session paste [--pane P] [--target S]     # вставить буфер обмена, как Ctrl+V; Enter не нажимается
agshellctl clipboard set "текст"                     # положить текст в буфер обмена; без аргумента — из перенаправленного stdin побайтно
```

- `type` превращает каждый перевод строки в Enter. Последний Enter отправляется через 10 мс после текста: иначе Claude Code принимает его за часть вставки и не отправляет.
- `type` в сессию, шелл которой завершился, возвращает ошибку.
- `text` возвращает текст так, как он виден в терминале. Перенесённые строки склеиваются, пустые строки в конце отбрасываются.
- У полноэкранных программ (vim, htop, Claude Code) прокрутки нет, поэтому читается только текущий экран.
- `copy` без выделения возвращает ошибку `no selection`; у сессии, которую ещё не показывали, `copy`, `select-all` и `paste` отвечают `session not realized`.
- `clipboard set`, как в agterm: без аргумента текст читается из stdin побайтно, но только перенаправленного (если stdin — терминал, ошибка `give the text as an argument or pipe it on standard input`, а не ожидание); пустой текст — `nothing to copy`; в base64 текст должен уложиться в 8 МБ без 64 байт, иначе `text is too large to copy through the terminal: N bytes encoded, the limit is 8388544`. Текст, начинающийся с `-`, передайте через stdin или после `--`. Панель, чей демон уже не держит шелл, — `this pane has no live shell…` с кодом 1; код 0 не значит, что какой-то терминал текст принял.
- `clipboard set` отправляет текст через панель, в которой запущен, как OSC 52: буфер обмена ставит каждый терминал, который её показывает, в том числе AgShell на другой машине. Как в agterm, команда обращается к живому демону панели, а не к окну, поэтому работает и при закрытом окне AgShell. Каждый терминал решает по своей настройке «Программы могут записывать в буфер обмена» (по умолчанию включена; она же разрешает OSC 52 любым программам). Вне основной или правой панели режима live (scratch, quick terminal, overlay, в том числе overlay основной панели, другой режим восстановления) команда отказывает: `this pane has no live shell`. Панель — та, чей шелл запустил команду: её демон даёт шеллу `AGSHELL_LIVE_PIPE`, как zmx даёт `ZMX_SESSION`, поэтому обмен и перенос панелей её не путают; значение, которое не называет демон этой папки состояния, отвергается. Демон отвечает, есть ли у него шелл, а отсутствующий — `this pane has no live shell`. Как inject у zmx, последовательность попадает и в терминал демона, поэтому её видят `live screen` и вернувшееся окно, а пока панель показывает окно, ConPTY перерисовывает её, как после смены размера. Как в agterm, ключей `--pipe` и `--json` у неё нет.
- **Что программы могут просить у терминала** (как Ghostty в agterm): фон, заданный через OSC 11, красит только эту панель с прозрачностью окна, пока OSC 111 не вернёт её собственный цвет, а `OSC 11 ; ?` отвечает цветом на экране; OSC 22 задаёт форму указателя мыши по имени CSS-курсора (пустое — курсор терминала); протокол клавиатуры Kitty (`CSI > флаги u` и остальное, свой стек у каждого экрана) кодирует клавиши как Ghostty, поэтому Shift+Enter, сочетания с Ctrl и Alt и Esc доходят до Claude Code и Codex отдельно от простого Enter и текста; `CSI ? 996 n` отвечает, тёмная система или светлая, а после режима 2031 каждая смена приходит программе сама; при выключенных в настройках Windows эффектах прозрачности окно непрозрачно в цвете темы, а настройка прозрачности сохраняется до их возвращения. Файлы тем читаются как у Ghostty: значения в кавычках, `#rgb`, `#rrggbb` и другие формы Ghostty, `rgb:r/g/b`, имена цветов X11 (rgb.txt Ghostty, так что `green` — #00ff00), пустое значение сбрасывает ключ, а без фона и текста берутся цвета Ghostty. Явная смена шрифта или темы и перечитывание ghostty.conf сбрасывают размер Ctrl+/- у всех сессий, в закрытых окнах тоже, как в agterm; смена светлой и тёмной системой его не трогает.
- **Выделение и вставка** (как Ghostty в agterm): выделенное мышью копируется в собственный буфер выделения AgShell, средняя кнопка вставляет его (пока программа читает мышь, кнопка принадлежит ей, Shift возвращает её себе). Ctrl+C или Ctrl+Shift+C копирует в буфер обмена и оставляет выделение; Ctrl+Shift+A выделяет всё (у agterm — Cmd+A, а Ctrl+A принадлежит шеллу). Файлы, скопированные в Проводнике, вставляются путями в кавычках под шелл панели (`/mnt/c/...` в WSL), и программа, читающая буфер, получает их так же; текст и ссылки, перетащенные на терминал, вставляются как вставка. Незавершённый ввод IME фиксируется перед `session type`, перетаскиванием и вставкой, чтобы недописанное слово не оказалось после них. Как в agterm, клик, которым возвращают неактивное окно, доходит до терминала только левой кнопкой: правая не вставляет, средняя не вставляет выделение; при включённой «Прятать боковую панель в неактивных окнах» такой клик только возвращает окно. Таким кликом AgShell считает нажатие в пределах 100 мс после того, как окно вышло вперёд, если между ними не было клавиш.
- **Программы и буфер обмена** (как в agterm, по правилам Ghostty): запись OSC 52 подчиняется настройке «Программы могут записывать в буфер обмена»; чтение OSC 52 (`52;c;?`) и чтение по протоколу буфера обмена Kitty (OSC 5522) сначала спрашивают: «Разрешить программе прочитать буфер обмена?» с кнопками «Разрешить», «Запретить» и флажком «Не спрашивать до конца сеанса» (запоминается до выхода из AgShell, отдельно для чтения и записи). Запросы одной панели ждут один ответ. Tab и Shift+Tab удерживают фокус внутри запроса буфера обмена. Esc запрещает только текущий запрос, не учитывает флажок запоминания и не доходит до терминала. Запрещённое чтение OSC 52 получает пустое содержимое, чтение Kitty — `EPERM`. Запись Kitty приходит частями, с псевдонимами и любыми MIME-типами: текст ложится в буфер как текст, остальные типы — под своим MIME-именем (PNG ещё и как `PNG`); чтение Kitty получает только текст и только если просит `text/plain`; запрос одного списка типов (`.`) не спрашивает. Режим 5522 превращает вставку из буфера (Ctrl+V, правый клик, `session paste`) в paste-событие Kitty с одноразовым паролем на одно чтение. OSC 52 `s` идёт в собственный буфер выделения AgShell, а не в системный. Как в Ghostty, ответ OSC 52 заканчивается ST, а ответ Kitty — тем терминатором, с каким пришёл запрос (BEL или ST).
- **Текст от средств специальных возможностей** (как в agterm): инструмент, который задаёт значение терминала через UI Automation, вводит текст; текст с переводом строки, табуляцией или другим управляющим символом идёт как вставка, поэтому при включённой bracketed paste (режим 2004) он не отправляет строку и не запускает дополнение.
- **ConPTY**: AgShell поставляется с ConPTY из Windows Terminal (`conpty.dll` и `OpenConsole.exe` рядом с `agshell.exe`). Системный ConPTY съедает чтение OSC 52, сам отвечает на DECRQM и выбрасывает OSC-ответы по пути к программе, так что чтение буфера с ним не работает. `AGSHELL_CONPTY=system` включает системный (чтобы сравнить, если что-то не так); без этих двух файлов он используется и так.

## Фон сессии

```
agshellctl session background image C:\pics\logo.png [--opacity 0.3] [--fit contain|cover|stretch|none] [--position bottom-right] [--repeat]
agshellctl session background text DRIVER [--color #rrggbb] [--opacity 0.2] [--fit …] [--position …]
agshellctl session background color #1e2430
agshellctl session background clear
… [--pane left|right|scratch] [--target S]
```

Как в agterm:
- Без `--pane` фон общий для сессии и сохраняется между запусками; с `--pane` у панели свой фон (например DRIVER и PEER у двух агентов в сплите), а `clear --pane` возвращает её к общему.
- Фон панели переезжает вместе с её шеллом при обмене панелей и при закрытии левой; у scratch он живёт, пока scratch открыт.
- Картинка — PNG или JPEG. Из WSL путь `/home/…` читается как файл дистрибутива сессии, `/mnt/c/…` — как `C:\…`. Позиция: `center`, середина стороны (`top-center`, `center-left` и т. п.) или угол (`top-left` и т. п.).
- Картинка и текст рисуются под прозрачной сеткой терминала, панель при этом непрозрачна. Текст, как в agterm, сначала рисуется жирным в картинку, поэтому `--fit`, `--position` и `--repeat` действуют на него как на картинку: `contain` растягивает надпись на панель. Цвет учитывает прозрачность окна из настроек.
- `tree --json`: `background` и `paneBackgrounds` у сессии.

## Сплиты, scratch, zoom

```
agshellctl session split [on|off|toggle] [--axis vertical|horizontal] [--target S]   # второй шелл в сессии
agshellctl session split close [--target S]          # закрыть сплит и завершить его шелл
agshellctl session swap [--target S]                 # поменять панели местами, шеллы продолжают работать
agshellctl session lead [--pane left|right] [--target S]   # вести живую панель отсюда: программа получает размер этого окна
agshellctl session focus left|right|other [--target S]
agshellctl session resize --split-ratio 0.6 [--target S]   # доля левой (верхней) панели, 0.05–0.95; печатает применённую долю
agshellctl session resize --grow-left 0.05 [--target S]    # сдвинуть: --grow-left|right|primary|split|top|bottom, ровно одна
agshellctl session scratch [on|off|toggle] [--target S]    # ещё один шелл поверх сессии
agshellctl session scratch on --command "npm test" [--follow]  # один раз запустить программу вместо его шелла (открытый scratch заменяется)
agshellctl surface zoom [show|hide|toggle]           # активная панель на всё окно
agshellctl surface zoom [show|hide|toggle] --target surface:<сессия>:<панель>   # именно эта панель, даже скрытая
agshellctl surface cursor [--target active|surface:…|quick | --target S --pane-id ID]   # колонка курсора, с 0
```

Как в agterm:
- **Поверхность** — один терминал сессии: `surface:<сессия>:left|right|scratch|overlay|overlay-left|overlay-right` (id есть в `surfaces` у сессии в `tree --json`). `active` — тот, где работает пользователь: overlay сессии, иначе scratch, иначе overlay фокусной панели, иначе она сама.
- **`surface zoom --target surface:…`** разворачивает именно эту панель — и спрятанный сплит, и scratch, и панель под overlay, и панель невыбранной сессии, которая так и остаётся невыбранной; выбор, фокус, сплит и scratch не меняются. Любая цель, кроме `active`, `quick` и `surface:…`, — ошибка `invalid surface: …`. `toggle` выходит, если развёрнута как раз она; `hide` с id снимает только её. Zoom держит свою панель, пока из него не выйти: новый выбор, overlay, scratch или фокус его не переносят; он снимается сам, когда его панели не стало (закрыта сессия или сплит, вышел scratch или overlay, overlay скрыт). Ctrl+Shift+Enter разворачивает активную поверхность и под страницей ничего не делает. Вход в zoom закрывает палитру и завершает поиск выбранной и развёрнутой сессии; в quick terminal он ничего не делает, пока в активном окне ждёт pick или ask. Что развёрнуто — `zoomedSurface` в `tree` (`quick`, если развёрнут quick terminal); клавиши шрифта меняют развёрнутый терминал.
- **`surface cursor`** печатает колонку курсора (в `--json` — `cursorColumn`), ничего не выбирая и не показывая. С `--pane-id` цель — сессия, а неизвестный id — ошибка без отката на другую панель.

Сплит устроен как в agterm:
- это одна сессия с двумя терминалами и одной строкой в боковой панели;
- спрятанный сплит продолжает работать и сохраняет фокус: панель в фокусе показывается во весь размер, а `session focus` или клавиши фокуса переключают, какая;
- `--axis` с той же осью прячет сплит, с другой осью поворачивает его;
- новый сплит открывается в каталоге главной панели и получает фокус;
- имя сессии следует за каталогом активной панели.

Когда шелл завершается:
- шелл сплита — сплит закрывается;
- главный шелл при открытом сплите — сессия переходит ко второй панели.

Сплит, его ось, доля и каталог сохраняются между запусками.

Scratch открывается в каталоге сессии, при скрытии продолжает работать и между запусками не сохраняется.

У `session type` и `session text` есть `--pane left|right|scratch`. По умолчанию `type` пишет в главную панель, а `text` читает панель на экране; `session search`, как в agterm, работает с панелью на экране или с той, где открыт его поиск. Шелл знает свою панель из `AGSHELL_PANE`.

| Сочетание | Действие |
| --- | --- |
| Ctrl+Shift+D / Ctrl+Shift+E | Вертикальный / горизонтальный сплит |
| Ctrl+Alt+← / → | Фокус на левую / правую панель |
| Ctrl+Shift+J | Scratch |
| Ctrl+Shift+Enter | Zoom |
| Ctrl+Shift+W | Выйти из zoom, иначе спрятать scratch, иначе закрыть сессию |

Разделитель сплита можно тянуть мышью, двойной клик выравнивает панели. Как в agterm, клавиши сплита, кнопка в строке заголовка и «Закрыть сплит» из окна не меняют панели, скрытые под обложкой: над показанным scratch они только прячут его, под программой или страницей на всю сессию ничего не делают. `session split` работает и под обложкой.

## Overlay, HUD и quick terminal

```
agshellctl session overlay open "<программа>" [--cwd DIR] [--size-percent N [--width PT] [--height PT]] [--background-color #rrggbb]
                                            [--wait | --block] [--follow] [--target S]
agshellctl session overlay close | result | text [--target S]
agshellctl session overlay resize (--size-percent N [--width PT] [--height PT] | --width PT [--height PT] | --height PT | --full) [--target S]
agshellctl session overlay hide|show|toggle [--pane left|right] [--target S]   # скрыть, не закрывая; печатает hidden или shown
agshellctl session hud [open] "сообщение" | --file F [--detail T] [--spinner] [--spinner-style bar|braille|circle|blocks|dot|none]
                     [--position top-left|top-center|…|bottom-right] [--hide-after SEC] [--size-percent N] [--markdown]
                     [--background-color] [--text-color] [--font-size 6-72] [--sticky] [--no-frame] [--pane left|right | --pane-id ID] [--target S]
agshellctl session hud update "сообщение" | --file F [те же, кроме --background-color и --font-size] ; session hud close [--target S]
agshellctl quick [show|hide|toggle] ; quick type "текст" | --stdin ; quick text [--lines N | --all]
agshellctl surface zoom [show|hide|toggle] --target quick   # развернуть quick terminal на весь экран
```

**Overlay** — программа во временном терминале поверх сессии, как в agterm (без `--cwd` запускается в каталоге основной панели, какая бы панель ни была в фокусе):
- шелл под ней продолжает работать, а когда программа завершается, overlay исчезает;
- программа запускается как есть, без шелла: синтаксис шелла оборачивайте в `pwsh -c "…"` или `sh -c '…'`;
- в WSL-сессии программа запускается в том же дистрибутиве, поэтому `htop` и `lazygit` находятся;
- `--size-percent` делает плавающую панель в рамке; `--width` и `--height`, как в agterm, задают ширину или высоту её содержимого в точках (единицах окна WPF) вместо процента — например, ширина процентом, а высота по содержимому страницы. Каждая такая ось не больше 80 % сессии, у страницы с полоской высота полоски добавляется сверху. При открытии они идут только с `--size-percent` (`session.overlay.open: --width/--height need --size-percent`). В `resize` с `--size-percent` панель получает ровно указанные оси, одни точки меняют только свои оси уже плавающей панели (иначе `... need a floating overlay; pass --size-percent too`), а `--size-percent` без них или `--full` их сбрасывают. Для HUD и для overlay, который показывает другая машина, точки не работают. Фактический размер содержимого — `overlayWidth`/`overlayHeight` в `tree --json`;
- `--wait` держит overlay после выхода до нажатия клавиши;
- `--block` ждёт выхода и возвращает код программы;
- `--follow` переключает пользователя на сессию;
- `result` печатает `exit N` — код выхода последнего overlay (в `--json` — `exitCode`). Пока программа работает, это ошибка `overlay still running`; если код не остался (overlay закрыли или его не было), — `no overlay result`.

**Скрытый overlay**, как в agterm: `overlay hide|show|toggle` прячет программы и страницы сессии (с `--pane` — одной панели), не закрывая их. `toggle` прячет все, пока хоть один виден, иначе показывает все; ответ — `hidden` или `shown`. Скрытая программа работает дальше, `--block` продолжает ждать, `overlay result` отвечает. Слот остаётся занятым: открыть туда другой overlay или HUD нельзя (`overlay hidden`). HUD скрыть нельзя (`no overlay`), как и overlay, который рисует presenter (`overlay is shown on another machine`). В окне — действие «Скрыть или показать overlay» (`toggle_overlay`, Ctrl+Alt+Shift+J), кнопка в строке заголовка и «−» на полоске страницы (прячет её панель или всю сессию). Ctrl+Shift+W скрытый overlay пропускает, а вопрос о закрытии сессии напоминает, что скрытые overlay закроются вместе с ней. В `tree --json` — `hiddenOverlays` (`session`, `left`, `right`) и `hidden` у страниц в `htmlOverlays`.

**Overlay на одну панель сплита:** `--pane left|right` у `overlay open/close/result/text`. Он закрывает только эту панель, соседняя остаётся живой, и у каждой панели может быть свой. Такой overlay всегда на всю панель, переезжает вместе со своим шеллом при swap и закрывается вместе со сплитом. Для `text` правая панель должна быть на экране; `open`, `close` и `result` работают и со скрытой. Как в agterm, overlay с программой, чья панель ушла с экрана (сплит скрыт, фокус перешёл на скрытом сплите, сменился зум) до запуска программы, закрывается вместе с результатом; уже запущенный продолжает работать и показывается вместе с панелью, а страница и overlay, который показывает зум, остаются.

**HUD** — панель с сообщением поверх сессии, которая не забирает фокус. Как в agterm, у сессии один HUD: новый заменяет прежний, а `--pane` или `--pane-id` только выбирают, над какой панелью он висит; `update` без них возвращает его на всю сессию, `close` закрывает его, где бы он ни был (`no hud`, если его нет). `hud` без подкоманды — это `hud open`; сообщение, которое буквально `update` или `close`, пишется через `hud open`. `--file` читает сообщение из файла UTF-8 (CRLF сводятся к LF, последний перевод строки отбрасывается). Сообщение — до 256 символов (с `--markdown` — до 4096), `--detail` — до 256, `--hide-after` — до 86400 секунд, `--font-size` — 6–72. Фон и размер шрифта задаются только при открытии: `update` их сохраняет. `hud` и `hud update` при успехе ничего не печатают.

**Страница вместо программы:**

```
agshellctl session overlay open --html report.html [--cwd DIR] [--js] [--navigation | --chromeless] [--block]
agshellctl session overlay open --url http://localhost:5173 [--js] [--navigation] [--chromeless] [--persistent] [--browse]
agshellctl browser clear                                   # забыть cookies и логины страниц с --persistent
agshellctl browser links [browser|overlay]                 # где открываются ссылки по Ctrl+клику; без аргумента — текущий режим
agshellctl session overlay reload [--current] | navigate back|forward|browser|finder|URL | submit --value V | copy [--pane …]
agshellctl session overlay result --page ID              # {"pageID":…,"outcome":"pending|submitted|dismissed","value":"…"}; ID — overlayId из overlay open --json
```

Ссылки в терминале — найденные в тексте или выведенные программой (OSC 8) — подчёркиваются, пока зажат Ctrl, и открываются Ctrl+кликом (пока программа читает мышь — только Ctrl+Shift, чтобы клик оставался её), по правилам LinkPolicy из agterm: http, https, mailto и ftp открывает система (http и https в режиме `overlay` могут открыться поверх сессии, если клик в панели или scratch: https или http с хоста этой сети), локальный `file://` выделяется в Проводнике и никогда не запускается (Linux-путь из WSL-панели — через `\\wsl.localhost`), а другие схемы, `file://` чужой машины и сетевые папки игнорируются. Quick terminal открывает ссылки в браузере, как и окно с развёрнутым (zoom) терминалом и сессия с HUD, как в agterm. Поверх сессии ссылка открывается страницей для просмотра, как в agterm: с навигацией, скриптами, сохранённым хранилищем браузера и переходами на другие сайты внутри (`--navigation --js --persistent --browse`); если там открыть нельзя (слот занят, хранилище очищается), она открывается в браузере.

- Страница показывается под полоской, как в agterm. Имя на полоске даёт AgShell, а не страница: файл, открытый сейчас, или сайт (`http://127.0.0.1:8765`; с `--browse` — сайт, открытый сейчас). За ним через «·» идёт заголовок страницы. Как в agterm, полоска высотой 28 в цветах терминала, кнопки — значками, имя обрезается посередине; плавающая страница обрезана по скруглённым углам панели; ошибка неудачной загрузки — цветом текста, её можно выделить. После `navigate --url` полоска называет сайт, куда ушла страница. С `--navigation` слева кнопки «назад» и «вперёд» (неактивны без истории) и «обновить», справа — открыть в браузере, показать в проводнике (файл) или копировать ссылку (сайт). С `--chromeless` полоски нет. Если загрузка не удалась, страницу закрывает плашка «Страницу не удалось загрузить» с ошибкой; «обновить» убирает её.
- Страница живёт, пока её сессия не закрыта окончательно: после отмены закрытия она возвращается как была. Клик по странице над панелью переводит на эту панель фокус сплита, а ввод в страницу считается активностью и сдерживает auto-follow.
- Как в agterm, любая страница открывается отдельным браузером поверх overlay: у неё своя история («назад», «вперёд»), состояние загрузки и масштаб. `navigate back|forward` без истории — ошибка `no page to go back to` (`forward`), а `back`, `forward`, `browser` и `finder` для страницы, которая ещё ни разу не была на экране, — `html overlay not realized`. «Открыть в браузере» открывает в браузере по умолчанию исходный файл локальной страницы (а не тот, куда она перешла) или текущий адрес веб-страницы; «в проводнике» показывает файл, открытый сейчас. `window.close()` любой страницы закрывает её overlay. Падение процесса страницы — состояние `failed` с `web content process terminated`.
- **Переходы, как в agterm.** Локальная страница ходит только по своим файлам, веб-страница — по своему сайту (с `--browse` — по любому http(s)). Вложенные фреймы веб-страницы грузят любой сайт, кроме страниц с `--chromeless`. Адрес снаружи уходит в браузер только по клику пользователя и после вопроса (по умолчанию «Отмена»; один вопрос за раз, пропадает, когда страница уходит с экрана; после «Отмены» страница спросит снова только после ввода пользователя — свой ввод страницы AgShell не видит, поэтому считается любая клавиша или движение мыши); переход, который начала сама страница, отменяется, а если страница при этом ещё грузилась, её состояние — `failed` с `navigation blocked: адрес`. Диалоги `alert`/`confirm`/`prompt` не показываются, камера и микрофон запрещены, файлы на страницу не перетаскиваются. Как в agterm, файлы на страницу и не вставляются (Ctrl+V, Shift+Insert и «Вставить» в её меню ничего не делают, пока в буфере файлы; текст вставляется), а выбор файла страница не открывает: отказывают поле выбора файла, подпись к нему, `showPicker` и выбор через файловую систему. В отличие от agterm, перетащенный текст на страницу тоже не бросается (WebView2 принимает внешнее перетаскивание целиком или никак), а веб-страница без `--js` может открыть выбор файла через подпись (её скрипты выключены, а с ними и страж AgShell).
- **Тема терминала, как в agterm.** Каждая страница получает CSS-переменные `--agshell-background`, `--agshell-foreground` и `--agshell-color-0`…`--agshell-color-15` (палитра темы: 1 красный, 2 зелёный, 3 жёлтый, 4 синий, 5 пурпурный, 6 голубой, 8–15 яркие). Локальная страница по умолчанию ещё и окрашена: цвет текста и светлая или тёмная схема темы, на фоне темы; `--background-color` заменяет этот фон. Правило без веса, свои стили страницы его перебивают. При смене темы локальная страница перезагружается, веб-страница получает новые цвета при следующей загрузке. Используйте переменные с запасным значением: `background: var(--agshell-background, Canvas)`.
- **Локальный файл** раздаётся под своим именем хоста, поэтому видит только себя. С `--cwd` ему открыт ещё и каталог: как в agterm, адрес страницы — её путь внутри этого каталога, поэтому ссылки разрешаются рядом с файлом, а `../` достаёт то, что лежит выше в каталоге. Как в agterm, файл должен лежать внутри `--cwd` (`html file is outside cwd`), а каталогом не может быть корень диска или домашний (`cwd must not be a drive root or the home directory`). Файл, которого нет, открывается, и страница сообщает `failed` с `no such file: путь`. Файл отдаётся со своим типом, как agterm берёт его у системы: веб-типы (страницы, скрипты, стили, картинки, шрифты, видео и звук вроде `.webm`, `.mp4`, `.mp3`, `.ogg`, `.wav`, а ещё `.wasm`, `.pdf`, `.csv`) — по своей таблице AgShell, как их понимает браузер, прочие расширения — по типу, записанному для них в Windows, а без типа — как `application/octet-stream`.
- **Своя JavaScript страницы** без `--js` не работает: каждый её ответ приходит с заголовком Content-Security-Policy, который не выполняет ни одного скрипта, в том числе в документе SVG или XHTML. Мост и тема не входят в страницу: как пользовательские скрипты agterm, AgShell добавляет их в каждый документ при его создании, поэтому файлы страницы доходят до неё без изменений, а политика мост не затрагивает. Тема лежит в каскадном слое CSS, поэтому любой стиль страницы её перекрывает.
- **Мост работает и без `--js`:**
  - кнопки и формы с `data-agshell="<команда>"`; кнопка вне такой формы должна быть `type="button"`, иначе она отправит обычную форму, а кнопка внутри неё — часть отправки формы;
  - `data-agshell-target` — цель команды;
  - `data-agshell-args` — JSON с фиксированными аргументами, а именованные поля формы добавляются к ним, как в agterm: кнопки — только нажатая, пустое число пропускается, нечисло и поле файла — ошибка, два значения под одним именем — ошибка `more than one value for ИМЯ`;
  - `data-agshell-into` — элемент, куда выводится ответ: поле `text` ответа, если оно есть, иначе ответ одной строкой JSON.

  С `--js` есть ещё `agshell.request(cmd, {target, args})`. Как в agterm, запрос выполняется так же, как из agshellctl, а недостающее подставляется по месту страницы, только если она не указала ни цель, ни цели, ни окно: команда сессии (а также `notify`, `font.*`, `keymap.run`, `ask.open` без `--style gui`) действует на сессию самой страницы, а команды её собственного overlay (`close`, `reload`, `resize`, `navigate`, `submit`, `hide`, `show`, `toggle`) — на её панель; команда `window.*` — на окно страницы; общие для приложения (`hooks.*`, `browser.*`, `recent.list`, `recent.clear`) окна не получают; `live.attach`, `dashboard` и `recent.open` попадают в окно страницы; остальные получают окно страницы. `overlay reload` со страницы сохраняет то, что она показывает, если `current` не false.
- **Ответ скрипту, открывшему страницу:** страница отправляет значение через `session.overlay.submit` (например, `<form data-agshell="session.overlay.submit"><input name="value"></form>`). `overlay open … --block` печатает результат (`{"pageID":…,"outcome":…,"value":…}`). Как в agterm, значение — текст, и оно обязательно, пустое — тоже ответ: `submit` без него отвечает `session.overlay.submit requires a value`, а `agshell.request` с чем-то кроме строки — неверный запрос и завершается с кодом 0, если значение пришло, или 2, если страницу закрыли без ответа; разовый `result --page` для ещё открытой страницы завершается с кодом 1. Страница, закрытая вместе со сплитом, панелью или сессией, считается закрытой без ответа. Как в agterm, исход страницы читается по её id (`overlay result --page ID`), а не по слоту, и хранится для последних 32 страниц, даже после закрытия сессии; неизвестный id — `no such page`.
- **Веб-страница** (`--url`) может быть любым сайтом, логины на ней работают. Моста у неё нет. Своя JavaScript без `--js` выключена. Как в agterm, `--url` не сочетается с `--block` и `--cwd`, а `--chromeless` — с `--browse`. `--chromeless` разрешён только для 127.0.0.1, ::1 и localhost.
- **Хранение данных веб-страницы.** Cookies, логины и хранилище живут, пока страница открыта: у неё свой приватный профиль. С `--persistent` страницы используют один общий сохраняемый профиль, его чистит `agshellctl browser clear`. Как в agterm, очистка отказывает, пока открыта хоть одна страница с `--persistent` (и закрытая с возможностью отмены): `browser.clear: 1 persistent page still open`, ведь её логин в памяти записался бы обратно; а страница с `--persistent` не открывается здесь, пока идёт очистка (`session.overlay.open: browser storage is being cleared`), как в agterm; переданную presenter проверяет он сам.
- **Палитра, меню, переключатель Ctrl+Tab, список кнопки в заголовке (недавние сессии, ждущие внимания, пользовательские команды), выбор `pick`, вопрос `ask` и другие диалоги рисуются поверх страницы, как в agterm:** страница остаётся на экране и продолжает играть под ними, а где они затемняют окно, затемнена и она. Пока такой оверлей открыт, клик по странице закрывает его или ничего не делает и до страницы не доходит; после закрытия страница снова принимает клики и, если вы работаете в ней, клавиатуру. Матовый фон палитры не размывает страницу под собой: она просвечивает как есть. Дашборд закрывает страницу целиком.
- **Сочетания на странице:** Ctrl+Shift+W и остальные сочетания AgShell работают и тогда, когда фокус внутри страницы. Клавиши размера шрифта (`increase_font_size`, `decrease_font_size`, `reset_font_size`, по умолчанию Ctrl+= / Ctrl+- / Ctrl+0) меняют масштаб всех страниц по шкале agterm от 50 до 300 % — и тогда, когда фокус не в терминале (например, в боковой панели), а сессию закрывает страница. Масштаб — настройка (`htmlOverlayZoom`), он общий для всех окон и сохраняется между запусками.

**HUD** — пассивная панель с сообщением (в `tree --json` — узел `hud` с сообщением, панелью, позицией, временем скрытия, шириной `sizePercent` и высотой `heightPercent`: заданными или измеренными там, где он нарисован; `overlay` при этом false (`overlay` равен true, пока сессию закрывает программа или страница); у страниц в слотах — список `htmlOverlays` с id, файлом или адресом, состоянием загрузки `loading`/`loaded`/`failed` (с `error`), текущим адресом и заголовком, `canGoBack`/`canGoForward` и `zoom` (масштаб страниц, общий на приложение, как в agterm), у плавающего overlay — `overlaySizePercent`). Как в agterm, HUD рисуется и над страницей в его панели или сессии, а страница под ним живёт: HUD идёт отдельным окном поверх страницы, которое пропускает клики к ней (Ctrl+клик по ссылке открывает ссылку). `hud open --pane right` требует, чтобы панель была на экране (`pane not visible`), `update` — только чтобы она была (`session has no split`): сессия остаётся в фокусе, в неё можно печатать. Как в agterm, скрытый overlay в слоте (`overlay hidden`) и обновление без HUD (`no hud`) получают ответ до проверки панели. HUD над панелью не рисуется, пока этой панели нет на экране (сплит скрыт); от края, у которого он стоит, его отделяет 10 % панели или сессии (прикреплённый — вплотную). Пределы текста считают кодовые точки Unicode в составной форме, как в agterm: буква с ударением — одна, эмодзи из нескольких — каждая из них. Как в agterm, HUD всегда занимает место overlay всей сессии, а `--pane` только выбирает, над какой панелью он рисуется, поэтому overlay панели и HUD не мешают друг другу. Overlay всей сессии заменяет HUD, а HUD над программой или страницей — ошибка `overlay already open`; `overlay open` в занятое программой место тоже отказывает (`overlay already open`, для панели — `pane overlay already open`), а не заменяет её. `overlay close` закрывает и HUD, `overlay resize` меняет ширину HUD (10–80 %, у прижатого к краю до 100 %; `--full` — ошибка). `update` перерисовывает панель на месте, а параметры, которые не указаны, возвращаются к значениям по умолчанию. `--markdown` рисует сообщение как markdown, в раскладке agterm: заголовки и жирный — жирным, курсив, зачёркивание, код с отступом в два пробела, цитаты за «│ », списки с «• » или номерами и висячими строками, таблицы в рамке, линии; ссылка подчёркнута и открывается по Ctrl+клику; сырой HTML остаётся текстом. Как в agterm, панель — терминал шрифтом терминала (размера сессии или `--font-size`) на фоне терминала (или `--background-color`), с белой рамкой и скруглением 8 без тени (`--no-frame` — без них, фон остаётся): простое сообщение переносится по 60 колонок, каждая строка по центру, detail тусклее под пустой строкой; спиннер стоит перед первой строкой. Панель шириной по тексту, 10–80 % панели или сессии, и не выше 80 %: строки, что не поместились, заканчиваются «… N more», слишком широкая — «…».

**Quick terminal** — как в agterm, одна плавающая панель на всё приложение поверх остальных окон, на экране под указателем мыши (если указатель ни на одном — на экране переднего окна): 90 % его рабочей области, но не больше 1100×700, если в настройках не задан свой размер (40–90 %). Шелл один, он запускается в шелле выбранной сессии переднего окна и в каталоге её основной панели и продолжает работать, пока панель скрыта, так что из любого окна открывается тот же. Повторное сочетание, кнопка в строке заголовка или уход фокуса прячут панель; открытая через `quick show` от ухода фокуса не закрывается, и повторный показ вручную этого не меняет. Как в agterm, панель не открывается, пока `pick` ждёт ответа, глобальная горячая клавиша возвращает её сразу, даже сразу после скрытия, а набор текста в ней считается занятостью для автоперехода. `surface zoom --target quick` разворачивает её на весь экран (пока она показана). Когда клавиатура в панели, как в agterm, Ctrl+Shift+Enter разворачивает саму панель, клавиши шрифта меняют шрифт её терминала, а остальные клавиши действий работают в активном окне, как там, кроме поиска; новый шелл начинает с вычисленных семейства и размера шрифта из настроек и `ghostty.conf`. Терминал создаётся при первом показе; после выхода шелла следующий показ запускает новый шелл. Переменной `AGSHELL_SESSION_ID` у этого шелла нет.

| Сочетание | Действие |
| --- | --- |
| Ctrl+` | Quick terminal |
| Ctrl+Shift+W | Ответить «отмена» на ask или pick окна, ask сессии, выйти из zoom quick terminal, закрыть quick terminal, zoom, overlay или HUD, scratch — в этом порядке, и только потом сессию |

## Дашборд

```
agshellctl dashboard S1 S2 S3 [--font-size N | --auto-size]   # сетка живых сессий, до 9 панелей
agshellctl dashboard S1:left S2:right                          # только выбранные панели сплитов
agshellctl dashboard --mru [--auto-size]                       # недавно использованные сессии
agshellctl dashboard S1 --window W                             # в этом окне (по умолчанию — переднем)
agshellctl dashboard --close
```

Как в agterm:
- **Что это:** живой вывод нескольких сессий в сетке, только для просмотра. Сетка закрывает окно под заголовком вместе с боковой панелью непрозрачным фоном цвета терминала (прозрачность окна на это время пропадает); ячейки через 12 точек, со скруглёнными рамками, выделенная обведена цветом текста. Ячейка — это панель: сессия со сплитом занимает две.
- **Управление:** стрелки двигают подсветку, Enter переходит в эту сессию и фокусирует панель, клик сначала подсвечивает ячейку и переходит в неё через 0,18 с, если подсветка всё ещё на ней, Esc закрывает. Остальные клавиши ничего не делают, кроме сочетаний приложения; пока над сеткой pick, ask, палитра или меню, клавиши у них. Открытие закрывает палитру, завершает поиск и прячет quick terminal; кнопке в заголовке нужна выбранная сессия.
- **Подпись ячейки** — капсула на нижней рамке справа: имя сессии (длинное сокращается в середине) и у сессии со сплитом метка панели ◀/▶ или ▲/▼ по оси. Без статуса она цвета выделения темы, у невыделенной ячейки имя приглушено; со статусом агента закрашена его цветом (с учётом `--color`), текст чёрный или белый по яркости, а при `--blink` по капсуле пульсирует заливка (кроме режима «без анимации» Windows).
- **Панель под overlay** показывается надписью вместо терминала.
- **Цели:** `<id>`, `<id>:left` или `<id>:right`; вместо `left` подходят `top` и `primary`, вместо `right` — `bottom` и `split`, регистр не важен. Неверная запись (`:left` без id, `surface:<id>:left`, другой суффикс) отвергает всю команду раньше любой другой проверки окна. Повтор панели считается один раз, в том числе среди не поместившихся.
- **Ячейки следят за панелями:** когда выходит основная оболочка и сплит становится основной панелью, его ячейка остаётся и следит за ним. Подсветка держится на своей ячейке; если та пропала — на первой.
- **Шрифт:** `--auto-size` уменьшает его с ростом сетки от размера из настроек (не задан — от 13), `--font-size` задаёт точно, как есть; без них ячейки оставляют свой размер. На время дашборда шеллы получают размер ячейки, после закрытия — прежний.
- **Что не поместилось:** в сетке 9 панелей, остальное `dashboard` называет в выводе (`dropped N pane(s) beyond the 9-cell limit`), а id, которому нет сессии, и `:right` у сессии без сплита — как `unresolved: …`; если не нашлась ни одна цель, команда отказывает (`no dashboard sessions resolved`). `--mru` без недавних сессий отказывает с `no recent sessions`.
- **`tree --json`** показывает `dashboardMembers` и `dashboardHighlighted` (как `<id>:left` или `<id>:right`), `dashboardFontMode` (`fixed`, `auto` или `untouched`) и `dashboardFontSize` — размер, применённый к ячейкам.
- **Zoom** закрывает дашборд, а открытие дашборда снимает zoom.
- **Плитка под overlay**, как в agterm, показывает вместо терминала, что её закрывает: значок и «HTML overlay» с именем, как на полоске страницы (сокращается в середине), и приглушённым заголовком страницы или «Overlay с программой» с её командой. HUD и плавающий overlay плитки не закрывают.

Ctrl+Shift+G открывает сетку недавних сессий с автоподбором шрифта, повторное нажатие закрывает её.

## Поиск и шрифт

```
agshellctl session search "error" [--target S]       # открыть панель поиска и найти; печатает "S of N", "N matches" или "no matches" (--json: count)
agshellctl session search --next | --prev            # следующее или предыдущее совпадение
agshellctl session search --close
agshellctl font inc | dec | reset [--pane left|right|scratch] [--target S]   # размер шрифта одного терминала, ±1 пункт (по умолчанию левой панели; клавиши шрифта меняют терминал в фокусе); как в agterm, сессия помнит последний заданный размер — с ним открываются новый сплит, scratch и overlay, и он восстанавливается при запуске
```

В окне то же самое делают сочетания клавиш (их можно переназначить в `keymap.conf`):

| Сочетание | Действие |
| --- | --- |
| Ctrl+Shift+F | Панель поиска (Enter — следующее совпадение, Shift+Enter — предыдущее, Esc или повторное Ctrl+Shift+F — закрыть); как в agterm, у каждой сессии своя: остаётся на панели, где открыта, и снова видна при возврате в сессию; вход в зум терминала её закрывает |
| Ctrl+= / Ctrl+- / Ctrl+0 | Крупнее / мельче / обычный размер шрифта |
| Ctrl+P | Палитра сессий |
| Ctrl+Shift+P | Палитра действий |
| Ctrl+Shift+I | Сессии, ждущие внимания |

В палитрах, как в agterm, повторное сочетание закрывает палитру, а сочетание другой переключает на неё, оставляя набранный запрос. Стрелки или Ctrl+J / Ctrl+K двигают выделение и останавливаются на краях, Tab не уводит фокус из поля, мышь только подсвечивает строку под собой.

## Статусы агентов и уведомления

```
agshellctl session status active|blocked|completed|idle [--blink] [--auto-reset] [--sound NAME] [--color #rrggbb] [--shape SHAPE] [--pane P | --pane-id ID] [--target S]
agshellctl session context "PR #42" [--target S]     # чем занята сессия; видно в строке заголовка
agshellctl session context --clear [--target S]
agshellctl session wait --until completed --until blocked [--timeout 600] [--target S]
agshellctl session seen [--target S]                 # обнулить счётчик уведомлений, не переходя в сессию
agshellctl notify "текст" [--title T] [--target S]   # toast Windows и счётчик на строке сессии
agshellctl events [--kind status,notify,session.created,session.closed,session.selected,pane.split,pane.scratch,pane.focused,tree.changed,app.launched,remote.opened,remote.closed] [--json]
```

- **Статус** рисуется значком в строке сессии (подсказка, как в agterm, — «Agent status: Active», «Blocked» или «Completed»; в русском интерфейсе «Статус агента: работает», «ждёт ответа», «закончил»): `active` серо-лиловый, `blocked` янтарный, `completed` зелёный, у `idle` значка нет. `--blink` заставляет его пульсировать. Цвет и форма (круг, квадрат, треугольник, ромб, капсула, звезда) задаются в настройках для каждого статуса; `--color` и `--shape` меняют их только для этого вызова, следующий статус без них возвращает настройки.
- **Контекст** (`session context`) — одна строка до 256 байт: PR, задача. Сохраняется между запусками, дубликат сессии его не получает. В строке заголовка он идёт после имени сессии, а в двухстрочном виде заменяет каталог. В `tree --json` — поле `context`.
- **Строка заголовка** над терминалом, как в agterm: workspace (включается в настройках), имя сессии, контекст и кнопки — недавние сессии, колокольчик внимания (включается в настройках), scratch, сплит, дашборд, quick terminal, свои команды. Вид — одна строка, две или скрыта (вкладка «Интерфейс»). Заголовок окна Windows — имя текущей сессии. Как в agterm, пока терминал развёрнут (zoom), в строке только заголовок и кнопка выхода из zoom, а пока открыт дашборд — только «Дашборд» и кнопка его закрытия; значок сплита показывает ось и какую панель оставляет на экране скрытый сплит, а его подсказка и подсказка scratch говорят, что сделает нажатие, с клавишей. Хост ssh обрезается посередине, не шире 240 единиц. Pick закрывает палитру и прячет quick terminal; палитра и пикер затемняют окно ниже заголовка и встают по центру над терминалом.
- **Сброс статуса:**
  - `--auto-reset` гасит статус, когда пользователь заходит в сессию;
  - `--pane left|right|scratch` записывает, агент какой панели выставил статус (хук передаёт `AGSHELL_PANE`). Пока одна панель в `blocked`, другая может записать только `blocked`, иначе ошибка `blocked status owned by pane …`. Ввод гасит статус только в той панели, которая его выставила. Переход в сессию самим пользователем (клик в сайдбаре, клавиши сессий, палитра, список ожидающих) открывает и фокусирует эту панель, будь то сплит или scratch; как в agterm, автопереход делает это только в активном окне и не под зумом, а `session select`, `session go`, переключатель, недавние сессии, дашборд и клик по уведомлению только выбирают;
  - ввод в сессии гасит `blocked` и `completed` так, как задано в настройках («Сброс статуса»), как в agterm: от первой клавиши (по умолчанию), только от Enter (начатый и брошенный ответ держит значок; Esc или Ctrl+C всё равно гасят `blocked` — отмена запроса тоже ответ) или никогда (статус держится до следующего хука агента или Clear Status);
  - Esc (с любыми модификаторами) и Ctrl+C без других модификаторов гасят `active` при любой настройке;
  - как в agterm, считается нажатие клавиши, а не её байты: Enter — отправка только без модификаторов (Shift+Enter и Alt+Enter в Claude Code и Codex переносят строку), а вставка, перетаскивание и собственные ответы терминала не считаются ничем;
  - `session type` тоже считается вводом: перевод строки в тексте — отправка, прерыванием он не бывает.
- **Хранение:** статус не сохраняется между запусками. В `tree --json` у сессии есть поля `status`, `statusPane` (только если запись назвала панель), `statusBlink`, `statusColor`, `statusShape`, `statusChangedAt` (секунды Unix) и `unseen`; у сессии в idle из полей статуса есть только `statusChangedAt`.
- **`session wait`** печатает статус, на котором дождался, и завершается с кодом 0. Если сессия закрылась, код 2. Если вышло время, код 124. Ожидание идёт по ленте событий, поэтому смена статуса между проверками не теряется. Как в agterm, `--target` ищется во всех открытых окнах (`active` — выбранная сессия переднего окна), `--timeout` соблюдается, даже если AgShell перестал отвечать, а занятый канал повторяется до 30 секунд; прочие сбои — `Error: ...` с кодом 1. Как в agterm, несколько статусов задаются повтором `--until`; `--until idle,blocked` — это `invalid status: idle,blocked`.
- **Уведомления из терминала:** OSC 9 с текстом (`ESC ] 9 ; текст BEL`) и OSC 777 (`ESC ] 777 ; notify ; заголовок ; текст BEL`) показываются как toast. Исключение, как в agterm, — когда пользователь печатает именно в этой панели и AgShell впереди. Повтор из той же панели заменяет её toast, у `notify` в каждой сессии своё место, а клик открывает сессию на панели, откуда пришло уведомление (закрытое с тех пор окно откроется). Переход к сессии или фокус на её панели убирает её toast-ы из центра уведомлений. Собственные toast-ы AgShell (сбой хука или команды, проблемы в keymap.conf, hooks.conf, remotes.conf или в конфиге ghostty, сброс живых сессий) тоже заменяют свой прежний; как у agterm, они принадлежат приложению, поэтому не требуют открытого окна, не издают звука, а проблемы этих файлов, которые были уже при запуске, показываются один раз после открытия окон. Клик по такому toast-у или по toast-у закрытой сессии выводит AgShell вперёд. Кнопка на панели задач мигает, только пока впереди нет ни одного окна AgShell, — Dock не подпрыгивает, пока agterm активен. `session seen` обнуляет счётчик и, как в agterm, оставляет toast-ы в центре уведомлений. Как под agterm, текст читается так, как его читает libghostty: команды ConEmu в OSC 9 (`1;`, `10`, `11;`, `12`, `2;`–`9;`, `4;0`–`4;4`, `5`) — не уведомления, всё остальное — уведомление, пустой текст тоже; OSC 777 нужны обе `;` после `notify`, а пустой заголовок заменяется именем сессии. Уведомляют только собственные панели сессии (основная и правая), не scratch и не оверлей. Как у Ghostty, приложение показывает не больше одного уведомления из терминала в секунду, а одинаковые заголовок и текст — раз в пять секунд; `desktop-notifications = false` в ghostty.conf их выключает. `notify` показывает toast всегда.
- **Список переходов кнопки на панели задач**, как меню Dock у agterm: «Новая сессия», «Новое окно», Quick Terminal и «Дашборд» для переднего окна, его «Недавние сессии» (до 10, без выбранной) и «Сессии, ждущие внимания», каждая с подписью «сессия — workspace». Выбранный пункт выводит это окно вперёд и действует в нём, как в agterm; пункт, который сейчас выполнить нельзя (окно в зуме или под модальным, сессии уже нет, дашборд с тех пор открыт или закрыт), ничего не делает, так как Windows не умеет показывать пункт неактивным, пустая категория не показывается, а списки — плоские категории над задачами: у списка переходов нет подменю, а задачи всегда внизу. Список сохраняется заранее и обновляется, так как Windows не спрашивает его при открытии; пункт запускает `agshell.exe --dock …`, а тот передаёт его работающему экземпляру.
- **`events`** печатает события, пока его не остановят: как в agterm, по строке «время вид имя …» (у `status` — статус, `previous=`, `pane=`, `blink`, `color=`, `shape=`; у `remote.*` — `host=`), а с `--json` — строками JSON. Первое чтение отдаёт то, что приложение уже хранит. Как в agterm, аргументы (id `--run`, число `--after`, `--limit` 1–1000, каждый `--kind`) проверяются до отправки, повторяющиеся виды уходят один раз. Если канал есть, но не принимает подключение, поток повторяет чтение с растущей паузой до 30 секунд и только потом завершается; если канала нет (AgShell закрыт) или пришёл отказ, поток сразу завершается с `Error: ...`. У статусных событий в `payload` есть `status` и `previous`. Поток один на всё приложение: в нём события всех окон, у каждого поле `window` с id окна (у `app.launched` его нет, это событие одно на запуск).
- **`pane.focused`**, как в agterm: выбор в сессии перешёл на другую панель сплита. В событии — имя сессии, `pane` (`left` или `right`) и `paneID` этой панели (нет, пока её терминал не создан). Сообщается устоявшийся выбор, через 100 мс: переход туда и обратно за это время ничего не даёт. Событие следует за терминалом, а не за местом: клик, клавиши фокуса, `session focus`, новый сплит, закрытие выбранного сплита и выход основного шелла, пока он выбран, дают событие; обмен панелей, показ скрытого сплита и запуск шелла в панели — нет. Сессия, которую окно видит впервые, молчит.
- **Сочетания:** Ctrl+Alt+Shift+↓ и Ctrl+Alt+Shift+↑ — следующая и предыдущая сессия, которой нужно внимание (`blocked` или `completed`).

## Хуки и скилл

```
agshellctl install hooks [--opencode v1|v2|skip]   # хуки статуса Claude Code, Codex, Pi и OpenCode (Windows и WSL, где агент настроен)
agshellctl install skill     # папка скилла в ~/.claude/skills/agshell и ~/.codex/skills/agshell (Windows и WSL)
agshellctl hook <state> [аргументы…]                 # обёртка статуса: session status для этого терминала
agshellctl hook claude <state> [аргументы…]          # адаптер Claude Code
agshellctl hook codex <событие>                       # адаптер Codex
```

Куда что ставится, как в agterm:
- **Claude Code** — `~/.claude/settings.json` (в Windows всегда, в WSL при наличии `~/.claude`), копия в `settings.json.bak`. При файле-ссылке (dotfiles) меняется цель, а копия остаётся рядом с исходной ссылкой. Неверный тип `hooks` или события отклоняется без записи; пользовательские флаги и обёртки существующих хуков сохраняются. В WSL хуки Claude вызывают `~/.config/agshell/agent-status/agshell-claude-status.sh`: guard воркера обходит Linux-родителей, затем общая обёртка вызывает Windows CLI с передачей окружения сессии через `WSLENV`. В Windows остаётся `agshellctl hook claude`. Guard читает до восьми родителей и при недоступной цепочке разрешает отчёт; подряд идущие имена одного агента считаются один раз.
- **Codex** — блок `[[hooks.*]]` между метками `# >>> agshell agent-status >>>` в `~/.codex/config.toml`, если есть `~/.codex`. Повторная установка обновляет блок на месте и сохраняет записи доверия `[hooks.state…]`, которые Codex дописывает внутрь. Если в файле уже есть свои хуки (включая ключи в кавычках) или TOML невалиден, установка его не трогает и говорит об этом. Старый однострочный `notify`, чьё разобранное значение вызывает `codex-notify.sh`, удаляется; чужой notifier, комментарии и многострочный `notify` сохраняются. При ссылке резервная копия остаётся рядом с исходной ссылкой. В WSL команда hook передаёт окружение сессии обратно Windows-адаптеру через `WSLENV`. Новые или изменённые хуки нужно просмотреть и подтвердить через `/hooks` в Codex.

  **Известное ограничение общего сервера**, также описанное в agterm: Codex может запускать hooks с окружением сессии сервера вместо новой вкладки. Автоматической привязки беседы Codex к панели в AgShell нет. В WSL устаревший `WSL_INTEROP` может вовсе помешать запуску Windows-адаптера. Включённых и доверенных hooks недостаточно для подтверждения адресации: проверяйте session, pane и pipe настоящего hook. Full Access не заменяет доверие хукам. Интерактивное исследование WSL и оставшиеся проверки записаны в [публичные границы проверки](sanitation-summary.md).

  Запускайте интерактивный Codex с `--no-daemon` (сохраните свой launcher, например `codex-proxy`, и добавьте флаг к нему). Hooks будут работать в процессе своей вкладки; существующий общий сервер и его сессии продолжат работу. Эта беседа не управляется через общий сервер из desktop/mobile Codex. На Codex 0.165.0 в WSL проверены автоматические active/blocked/completed, настоящий запрос разрешения и правая панель сплита; см. [публичные границы проверки](sanitation-summary.md).

  Это обход, а не исправление общего сервера. Он не отключает сетевой прокси launcher и действует только на новые запуски. Не останавливайте общий сервер и не перезапускайте существующие беседы для его применения. `--no-daemon` несовместим с `--remote` и `codex agents`; такие явные команды общего сервера оставляйте без изменений. Проверка исходников/схем Codex 0.167.0 подтверждает, что одного hook input недостаточно для определения вызывающей панели; живая доставка статусов на этой версии здесь не проверялась. Если resume сообщает, что беседа открыта в другом приложении, оставьте сервер и существующие клиенты работающими: этот обход не переносит уже загруженную беседу.
- **Pi** — расширение `~/.pi/agent/extensions/agshell-status.ts`, если есть `~/.pi/agent`.
- **OpenCode** — версия берётся из `opencode --version` в шелле входа пользователя (в WSL — интерактивном, чтобы прочитались rc-файлы; на это 3 секунды). OpenCode 1 получает `~/.config/opencode/plugins/agshell-status.js`, если есть `~/.config/opencode`; OpenCode 2 — `plugins/agshell-v2/tui.js` в `$OPENCODE_CONFIG_DIR`, иначе в `$XDG_CONFIG_HOME/opencode`, иначе в `~/.config/opencode`, если эта папка есть. Если версию не определить, её задаёт `--opencode` (`skip` пропускает OpenCode); без него строка OpenCode об этом говорит, а команда выходит с кодом 2. Действие палитры, которое ставит хуки, в этом случае спрашивает, как agterm, а что поставлено, показывает в окне, как предупреждение agterm: «Хуки статусов агентов установлены», «— с предупреждением», если какой-то шаг не удался.
- **Интеграция шелла** — для агентов без своих хуков (gemini, cursor-agent, aider, crush, goose), только в WSL, так как в самой Windows нет bash, zsh и fish: скрипты кладутся в `~/.config/agshell/agent-status`, а блок между метками `# >>> agshell agent-status >>>`, подключающий `shell/integration.sh`, — в `~/.zshrc` и `~/.bashrc` (`shell/integration.fish` — в `~/.config/fish/config.fish`, если есть `~/.config/fish`). Как в agterm, команда, подходящая под `AGSHELL_AGENT_RE` (по умолчанию `^(gemini|cursor-agent|aider|crush|goose)([[:space:]]|$)`, чтобы изменить — задать до блока), ставит `active --blink`, а следующее приглашение — `idle`; Claude Code, Codex, Pi и OpenCode в список не входят нарочно: их собственные хуки сообщают точнее. В bash используется bash-preexec, если он загружен, иначе ловушка DEBUG — только если другой нет. Блок, уже стоящий в файле, не трогается.
- Файл расширения или плагина, который написал не AgShell (нет метки agshell в начале), не перезаписывается.

Адаптер Codex повторяет agterm: `PermissionRequest` приходит до того, как автопроверка Codex решит, нужен ли человек, поэтому сам по себе он не ставит `blocked`. Отдельный процесс раз в полсекунды читает экран панели и ставит `blocked`, только пока видно окно подтверждения, а когда оно закрылось — возвращает `active`. На `Stop` последний ответ проверяется на вопрос: если он спрашивает — `blocked`, иначе `completed --auto-reset`. Плагины OpenCode и Pi взяты из agterm (MIT, `src/AgShell.Ctl/AgentStatus/LICENSE-agterm`).

Наблюдатель запускается без наследования дескрипторов обработчика: WSL сразу возвращает управление из hook, а чтение экрана продолжается.

События Claude Code и статусы такие же, как у agterm:

| Событие Claude Code | Статус |
| --- | --- |
| `UserPromptSubmit`, `PostToolUse` | `active --blink` |
| `Stop` | `completed --auto-reset` |
| `PermissionRequest`, `Notification` с matcher `permission_prompt` | `blocked` |

**Как ведёт себя `hook`:**
- вне AgShell (нет `AGSHELL_SESSION_ID`) ничего не делает;
- ничего не печатает и всегда завершается с кодом 0;
- `hook <state>` — обёртка agterm: `session status <state>` для сессии терминала с его панелью и id панели (`AGSHELL_PANE`, `AGSHELL_PANE_ID`), остальные аргументы передаются как пришли (`--sound`, `--color`, `--shape`…); `--pane` или `--pane-id`, заданные вручную, главнее;
- `hook claude` добавляет защиту agterm, только для хуков Claude Code: если над Claude в дереве процессов есть ещё один агент, хук молчит: такой Claude — воркер, запущенный из инструмента, и не должен перекрашивать сессию родителя. Как в agterm, процесс node, bun, deno или python считается по скрипту, который он выполняет: по имени файла, а так как npm в Windows запускает `node "…\node_modules\ПАКЕТ\ФАЙЛ"`, а не ссылку с именем команды, — по имени из `bin` пакета для этого файла. `AGSHELL_AGENT_RE`, как `AGTERM_AGENT_RE` у agterm, добавляет имена (регулярное выражение .NET; некорректное не добавляет ничего). Если дерево процессов прочитать не удалось, хук всё равно отправляет статус;
- как `AGTERM_STATUS_WRAPPER` у agterm, `AGSHELL_STATUS_WRAPPER` называет программу, которую адаптеры Claude Code и Codex и плагины OpenCode запускают вместо обёртки, с состоянием и его флагами;
- наблюдатель Codex держит по файлу на терминал (по `AGSHELL_PANE_ID`, иначе по панели); как в agterm, `AGSHELL_CODEX_WATCH_FILE`, `AGSHELL_CODEX_WATCH_MAX_CHECKS` и `AGSHELL_CODEX_WATCH_INTERVAL` (секунды) это меняют.

Повторный `install hooks` ничего не дублирует, а при смене пути `agshellctl` обновляет команды на месте.

**Как работает `install skill`**, как в agterm: в Windows и в каждом дистрибутиве WSL папка скилла целиком ставится в `~/.claude/skills/agshell`, если есть `~/.claude`, и в `~/.codex/skills/agshell`, если есть `~/.codex`; если нет ни того ни другого — для Claude Code. Прежняя установка заменяется целиком. Одноимённый скилл, который AgShell не ставил (в его `SKILL.md` нет `<!-- agshell-skill -->`, файла нет или он не читается), не трогается и попадает в «Skipped». В отчёте — куда скилл встал, что пропущено и почему, а если каталог skills создан впервые — просьба перезапустить работающие сессии агентов; код выхода 0 только без пропусков. С `--json` отчёт — объект JSON с `installed`, `skipped` и `freshSkillsDirectory`.

## Флаги и фильтр workspace

```
agshellctl session flag [on|off|toggle] [--target S]...   # пометить сессии; toggle помечает все, если не все уже помечены
agshellctl session flag clear                            # снять пометку со всех сессий
agshellctl workspace flag [on|off|toggle] [--target W]   # пометить или снять пометку со всех сессий workspace разом
agshellctl sidebar mode tree|flagged|toggle               # дерево или список помеченных сессий
agshellctl sidebar flagged-layout [flat|plain|tree|toggle] # вид помеченных: список с workspace, только имена или дерево
agshellctl workspace focus [on|off|toggle|add] [--target W]
agshellctl workspace filter on|off|toggle                 # включить или выключить фильтр, набор сохраняется; включение без отмеченных ничего не делает
```

Как в agterm:
- **Флаг** — рабочий набор сессий поверх workspace. Помеченная сессия выделена цветом иконки. Вид «Помеченные» (флажок внизу боковой панели, `toggle_flagged_view`) показывает их одним списком с подписью «сессия : workspace»; `sidebar flagged-layout` и настройка «Помеченные сессии» меняют это на список без workspace или дерево по workspace; когда помеченных нет, там подсказка, как пометить. «Убрать все пометки» (`clear_flagged`) спрашивает подтверждение. `workspace flag` и пункт «Пометить все сессии» в меню workspace ставят одно значение всем его сессиям, в том числе скрытым в виде «Помеченные»: `toggle` снимает пометку, только если помечены все, иначе помечает все; пустой workspace не меняется, другой режим — ошибка `invalid workspace flag mode: …`.
- **Фильтр workspace** показывает только отмеченные workspace. В меню workspace есть два пункта:
  - «Фокус» оставляет только этот workspace; если он уже единственный, фильтр снимается (`workspace focus toggle`, действие `focus_workspace`);
  - «Добавить в фокус» / «Убрать из фокуса» меняет только его отметку (`add` / `off`); добавление фильтр не включает, чтобы набор собирался при видимом дереве целиком, а снятие последней отметки фильтр выключает.
  Воронка внизу панели (`toggle_workspace_filter`) включает и выключает фильтр, не забывая набор.
- **Низ боковой панели**, как в agterm: слева «Новый workspace» и «+», в меню которого «Новая сессия», «Новая сессия с шеллом» и «Открыть каталог…»; справа воронка и флажок. Флажок выключен в дереве, пока нет помеченных; подсказки говорят, что сделает нажатие, с клавишей.
- **Навигация** идёт только по видимому: `session go`, Ctrl+Alt+↑↓, переход к сессиям, ждущим внимания, палитра сессий, Ctrl+Tab. Палитра «ждущих внимания» показывает все сессии.
- **Выбор сессии вне фильтра** (из agshellctl, из уведомления), создание выбранной сессии в скрытом workspace или перенос выбранной сессии из отмеченных выключает фильтр, набор сохраняется. Если сужение скрыло текущую сессию, выбирается последняя использованная из видимых. Выбор пустого скрытого workspace (`workspace select`) добавляет его в набор. `workspace go` шагает только по показанным workspace и не работает в виде «Помеченные»; из workspace вне них входит с того края, откуда шаг.
- **Закрытие выбранной сессии** выбирает, как в agterm, последнюю использованную видимую сессию её workspace, затем из всех видимых, затем из всего дерева; без истории — ближайшую видимую строку. Закрытый или удалённый workspace уходит из отмеченных; отмена и Open Recent отмечают его снова.
- **Свёрнутый workspace** раскрывается на экране, когда выбрана сессия в нём, но в состоянии остаётся свёрнутым (`collapsed` в `tree --json`); сворачивание строки закрывает его.
- **`tree`** показывает `(flagged)` у сессий и `(focused)` у отмеченных workspace; в `--json` есть `flagged`, `focused`, `sidebarMode`, `focusEnabled`. Флаги, набор и режим сохраняются между запусками.
- **Клавиши:** у agterm `toggle_flag` — ⌘⇧F, но Ctrl+Shift+F у нас занят поиском, поэтому эти действия без клавиш по умолчанию.

## Выделение нескольких сессий и папки из Проводника

Это только окно, без команд agshellctl. Как в agterm:
- **Выделение.** Ctrl+клик добавляет сессию к выделению или убирает из него, Shift+клик выделяет диапазон видимых строк, обычный клик снимает выделение. Как в agterm, текущей становится кликнутая строка, если она выделена (иначе остаётся текущая, если она ещё выделена, иначе последняя выделенная); все выделенные строки рисуются одинаково и приглушаются, пока окно не активно. Выбор сессии любым другим способом (клавиши, палитра, `agshellctl`) снимает выделение, как и фильтр или режим помеченных, скрывший его строки. Правый клик вне выделения сужает его до кликнутой строки. Контекстное меню на выделенной строке относится ко всем сразу: сбросить статусы, отметить для внимания, пометить или снять пометку, перенести в workspace, закрыть. Закрытие нескольких отменяется одним Ctrl+Shift+Z. Контекстным меню можно управлять клавишами: стрелки, Enter, вправо и влево — в подменю и обратно, буква — к следующему пункту на неё.
- **Перетаскивание в боковой панели** (только в дереве, как в agterm). Сессия встаёт до или после строки, а брошенная на заголовок workspace — в его конец; перетаскивание с выделенной строки переносит всё выделение одним блоком. Workspace встаёт до или после другого, а на пустом месте ниже — после последнего. Место, где ничего не изменится, не подсвечивается и не принимает перенос. Свёрнутый workspace, над которым задержались, раскрывается через 0,65 с и сворачивается обратно, если увести курсор или отменить; после переноса в него он остаётся раскрытым на экране, но без сохранения.
- **Папки из Проводника.** Папка, брошенная на боковую панель, открывается новой сессией в этом каталоге: в workspace строки, на которую её бросили, на пустом месте — в единственном отфильтрованном или текущем; этот workspace подсвечивается при перетаскивании. Больше 20 папок за раз — не открывается ни одна, появляется предупреждение; файлы пропускаются, вид «Помеченные» перетаскивание не принимает.
- **Файлы на терминале.** Брошенные на терминал файлы и папки вставляются путями: в кавычках для Windows-шеллов, как `/mnt/c/...` для WSL. Брошенное мимо игнорируется, окно никуда не уходит.
- **«Открыть каталог…»** (палитра действий, меню workspace, действие `open_directory`) создаёт сессию в выбранной папке: в workspace, из меню которого его выбрали, иначе в текущем, и в режиме помеченных тоже. У agterm это ⌘O, у нас Ctrl+O принадлежит терминалу, поэтому клавиши по умолчанию нет.
- **«Открыть в AgShell» и пути в командной строке** (как `open -a agterm <путь>` у agterm): `agshell.exe <путь>…` открывает каждый путь новой сессией в текущем workspace последнего активного окна, выбирает её и выводит окно вперёд: папку — саму, файл — его папку, несуществующий путь пропускается. Пути получает уже запущенный AgShell той же папки состояния; новый сначала открывает свои окна. Установщик добавляет «Открыть в AgShell» в контекстное меню Проводника для папки, пустого места внутри папки и диска (в Windows 11 — в «Показать дополнительные параметры»: новое меню принимает команды только упакованных приложений).

## Выбор и вопросы

```
printf '%s\n' staging production | agshellctl pick --prompt "Куда выкатывать?"
agshellctl pick [--prompt T] [--query Q] [--select ID] [--allow-custom] [--follow] [--no-block]   # пункты из stdin
agshellctl pick result ID | pick cancel ID
agshellctl ask "Выкатить?" --button yes=Выкатить --button "no=Не сейчас" --default no --hotkey yes=d
agshellctl ask "Сообщение?" --input line|multiline [--value T] [--placeholder T]
agshellctl ask "Что собрать?" --choice a=Alpha --choice b=Beta [--choice-subtitle b=…] [--multiple] [--checked a] [--other "другое"]
agshellctl ask … [--style terminal|gui] [--align left|center|right] [--width 10..100] [--target S] [--pane left|right] [--no-block]
agshellctl ask result ID | ask cancel ID
```

Как в agterm:
- **pick** читает пункты из stdin до конца, как agterm, даже из терминала (конец — Ctrl+Z, Enter): каждая непустая строка (деление по любому переводу строки) — пункт, stdin не в UTF-8 — ошибка использования, а текст, начинающийся с `[`, — JSON-массив `{id,label,subtitle?,status?,statusColor?,statusShape?}` (до 1000). Поиск идёт только по подписи; пока запрос пуст, порядок как у вызывающего. `--allow-custom` принимает запрос, которому ничего не соответствует: как в agterm, вместо пустого списка появляется строка «Использовать «…»» с запросом без пробелов по краям, её выбирают Enter или кликом. Esc или клик по затемнению вокруг отменяют. Сочетания меню, например Ctrl+, и Ctrl+Shift+Q, доступны и в поле поиска. Ответ — одна строка JSON: `{"result":"picked","id":…,"label":…,"index":…}` или `{"result":"custom","query":…}` с кодом 0, `{"result":"cancelled"}` с кодом 2 (Esc).
- **ask** — заголовок и от одной до шести кнопок (`ID=ПОДПИСЬ` или просто подпись). С полем ввода или списком кнопки можно не задавать: будут OK и Cancel. Enter жмёт подсвеченную кнопку (в многострочном поле — Ctrl+Enter), Tab и стрелки двигают подсветку (у списка вверх и вниз ходят по нему, пробел отмечает), буква из `--hotkey` жмёт свою кнопку, и у списка тоже: как в agterm, на латинской раскладке — набранная буква, на любой другой — по месту клавиши в US. Буква подчёркнута в подписи или дописана как « (X)»; кнопки шириной в самую широкую, в ряд или, если ряд не помещается, столбиком. Как в agterm, сочетания с Ctrl или Alt достаются окну, кроме закрывающего. Клик по области терминального вопроса выбирает его панель и отдаёт вопросу клавиатуру. Как в agterm, терминальный стиль берёт шрифт терминала из настроек и показывает кнопку `--destructive` жирной с «! » (в GUI-стиле она красная); `--width` — эта доля области под вопросом, без него панель берёт свою ширину до 90 % области и 72 клеток терминала (поле ввода — всю эту ширину). Поле вмещает до 64 КБ (предзаполнение обрезается до них); многострочное растёт с текстом, с учётом переносов, от 5 до 15 строк. Esc и кнопка из `--cancel` дают `{"result":"escaped"}` с кодом 3; ответ — `{"result":"answered","id":…,"label":…,"index":…}` плюс `text` у поля и `selected` у списка, код 0; `ask cancel` и закрытие сессии — `cancelled`, код 2.
- **terminal** (по умолчанию) рисуется шрифтом и цветами терминала над выбранной сессией или панелью и не мешает работать в остальном окне; у сессии одновременно один такой вопрос. Он забирает клавиатуру, пока виден на экране, а вопрос панели — пока у его панели фокус; только тогда его закрывает Esc. Как в agterm, Enter и Esc во время набора через IME достаются IME. Набранное и выбранное в нём сохраняется при переходе в другую сессию и обратно. **gui** — панель по центру того, к чему она привязана: области терминала, сессии с `--target`, панели с `--pane`; эта часть затемняется, а остальное окно не принимает кликов, пока вопрос открыт. Она делит место с `pick`, второй диалог отвечает `pick already pending` или `ask already pending`; палитру она закрывает. Как в agterm, GUI-вопрос над панелью идёт за панелью, когда панели меняются местами или сплит встаёт на место главной, и отменяется, когда его панель закрылась или ушла с экрана (сплит скрыт, а фокус у другой панели). Как в agterm, вопросу с `--target`, который рисуется здесь, нужна панель на экране (`pane not visible`), а GUI-вопросу — выбранная сессия не под zoom и не под дашбордом (`session not visible`).
- Без `--no-block` команда ждёт ответа; Ctrl+C отменяет диалог. С `--no-block` печатается `{"id":…}`, а ответ читается через `result`. Как в agterm, ответы хранятся и после закрытия диалога: последние 8 выборов каждого окна (и 32 закрытых окон), последние 32 вопроса всего приложения.
- `tree --json`: `pickPending` и `askPending` вверху, `ask` с `id` и `pane` у сессии.

## Восстановление сессий

```
agshellctl restore mode                 # текущий режим
agshellctl restore mode none|rerun|live # сменить; live включается после перезапуска AgShell
agshellctl restore capture              # запомнить программы панелей сейчас, как при выходе (только rerun)
agshellctl restore clear                # забыть запомненные программы; закрепления остаются
agshellctl session restore "claude --resume ID" [--pane left|right] [--target S]   # закрепить команду
agshellctl session restore --none | --clear [--pane left|right] [--target S]       # закрепить простой шелл или снять закрепление
agshellctl live list                    # как zmx list в agterm: режим восстановления, затем каждый сохранённый шелл с состоянием, клиентами и панелью-владельцем
agshellctl live screen NAME [--all | --lines N]   # экран сохранённого шелла текстом из терминала его демона, показан он в окне или нет; NAME — как печатает live list
agshellctl live prune                   # завершить шеллы, которые ничья панель не забирает
agshellctl live reset --force           # как zmx reset у agterm: сбросить живые сессии старше последнего обновления демона, затем выйти и открыться снова
agshellctl live kill --pane left|right --force --target S [--window W]  # завершить сохранённую оболочку одной панели и её процесс; как zmx kill в agterm, без отмены, 'active' не принимается
agshellctl live proxy PANE              # протокол демона панели на stdin/stdout, для другого ПК: ssh ПК agshellctl live proxy PANE
agshellctl live tree [HOST]             # сессии, к которым можно подключиться: этого ПК или HOST через ssh
agshellctl live attach HOST ID [--window W]   # подключить сессию HOST удалённой строкой (ID из live tree HOST), печатает id строки
agshellctl live present SESSION         # поток статуса, контекста, HUD и уведомлений сессии строками JSON, для другого ПК
agshellctl session overlay run-job JOB  # запустить overlay, переданный другому ПК, в его ssh-терминале (вызывает AgShell)
agshellctl session overlay page-serve TOKEN  # канал страницы, переданной другому ПК (вызывает AgShell)
```

Как в agterm («Восстанавливать сессии» во вкладке «Общие»):
- **none** (по умолчанию): при запуске та же раскладка со свежими шеллами.
- **rerun:**
  - При выходе (закрытие последнего окна, «Выйти из AgShell», выход из сеанса) для каждой основной панели и показанного сплита запоминается программа, работающая в шелле. Окно, закрытое, пока открыты другие, свои программы забывает. Для Windows-шеллов она берётся из дерева процессов, для WSL — по переменным `AGSHELL_*` процессов дистрибутива.
  - При запуске программа набирается в свежий шелл, как только появится приглашение. Так делает только запуск приложения, как в agterm: окно, открытое позже, и недавно закрытое возвращаются простыми шеллами. Запуск сразу убирает программы из файла состояния, поэтому после сбоя они не запустятся второй раз.
  - Шелл, после которого только флаги, ничего не запоминает; шелл, выполняющий скрипт или строку (`bash ./run.sh`, `pwsh -File x.ps1`, `cmd /c …`), запоминается как программа, как в agterm.
  - Не возвращаются программы из `restore-denylist.conf` в папке конфигурации (`%APPDATA%\agshell\config`) (по одному имени в строке, например `ssh`), а также команды с управляющими символами; список читается при запуске, поэтому не вернётся и программа, добавленная в него после выхода.
  - Перезапуск сессии команду не повторяет.
  - `restore capture` нужен на случай выхода без закрытия окна (сбой, выключение питания): его можно повесить на клавишу или запускать по расписанию.
  - **Закрепление** (`session restore`) задаёт, что панель запускает при каждом старте вместо запомненной программы; `--none` — простой шелл. Закрепление не исчезает после запуска и не проверяется по `restore-denylist.conf`. Оно работает только в rerun; в другом режиме сохраняется на будущее, и команда об этом предупреждает. Закрепление, заданное во время работы, действует со следующего запуска. Видно в `tree --json` как `restoreCommand` и `splitRestoreCommand`. Значение хранится в файле состояния, секреты туда не кладите; если файл не записать, команда отвечает ошибкой и остаётся прежнее значение.
  - Scratch, overlay и quick terminal не восстанавливаются.
- **live** (замена zmx из agterm):
  - Шелл основной панели или сплита держит собственный демон `agshell-live.exe`, как zmx у agterm держит каждую панель, поэтому шелл переживает закрытие окна вместе с запущенными программами. Демон называется по личности панели (`AGSHELL_PANE_ID`), которая переходит вместе с шеллом при обмене и при повышении сплита.
  - При следующем запуске окно подключается к ним снова. Как zmx в agterm, демон держит состояние терминала своей панели (ghostty-vt, в `agshell-vt.dll` рядом с демоном), и вернувшееся окно получает это состояние, а не вывод заново: экран и до 10 000 строк истории, стили, курсор и его форма, режимы, заголовок и рабочий каталог, разложенные под размер ведущего окна. Строка длиннее панели возвращается перенесённой, как была, одной строкой, так что копирование и смена размера сохраняют её целой (zmx в agterm режет её на строки). Затем демон дёргает размер на строку вверх и обратно, и программы, которые перерисовываются при смене размера (`top`, агенты), встают как были; строка шелла остаётся там, где её показывает окно. Окно, которое запустило панель, получает вывод по мере появления. Вопросы шелла или ConPTY к терминалу (`ESC [ c` и подобные) не повторяются, поэтому вернувшееся окно не отвечает на них заново в строку шелла. Пока панель не показывает ни одно окно, на DA1 и DA2 отвечает сам демон (`ESC [ ? 62 ; 22 c`, `ESC [ > 1 ; 10 ; 0 c`, как zmx), так что спросившая в это время программа не ждёт ответа.
  - Текст читается из того же терминала, как `zmx screen` у agterm: обычный текст, перенесённые строки склеены, пробелы в конце строк обрезаны, раскладка под размер ведущего, без управляющих последовательностей и без стёртого. `live screen` отдаёт видимый экран, `--all` — ещё и историю, `--lines N` — последние N строк (пустые строки внизу отбрасываются); окно для этого не нужно. У панели этой машины в режиме live `session text --all` и `--lines` и `surface cursor` тоже читают демон, как и обычный `session text`, пока панель ведёт другая сторона или не ведёт никто; обычный `session text` ведущей панели читает саму панель, в том числе с её прокруткой.
  - `session type` в такую панель тоже идёт через её демон, ведёт панель или нет, как `zmx type` у agterm. Демон пишет текст в шелл и ведение не трогает. Каждый Return он кодирует под режим клавиатуры, который запросила программа (при протоколе клавиатуры Kitty это `CSI 13 u` и отпускание), и отвечает, принял ли ввод. Недонабранная композиция IME уходит первой тем же путём и второй раз не отправляется. Отказ или отсутствие ответа — `the pane's daemon did not accept the input`. Если не подтверждён только последний Return, который уходит отдельно от текста, ошибка — `text typed, but its final Return could not be confirmed; do not retype the text`. Ввод больше 256 КБ отвергается, как у zmx. Демон старше этой операции не отвечает, поэтому ввод в его панель не проходит до `live reset`.
  - Если демона нет (например, после перезагрузки), панель стартует заново с запомненной программой, как в rerun; если программа не запомнена — с `--command` сессии. Как скрипт повтора agterm, программа — первая команда нового шелла демона, а не набор в его приглашение: PowerShell запускает её после своего стартового скрипта (`-EncodedCommand`, затем `-NoExit`), cmd — через `/k`, WSL — в шелле входа (`$SHELL -lic`), который затем становится интерактивным. Поэтому она не ждёт приглашения, не попадает в историю команд шелла (`Get-History` в PowerShell её показывает, стрелки — нет), а Ctrl-C завершает программу и оставляет шелл. Если демон ещё жив, шелл остаётся его и ничего не запускается. Как в agterm, закрепление (pin) в live не используется. `session restart` такой панели запускает свою строку так же.
  - Демон, который не удалось запустить (например, из-за антивируса), пробуют запустить из папки установки. При отказе запуска или подключения, а также обрыве связи без подтверждённого выхода шелла панель показывает ошибку и сохраняет сессию, id, каталог и заявку. После повторного открытия окна она остаётся остановленной до явного перезапуска. Подтверждённый выход шелла по-прежнему штатно закрывает панель.
  - Демоны и перезапускатель Reset Live Sessions выходят из job приложения (`CREATE_BREAKAWAY_FROM_JOB`), как у agterm они запускаются отдельно от приложения, поэтому переживают AgShell, запущенный из терминала, который завершает свой job при закрытии. Если job этого не разрешает, они остаются в нём и завершаются вместе с ним.
  - Можно ли работать в live, проверяется при каждом запуске в любом режиме, как в agterm; если нельзя (нет `agshell-live.exe`), `restore mode` показывает `live unavailable: the agshell-live executable is unavailable`, активный режим указывается как none, а основные панели и сплиты остаются остановленными с сохранёнными сессиями; настройки показывают причину под режимом, пока выбран live. Уведомления об этом нет, как в agterm.
  - Сохранённый id панели старой версии, несовместимый с live, сохраняется вместе со ссылками. Панель показывает ошибку совместимости и не получает новый id. Её заявка оставляет обход неполным, поэтому prune и reset отказывают. Разные текстовые записи одного UUID означают одну идентичность; несколько владельцев остаются конфликтом.
  - Scratch, overlay и quick terminal остаются временными.
  - Закрытие сессии завершает её демоны.
  - Как уборка при запуске в agterm, каждый запуск в live до открытия окон завершает демоны, которые ничья панель не забирает и ни один клиент не показывает (например, оставшиеся после сбоя); шеллы закрытого окна остаются. Если состояние какого-то окна не читается, не завершается ничего.
  - Как в agterm, панель получает id при создании своей сессии или сплита и сохраняется с ним, поэтому шелл, запущенный перед самым сбоем, возвращается к своей панели. Сохранённая панель без id получает его при запуске, и он сразу записывается в состояние её окна; её прежний шелл, если был, завершается как ничейный.
  - Режим выбирается при запуске. После переключения на другой режим и перезапуска шеллы, которые ни один клиент не показывает, завершаются вместе с их демонами, как в agterm.
  - Демон уходит вместе со своим шеллом.
  - `live list`, `live prune`, `live kill` и `live screen` работают в любом режиме восстановления, как команды zmx у agterm. `live list` сводит демонов с панелями, которые их заявляют (открытые окна, сессии в окне отмены, закрытые окна и файлы окон, которых нет в индексе): строка на каждого демона и каждую заявку, `state` `claimed`, `pendingClose`, `orphan` (ничья), `unknown` (ничья, пока какое-то окно не прочитано) или `conflicted` (её заявляют две панели), `observation` `running`, `unreadable` (демон не ответил) или `absent` (панель, чей демон пропал). Удалённая строка панелей не заявляет. Если каналы не перечислить, команды отвечают `could not read the live session list`. `live prune` завершает только ничьих демонов, работающих и без клиентов, перед этим перечитывает список и щадит того, к кому подключился клиент, и сообщает про каждого `killed NAME` или `NAME: not killed (ПРИЧИНА)`; считаются только подтверждённые. `live kill` отказывает `NAME is not running`, `NAME is unreadable; killing it could orphan a live daemon`, `NAME belongs to a session waiting out its undo window`, `NAME is not claimed by that pane` или ошибкой неполного учёта; промах — `no left|right pane daemon for session S`, неизвестный `--window` — `no such window: W` (ищется среди окон заявок, закрытые и неиндексированные тоже). Как у zmx в agterm, завершение засчитывается, только если демон сказал, что завершил шелл; иначе `could not kill NAME: ПРИЧИНА`, и панель остаётся. `live screen` принимает имя демона без пробелов и управляющих символов (`live.screen requires a daemon name`).
  - Обновление сохраняет живые сессии, как обновление agterm сохраняет его демоны zmx: демон работает из копии своей сборки `%LOCALAPPDATA%\agshell\live\<сборка>`, поэтому установщик заменяет программу и закрывает окно, не трогая его (Windows блокирует файлы запущенной программы, а установщик закрывает всё, что держит заменяемые файлы). Шеллы, запущенные до обновления, остаются на демонах старой сборки, новые стартуют на новой; копия, из которой не работает ни один демон, удаляется при следующем запуске. Это относится к совместимым версиям с отдельными демонами панелей. Опубликованная 0.3.0 ещё использует общий `agshell.exe --host` из папки установки: перед обновлением до 0.4.0 его live-процессы нужно явно завершить, иначе установщик может отказать из-за занятого exe. Автоматического подключения к этому старому хосту нет. Старые id панелей `p…` сохраняются заблокированными, как описано выше; перед переходом сохраните работу и резервную копию состояния.
  - К демону можно подключиться сразу нескольким клиентам: окну этого ПК и AgShell с другого ПК через `ssh ПК agshellctl live proxy PANE` (как zmx attach у agterm; нужен OpenSSH Server на этом ПК и AgShell в режиме live). Вывод панели получают все, кто её показывает. Размер ConPTY задаёт ведущий — тот, кто подключился последним. Как у zmx в agterm, когда он уходит, не ведёт никто: остальным об этом сообщается («Переподключаю…»), и они подключаются заново, не заявляя ведение; ведёт первый пришедший, а до тех пор панель сохраняет размер. Ввод от неведущего клиента отбрасывается; клиент, который не говорит, что он окно (стоковый `attach` zmx, у нас — только AgShell старой версии), забирает ведение вводом с клавиатуры, но не ответами своего терминала и не отчётами мыши и фокуса.
  - **Сбросить живые сессии…** (меню «AgShell», рядом с выходом, как у agterm; видно, только когда live — и настроенный режим, и режим этого запуска) и `live reset --force`, как Reset Live Sessions и `zmx reset` у agterm. Живые сессии переживают обновления на том демоне, с которым начались; сброс завершает процессы сессий, чей демон запущен раньше первого запуска с этой сборкой демона (`live-build.json` в каталоге состояния: id сборки демона и время его смены; id — хеш исходников демона, поэтому обновление, не затронувшее демон, его не сдвигает), и создаёт их заново на текущем демоне, по возможности снова набирая запомненные программы. Остальная работа в них останавливается, а разговоры агентов, возможно, придётся продолжить вручную. Действие сначала спрашивает; `live reset` не спрашивает и требует `--force`. Оба отказывают вне режима live или когда смена режима ждёт перезапуска, когда не читается список демонов, когда не читается состояние какого-то окна или панель указана дважды, и когда сбрасывать нечего. Затем AgShell выходит без вопроса о выходе и открывается снова на том же каталоге состояния (`live reset` сначала отвечает): выход пишет `live-reset.json`, только когда все окна и список окон сохранились. Следующий запуск до открытия окон заново проверяет каждую панель и сбрасывает только меньше подтверждённого: панель, которую больше никто не забирает, демон, у которого сменился шелл, или запущенный после отсечки пропускаются. Шелл, который после сброса ещё работает, в этом запуске не получает запомненную программу. Если сброс затронул только часть сессий, об этом скажет уведомление. `live list` помечает такой демон `outdated` (`outdated: true` в `--json`). В `tree --json` и `live list --json` есть `liveReset`: `pending` (панели, ждущие выхода) и `last` (что сделал сброс этого запуска: `panes` confirmed/killed/gone/skipped, `unconfirmed` — id панелей, `sessions` affected/reset/partial/unconfirmed, `inventoryFailed`); поля нет, когда нет ни того, ни другого. agterm сбрасывает ещё сессии, чьи процессы macOS приписывает приложению или оставляет сиротами (повторный запрос доступа к микрофону); в Windows шелл всегда дочерний процесс своего демона, такого случая нет.

**Удалённые сессии** (как remote-строки agterm):
- Машины перечисляются в `remotes.conf` рядом с `keymap.conf`: по строке «адрес-для-ssh [подпись]», `#` — комментарий.
- Пока идёт подключение, над сессией, которая была текущей при запуске действия, как в agterm, висит панель «Подключиться к сессии на другой машине: получаю сессии с …» (затем «подключаю …»); ошибка открывается там заново на 5 секунд, даже если панель хода уже скрылась, а если места нет (нет сессии или её закрывает программа) — приходит уведомлением. Действие недоступно, пока `remotes.conf` нет или в нём нет машин. Адрес — первое слово строки без управляющих символов, не начинающееся с `-` (ssh принял бы его за опцию); остаток строки — подпись. Строку с плохим адресом, с управляющими символами в подписи или с адресом, который уже был выше, AgShell пропускает и сообщает уведомлением, как и нечитаемый файл.
- ssh запускается с `BatchMode=yes` и `ConnectTimeout=5`, соединение каждой панели — ещё с `LogLevel=ERROR`. Причина ошибки переподключения — последняя непустая строка ssh при последней пробе, без управляющих символов, не длиннее 200 знаков, а если ssh ничего не сказал — никакой; если на той машине нет `agshellctl`, так и сказано. ssh задания overlay запускается с `-tt`. В отличие от agterm, AgShell не дописывает к PATH той машины каталог установки: установщик AgShell сам кладёт `agshellctl` в PATH пользователя, а Windows OpenSSH даёт сессии PATH пользователя (на macOS у sshd фиксированный PATH, поэтому agterm его дополняет); дописать PATH у нас можно было бы только синтаксисом конкретной оболочки, а она на той машине может быть и cmd, и PowerShell.
- `live tree --json` отдаёт `remote`: `host` (адрес, который спросили; только для `live tree HOST`), `endpoint.pipe` (префикс каналов демонов панелей), `presentation` (версия протокола статуса; нет у слишком старого AgShell — тогда строка подключается без зеркалирования, `presentation.state: unsupported`) и `sessions`: `id`, `name`, `windowName`/`windowID` и `workspaceName`/`workspaceID` (показывать имена, группировать по id — имена повторяются), `cwd`, `split`, `splitAxis`, `status` с `statusColor`/`statusShape` (нет у idle), `context` и `panes` (`pane`, `daemon` — имя на хосте, `foreground` — аргументы запущенной программы, если она есть). `live present` отказывает сессии, у которой не все панели держит хост (`session is not live-backed, so nothing can be attached to it`); кадр длиннее 256 КБ не отправляется и не принимается, а раскладка, которую не прочитать, отбрасывается без обрыва потока.
- В `live tree` попадают только сессии, у которых хост держит все панели (и сплит, если он есть). `live attach` ищет сессию на машине заново, только по id, поэтому ушедшая с момента списка сессия даёт ошибку `no attachable session ID on HOST`, а не свежий шелл под её именем. Как в agterm, до создания строки проверяются панели сессии: каждая названа один раз как `left` или `right`, среди них есть `left`, иначе `HOST reported panes agshell cannot address`; имя демона, к которому панель не может подключиться, даёт `HOST reported a session agshell cannot address`. Сплит у строки есть, если машина назвала панель `right`. Как в agterm, окно из `--window` (или переднее) выбирается уже после ответа машины; без открытого окна — `no open window`; `--window`, который не открыт, — `window not open — window.select it first`; окно без workspace — `no window to attach into`. Окно на передний план не выходит. Текстовый `live tree` печатает по строке на сессию: `окно/workspace/имя (split ось)  [id]  каталог  контекст  программы`; пустой ответ — `no attachable sessions on HOST`.
- Как в agterm, выбор идёт в пикере окна, том же, что открывает `pick`: при нескольких машинах в `remotes.conf` он сначала спрашивает, с какой (при одной не спрашивает), а когда машина ответила, предлагает её сессии; ищет только по имени. Если машина не ответила или на ней нечего подключать, пикер не открывается: причина показывается на панели над сессией. Иначе пикер показывает все сессии машины, в том числе уже подключённые; подзаголовок — окно/workspace, контекст, каталог и запущенные программы; больше 1000 сессий сообщается на панели. Выбранная сессия ищется на машине заново под панелью «подключаю …» (она открывается и поверх HUD и сама скрывается через 30 секунд); если панель негде показать, ошибка приходит уведомлением. Действие недоступно без workspace. `live attach` проверяет окно из `--window` сразу, а окно по умолчанию выбирает после ответа машины; без workspace отказывает. Сплит приходит со своим направлением и с фокусом.
- `remotes.conf` читается при запуске, при смене папки конфигурации и при каждом изменении файла, его папки (в том числе созданной позже) и файла, на который указывает ссылка (наблюдение ставится заново после каждого изменения, как в agterm); адрес — до первого пробельного символа любого вида. Ошибки приходят уведомлением один раз, когда файл во время работы из чистого становится с ошибками (уже испорченный при запуске или в новой папке конфигурации файл не сообщается). Действие «Подключиться к сессии на другой машине…» доступно, пока в файле есть машина. ssh ищется по PATH, как у agterm. Опрос машины и проба ждут ответа 10 секунд (`the remote did not answer in time`); ответ ssh с ненулевым кодом не читается как список: ошибка — то, что ответил agshellctl там, иначе то, что напечатал ssh, иначе `the remote command failed on HOST`; нечитаемый ответ — `the remote did not return a readable session list`. `live tree` обрезает пробелы у адреса, а пустой адрес — это сессии этой машины. Повтор подключения запускает любое изменение сети, пока она доступна (появление сети, смена адреса или подключения), но не её пропадание.
- `attach_remote` (Ctrl+Shift+R) открывает выбор машины (при одной машине шаг пропускается), затем список её сессий: AgShell выполняет `ssh -T -o BatchMode=yes машина agshellctl live tree --json`. Нужен вход по ключу, на той машине — OpenSSH Server, `agshellctl` в `PATH` и AgShell в режиме live. Пользователь может быть администратором: вход по ssh даёт ему повышенный токен, и `agshellctl` всё равно принимает каналы AgShell, запущенного без повышения, но только принадлежащие этому же пользователю.
- Выбранная сессия появляется в текущем рабочем пространстве строкой с пометкой `@машина`; её панели (и сплит, если он есть) подключаются каждая своим `ssh -T машина agshellctl live proxy PANE` к демону, которого для неё назвал `live tree`, как agterm запускает на каждую панель своё `ssh -tt машина zmx attach`. В отличие от agterm, у ssh нет терминала: Windows OpenSSH дал бы ему ConPTY, а она выносит escape-последовательности вперёд текста, сама отвечает на запросы или выбрасывает их (DECRQM, `OSC 11;?`) и переписывает другие, поэтому байты панели передаются как есть. Если демон панели там закончился (или его там уже нет), панель здесь закрывается; закрытие строки завершает её соединения. Ввод и вывод общие с той машиной.
- При обрыве связи панель сохраняет последний экран; режимы мыши, фокуса, вставки, темы и размера, оставленные программой, выключаются, чтобы их сообщения не печатались поверх, курсор скрывается. Если ssh сам не смог подключиться (код 255, в том числе отказ входа), в панели появляется строка «Связь потеряна · переподключение…», а внизу панели — строка «ssh: …» с тем, что ssh сказал при последней пробе. Каждая панель ждёт сама по себе, как в agterm: обрыв одной не трогает другую. AgShell, как agterm, сразу проверяет машину коротким `ssh машина exit 0` и подключает эту панель заново, только когда машина ответила; после неудачной проверки следующая — через 1, 2, 4, 8, 16, 30 секунд, после восьми неудач подряд задержка растёт дальше до 5 минут, без конца. Если связь рвётся снова в течение минуты после восстановления, задержка продолжает расти, а не начинается заново. Клавиша в ждущей панели проверяет сразу только для неё; пробуждение компьютера или смена сети — для всех ждущих панелей; и то и другое начинает расписание заново. При любом другом коде выхода в панели остаётся то, что ssh или та сторона напечатали последним, и строка с машиной, сессией, панелью и кодом; то же с кодом 127, если ssh вообще не запустился (как подключение agterm через его шелл); клавиша (в том числе непустой ввод `session type`) закрывает свою панель, как приглашение «нажмите любую клавишу» в agterm (основная — уступая место сплиту); с последней панелью закрывается строка. Ввод в локальный сплит или overlay удалённой строки при этом не задерживается: ждут только панели той машины. Закрытая с возможностью отмены строка продолжает ждать машину; ответ проверки в это время считается неудачей, и расписание растёт дальше, как в agterm. Повтор запускает и включение экрана (как пробуждение дисплеев у agterm).
- Хост виден в заголовке (значок облака и адрес; скрывается переключателем «Удалённый хост» в настройках интерфейса), в переключателе Ctrl+Tab и в списках недавних и ждущих внимания сессий. В сайдбаре, как в agterm, у строки только значок облака, без адреса.
- Сплит, пришедший с той машины, — её панель; сплит, открытый на строке потом (или после закрытия удалённого), — обычный локальный шелл. Две панели той машины можно поменять местами и здесь — это здешняя раскладка, имена шеллов там не меняются, а статус, HUD, вопросы и overlay той машины после этого попадают на свою панель; панель той машины и локальную тоже можно поменять местами, и панель той машины остаётся её парой. Если там закончилась единственная панель, а на строке открыт локальный сплит, он становится основной панелью; строка, как в agterm, остаётся удалённой (пометка, значок, не сохраняется): поток статуса идёт дальше, пока строка видна, а панелей, ждущих переподключения, у неё больше нет. Если локальный сплит ещё не запущен, основная панель не закрывается, чтобы его не потерять. У удалённой строки свой значок (облако, с чертой — если сплит с той машины).
- Когда той машины больше нет панели (сессию закрыли там), её копия здесь закрывается без нажатия клавиши: сплит закрывается; если там закончилась основная панель, а сплит жив, сплит здесь, как и там, становится единственной панелью; строка закрывается с последней удалённой панелью, если на ней нет локального сплита. Какая панель ушла, строка узнаёт, как в agterm, по id панелей, которые та машина присылает в кадре раскладки: если там закрыли сплит, а здесь панели поменяны местами, уходит здешняя основная панель (она показывала тот сплит), и её место занимает другая. От AgShell старше этой версии id не приходят, и тогда закрытие ждёт 1,5 секунды сообщения о выходе самой панели. Если строку закрыли с возможностью отмены и за это время панель там закончилась, отмена возвращает строку уже без неё. Переданный сюда overlay открывается и поверх HUD строки (HUD закрывается), как в agterm. Одну сессию можно подключить и в две строки: каждая следующая строка получает своё соединение.
- Пока поток статуса не поднят, облако строки перечёркнуто, а подсказка на нём говорит, почему — как в agterm, чем закончился мост (`exit N`, сказанное ssh уходит в журнал), нечитаемый кадр или 30 секунд тишины; уведомлений об этом нет, как в agterm. Как мост agterm, строка больше 256 КБ прекращает чтение, окна ждут не больше 64 кадров, а мост, переставший принимать ввод, завершается. Сразу после нажатия клавиши под покрышкой и при повторном подключении закрытой панели покрышка показывает «Забираю…», пока не придёт ответ о ведении; пока панель не ведёт никто — «Переподключаю…». Для машины со слишком старым AgShell (`unsupported`) пометки нет: здесь с этим ничего не сделать.
- Присланный контекст, не прошедший здешнюю проверку (одна строка до 256 байт), не показывается; HUD, чьё время истекло в пути, тоже, а уже показанный убирается, как в agterm. Звук, которого здесь нет, заменяется системным сигналом.
- Статус, поставленный там панелью, у которой здесь нет пары (scratch той машины или сплит, закрытый на строке), принадлежит строке целиком: нажатия здесь его не снимают.
- Удалённые строки не сохраняются в состоянии (ни сами, ни их место в порядке недавних, ни выбор закрытого workspace) и не попадают в недавно закрытые: сессию хранит та машина. Рядом с `session.created` и `session.closed` такой строки приходят события `remote.opened` и `remote.closed` с адресом машины в `host`. `remote.opened` приходит сразу за `session.created`. Как в agterm, `session.closed` (и `remote.closed`) приходит, когда строка уходит из дерева, то есть сразу при закрытии с возможностью отмены, а отмена присылает `session.created` (и `remote.opened`). Пока закрытая строка ждёт окончательного закрытия, её поток статуса остановлен: роль presenter освобождена, переданные ей вопросы возвращены, отмена запускает поток заново.
- `agshellctl live tree HOST` и `live attach HOST ID` отказывают адресу, который пуст, содержит пробелы или управляющие символы или начинается с `-` (ssh принял бы его за опцию). `session restart` на удалённой строке отказывает целиком, как в agterm, включая локальный сплит.
- В `tree --json` у удалённой строки есть `remoteHost` и `presentation`: `state` (`connecting`, `connected`, `failed` с причиной в `error`, `unsupported` для машины со слишком старым AgShell) и `mode` (`presenter` или `mirror`); `connected` говорит только о потоке статуса, не о панелях. У сессии, которую читают другие машины, есть `presenters`: `mirrors` (сколько машин только зеркалируют) и `presenter: true`, если одна её представляет. У панели удалённой строки, которая ждёт переподключения, есть `reconnect`: `failures` (неудач подряд) и `reason` (что ssh сказал при последней попытке).
- Дубликат удалённой строки и новая сессия «в каталоге текущей» — обычный шелл этой машины (профиль по умолчанию) в каталоге фокусной панели, если он есть здесь, иначе в домашней папке. Linux-путь той машины для WSL здесь не используется. Если при выходе выбрана удалённая строка, сохраняется выбор последней сессии этой машины; число сессий у недавно закрытого workspace не считает удалённые строки. Сочетание `attach_remote` по умолчанию не занимается, если keymap.conf уже отдаёт его другому действию или команде (как в agterm для конфигов, написанных до этого действия).
- Каталог удалённой строки — каталог той машины. Локальные запуски (scratch, overlay без `--cwd`, сплит, свои команды, quick terminal) стартуют в нём, если такой каталог есть и здесь, иначе в домашней папке.
- Контекст, заданный на удалённой строке здесь, главнее присланного; после его очистки снова виден присланный.
- Если `ssh -G` с теми же опциями подключения говорит `serveraliveinterval 0` (в конфиге не задано), AgShell добавляет `ServerAliveInterval=5` и `ServerAliveCountMax=2`, чтобы оборванная связь замечалась примерно за 15 секунд. Своё значение в конфиге отключает это; если `ssh -G` не ответил, опции не добавляются. Как в agterm, `ssh -G` спрашивается при каждом подключении, так что правка конфига ssh действует без перезапуска.
- Статус агента, контекст, HUD и уведомления `agshellctl notify` той сессии видны на строке. Для этого на каждую строку запускается отдельный `ssh машина agshellctl live present ID`: сначала он присылает снимок, потом изменения, раз в 10 секунд — ping. Уведомления OSC 9/777 не пересылаются: они приходят байтами в саму панель и срабатывают здесь сами. Если поток оборвался или молчит 30 секунд, всё, что он поставил на строку, снимается, а поток перезапускается с той же задержкой, что и панели. Снимок после переподключения не сбрасывает статус, поставленный на этой машине. Как в agterm, AgShell на той машине сам отправляет каждое изменение, как только сессия меняется: `live present` держит с ним соединение и только пересылает данные, а с закрытием соединения роль presenter снимается сразу.
- **Ведущий** (как lead в agterm): у каждой панели один ведущий, его размер видит программа. Подключение забирает ведение всех панелей сессии, и те же панели на машине, где сессия работает, закрываются покрышкой «Используется с другой машины» (на подключившейся машине закрытая панель пишет «Используется на машине, где запущена») со значком и подсказкой «Нажмите любую клавишу, чтобы работать здесь». Клавиша, нажатая в панели под покрышкой (сама она не печатается), или `session lead` забирает ведение и закрывает панель на другой стороне. Как в agterm, захват — новое подключение: панель отпускает демона, шелл продолжает работать, и подключается к нему заново новым терминалом, разложенным из снимка демона под размер этого окна; до ответа демона на ней «Забираю…», а панель, которая уже подключается, повторно не забирается; щелчок по покрышке только переводит фокус в панель. Клавиша захвата «защёлкивается»: её автоповтор не уходит в программу, пока её не отпустят; так же с клавишей, повторяющей подключение. Закрытая панель держит размер ведущего, поэтому её экран и то, что читают с неё скрипты, совпадают с тем, что рисует программа. Покрышка есть и на плитках дашборда. Как `covered` у agterm, панель закрыта, пока её ведёт другая сторона, пока её не ведёт никто и пока она подключается заново и ещё не получила ответ о ведении. Ответы терминала на запросы программы и сообщения о фокусе ведение не забирают и, пока панель закрыта, отбрасываются. На машине, где сессия работает, `session type`, `session text` и `surface cursor` работают и с закрытой панелью: они идут через саму сессию, а текст и курсор берутся из терминала её демона, разложенного под размер ведущего; `session paste`, `copy`, `select-all` и `search` (кроме `--close`) действуют на сам терминал и отказывают: `pane is covered while another machine leads it; take the lead first (session lead)`. На подключившейся машине закрытая панель отказывает и им (`pane is in use on the machine it runs on; take the lead to drive it from here`), пока не станет ведущей. Когда ведущий уходит, не ведёт никто: оставшиеся панели показывают «Переподключаю…» и подключаются заново без заявки, как в agterm, и ведёт первая вернувшаяся. Панель, вернувшаяся после обрыва, ведение не забирает: если другая сторона уже ведёт, она приходит закрытой покрышкой; если не ведёт никто, она становится ведущей, как в agterm подключение «без заявки» ведёт, пока никто не забрал ведение. Своя панель окна, открываясь на своём демоне (при запуске или когда окно возвращается), тоже подключается без заявки, поэтому панель, которую ведёт другая машина, приходит закрытой. Повторное подключение никогда не запускает шелл: если демона уже нет, панель заканчивается строкой `agshell: session is gone`.
- Уже подключённые панели удалённой строки повторяют сплит той машины: направление, скрытие и показ, обмен панелей местами (демоны сохраняют имена, layout сообщает, где теперь каждый, и строка меняет свои терминалы местами вместе с прокруткой, без переподключения). Новую панель строка не открывает: сплит, открытый там после подключения, требует подключить строку заново. Сплит, закрытый там, закрывается и здесь. Свои панели, соотношение и фокус остаются локальными.
- **Presenter** (как в agterm): одна из подключившихся строк представляет сессию — первая, чей поток `live present` попросил эту роль, пока она свободна. Как в agterm, поток начинается с hello в обе стороны: эта машина называет виды кадров, которые понимает (вопросы с полями и списками, страницы), и просит режим presenter, машина сессии отвечает тем, что понимают обе, и поток один раз просит роль (`presenter.acquire`, ответ granted или refused); остальные зеркалируют и просят снова только при своём переподключении. Закрытый поток отдаёт роль сразу, как и тот, что 30 секунд не отвечает на ping, который приходит раз в 10 секунд. Вопрос с полем ввода, списком или кнопкой отмены уходит только на presenter, понимающий формы, а со строкой «другое» — только на понимающий и её. Как в agterm, поток, который за 10 секунд не прислал hello, закрывается, как и тот, чей первый кадр не hello, в чьём hello нет версии 1 или выше, или который прислал нечитаемый кадр. Кадры как у agterm: по строке JSON, с `kind`, `gen` (поколение потока на машине сессии) и `rev` (счёт его кадров) и телом под ключом своего вида; зритель ничего не берёт до ответа на свой hello и отбрасывает кадры другого поколения или не по порядку. Панели передаются стабильным id (`AGSHELL_PANE_ID`), а не как left или right, поэтому перестановка на любой машине не путает адресата статуса, HUD, вопроса, overlay или страницы; раскладка называет панели, ту, что на основном месте, и ось, а несогласованная раскладка пишется в журнал и пропускается, остальной кадр применяется. AgShell до этой версии не покажет статусы этой машины, и наоборот: обновлять обе машины. Новый вопрос `agshellctl ask` в этой сессии уходит на presenter (туда, где сидит пользователь), если здесь все нужные панели — follower: панель вопроса или все панели для вопроса на всю сессию. Иначе вопрос остаётся здесь; уже открытый вопрос при смене ведущего не переезжает. Как в agterm, пока у сессии есть presenter, вопрос для `--pane right` сессии без сплита отвечает `session has no split`, даже если остался бы здесь. На presenter вопрос рисуется на удалённой строке, ответ возвращается вызывающей программе как обычно. Если presenter не может его показать (слот занят, GUI-вопрос для невыбранной сессии), вопрос отменён там или поток пропал, вопрос возвращается сюда и ждёт как обычный. Ответ presenter проверяется по форме вопроса, как в agterm: известная кнопка, текст поля в пределе 64 КБ и без запрещённых управляющих символов, выбор из списка в его порядке (ровно один для одиночного), текст строки «другое» только при ней; ответ, который форма не могла дать, отвергается, и вопрос ждёт дальше. Переданный вопрос ждёт здесь в слоте своей сессии, а не окна, даже GUI-вопрос, и сессия для передачи не обязана быть выбрана: здесь он не рисуется. GUI-вопросу, вернувшемуся сюда, нужен слот окна и выбранная сессия; если их нет, он завершается `cancelled` с `reason: presentation-lost`. GUI-копия вопроса на presenter тоже ждёт в слоте сессии и отказывается, если сессия не на экране (не выбрана, свёрнута в zoom другой панели или закрыта дашбордом). Вопрос, который вместе с самым большим допустимым ответом не помещается в кадр 256 КБ, остаётся здесь. `--follow` у переданного вопроса здесь окно не поднимает. HUD для правой панели, которую строка не показывает (сплит скрыт или открыт здесь), закрывает всю сессию; вопрос или overlay для неё presenter не принимает.
- Overlay с программой (`session overlay open КОМАНДА`) по тому же правилу отдаётся presenter. Здесь панель не открывается, а `session overlay result` ждёт результата. Presenter открывает у себя overlay с `ssh -tt машина agshellctl session overlay run-job ЗАДАНИЕ`, и программа один раз запускается здесь, в терминале этого ssh, в каталоге и окружении сессии. Код выхода приходит в `session overlay result`; задание, закончившееся без кода, — ошибка `overlay ended: launch-failed` (или `canceled`, `unknown`), её же печатает `overlay open --block`. Если за 30 секунд задание никто не забрал или presenter не может показать overlay, результат — `launch-failed`; если соединение хелпера закрылось раньше, чем он сообщил, чем кончилась программа, — `unknown`. Как в agterm, хелпер забирает задание и держит одно соединение: по нему приложение присылает, что запустить, и при отмене — просьбу остановить, а хелпер сообщает о старте и завершении. Пока задание идёт, а при `--wait` — пока на presenter открыт экран с результатом, его слот здесь зарезервирован: другой overlay в него не откроется, а HUD — откроется (здесь сессию ничего не закрывает); передача overlay сама убирает HUD из слота. Если копию закрыли на presenter, пока программа работает, слот держится до отчёта хелпера. Если presenter ушёл, незабранное задание сразу становится `canceled`. Хранятся последние 32 завершённых задания. Слот следует за своей панелью при обмене панелей и при переносе сплита на место основной. `session overlay close` здесь отменяет задание (программа завершается, результат `canceled`) или убирает показанный результат; overlay на presenter закрывается. `session overlay resize` здесь меняет размер overlay на presenter; `--follow` выбирает сессию на presenter. `session overlay text` для overlay, который рисует presenter, отвечает `overlay is shown on another machine`, а открыть другой overlay в его слот — `overlay already open`. Если в слоте теперь HUD, `session overlay result` отвечает `no overlay result: the slot holds a hud`. Ссылка, которую из-за presenter или занятого слота не открыть поверх сессии, открывается в браузере. Передать overlay в слот, где открыт здешний overlay, нельзя (`overlay already open`); Если поток пропал, запущенная копия на presenter закрывается вместе со своим ssh, даже с `--wait`. В `tree` у сессии видны слоты, занятые для presenter (`remoteOverlays`), а у вопроса — `remote` (передан presenter) или `replica` (передан сюда). Задание завершается и тогда, когда здесь закрывают его сессию (в том числе с возможностью отмены: отмена слот не возвращает), правую панель, в которой оно было, или основную панель, место которой занял сплит: слот освобождается сразу, результат — `canceled`. Перезапуск шелла панели отменяет задание её слота, но слот держится до отчёта хелпера, и результат — то, чем программа закончилась. `open`, `close` и `result` с `--pane right` работают и при скрытом сплите. На странице в слоте `result` отвечает `no overlay result: the slot holds an html page`. Текст HUD ограничен, как в agterm: 256 символов (с `--markdown` — 4096), подпись — 256. Хелпер запускает программу с тем каталогом, окружением и командой, что были при открытии overlay; если каталога нет или программа не стартовала, результат `launch-failed`, а хелпер выходит с кодом 127. Потеря связи с приложением программу не останавливает: хелпер её дожидается. Потеря терминала (закрыли ssh) отменяет задание. Отмена — как SIGTERM и через 3 секунды SIGKILL у agterm: консоль хелпера получает Ctrl+C (сам хелпер его пропускает), а то, что от программы и запущенных ею процессов работает и через 3 секунды, завершается; результат `canceled` приходит, только когда их не осталось. `session overlay resize` отказывает, если поток, которому отдано задание, ушёл. Если overlay закрыли на presenter, сюда сразу приходит об этом: незабранное задание, как в agterm, ждёт своего срока и становится `launch-failed`, запущенное держит слот до отчёта хелпера, показанный результат освобождает слот. При закрытии сессии здесь (в том числе с возможностью отмены) роль presenter снимается сразу.
- **Веб-страница** (`--url`), как в agterm, по тому же правилу открывается на presenter, если он сам её показывает (AgShell этой версии и новее): там она грузится со своей сетью и своим хранилищем (`--persistent` — профиль той машины). Здесь слот занят, `overlay open` возвращает id страницы, а `overlay result --page ID` ждёт исхода; на presenter у страницы в `htmlOverlays` стоит `replica: true`, здесь — `remote: true` с состоянием, адресом и заголовком, как их сообщил presenter, а в `remoteOverlays` — `pageID`. Адрес loopback (127.0.0.1, ::1, localhost) указывает на эту машину и не передаётся (`a loopback url names this machine, so the machine presenting the session cannot load it`); `--width`/`--height` для неё не поддерживаются. Отсюда до presenter доходят `close`, `resize --size-percent`/`--full`, `reload [--current]`, `navigate back|forward|browser` и `hide|show|toggle` (ответ не ждёт той машины); `navigate finder` и адрес в `navigate` отвечают `page is shown on another machine` (`navigate finder` у веб-страницы — `show in Finder requires a file page`, как в agterm), а `submit` отвечает за страницу здесь и закрывает её там. Закрытие страницы на presenter, его отказ её показать или уход presenter закрывают её здесь без ответа (`dismissed`). Если эта машина сама ведёт панели, страница, как и программа, открывается здесь. Старый presenter, который страницы не показывает, получает прежний отказ (`a viewer presents this session: an html overlay would open where nobody sees it`).
- **Страница из файла** (`--html`) уходит на presenter по тому же правилу. Её файлы presenter читает отсюда через канал страницы, `ssh машина agshellctl session overlay page-serve ТОКЕН`: сам файл, а с `--cwd` — файлы внутри этой папки; ссылки и junction раскрываются до проверки, так что ведущая наружу отклоняется (`file is outside the page's folder`). Как в agterm, канал держит и файлы читает сам AgShell здесь, а `page-serve` только пересылает данные; файл идёт кусками по 64 КБ вместе с типом, одновременно в работе не больше 8 запросов (остальные ждут на presenter), а загрузка, брошенная страницей, здесь отменяется. На presenter страница грузится со своего адреса под `localhost` (`http://r<секрет>.localhost:<порт>/`), который AgShell обслуживает на loopback: перехваченный ответ WebView2 отдаёт странице только целиком и о брошенной загрузке не сообщает, поэтому страница обслуживается через сокет, и каждый кусок доходит до неё сразу. Отдаётся только по секретному имени этой страницы и только пока она открыта. Как в agterm, токен одноразовый: presenter поднимает канал при открытии страницы, и страница, чей канал не занят за 30 секунд, закрывается без ответа; дальше канал отдаёт файлы, только пока страница открыта и presenter тот же, которому её передали, а с концом канала страница закрывается на обеих сторонах. В `htmlOverlays` здесь у неё `file` и `cwd`; на presenter — только `file`, как в agterm, а файл, который канал не принёс, показывается ошибкой загрузки с причиной, что дала та машина. Как в agterm, `htmlOverlays` перечисляет страницы по слотам (сессии, левой панели, правой), на какой бы машине они ни показывались; presenter, отказавшись показать страницу, сообщает причину машине сессии, и та пишет её в журнал. На presenter у её полоски нет кнопок «Открыть в браузере» и «Показать в проводнике», как в agterm, а `navigate browser` здесь отвечает `page is shown on another machine`. Мост (кнопки `data-agshell`, `agshell.request`) работает так же, как у страницы здесь: как в agterm, её запросы идут обратно по тому же каналу и выполняются здесь, сессия и панель страницы подставляются, если страница их не указала, а ответ доходит до страницы как есть; `session.overlay.submit` со страницы отвечает за неё здесь и закрывает её там. Запросы, которые держат поток или обслуживают помощника (`session.overlay.job.run`, `session.overlay.page.serve`, `live.present`, `live.presentation`, `live.answer`), и `live.reset`, чья работа идёт после ответа, как в agterm, отклоняются с любой страницы (`... cannot be sent from a page`).
- Звук без имени на presenter — его собственный звук blocked, а если его нет или такого звука нет на этой машине — системный сигнал.
- Звук blocked из настроек играет только при переходе в blocked, повторный blocked беззвучен; `--sound ИМЯ` звучит при каждой записи; `--sound ""`, как в agterm, считается отсутствием имени, и при переходе в blocked играет звук из настроек. Как в agterm, тот же звук повторно в пределах 200 мс не играет (пачка записей не заикается); другой звук играет всегда, прослушивание в настройках не сдерживается. Как в agterm, ИМЯ — `default` или `beep` (системный сигнал) либо звук из `C:\Windows\Media`; неизвестное отклоняется (`unknown sound: …` со списком), а статус не меняется.
- Звук статуса (`--sound` или звук blocked из настроек) играет на presenter, а не здесь, если панель, поставившую статус, ведёт другая машина и hello presenter назвал звуки (как в agterm; иначе играет здесь). Звук blocked при этом берётся из настроек presenter.

## Отмена закрытия и недавно закрытые

```
agshellctl recent list                 # недавно закрытые сессии и workspace, новые сверху, с id
agshellctl recent open [ID]            # открыть заново (по умолчанию последнее); id или уникальный префикс
agshellctl recent clear
```

Как в agterm:
- **Отмена закрытия.** Сессия или workspace, закрытые из окна (Ctrl+Shift+W, меню, палитра), сразу пропадают из дерева, но их шеллы живут ещё 3 секунды. Внизу видна строка «Отменить». Ctrl+Shift+Z (`undo_close`) возвращает их на прежнее место живыми, вместе с выводом. Событие `session.closed` уходит сразу, а отмена снова шлёт `session.created`. По истечении 3 секунд закрытие становится окончательным. Отмена выбирает сессию, которая была выбрана до закрытия; место сессий в порядке Ctrl+Tab сохраняется, пока закрытие не окончательное. Отмену можно выключить в настройках («Общие»). `session close` и `workspace delete` из agshellctl закрывают сразу.
- **Недавно закрытые.** Каждое закрытие сразу запоминается в `%APPDATA%\agshell\recent-closed.json`, как в agterm (отмена убирает запись обратно): последние 20 записей, по одной на сессию или workspace. Пока видна полоса отмены, файл состояния ещё хранит закрытое, поэтому сбой в эти секунды ничего не теряет. Ctrl+Alt+Shift+T (`reopen_recent`, как Reopen Last Closed Item у agterm) сразу возвращает последнюю запись; весь список — в меню «Файл ▸ Недавно закрытые», как File ▸ Open Recent у agterm: сначала сессии, затем workspace, у workspace — число сессий. Запись восстанавливается со свежими шеллами: каталог, имя и сплит; сессия — на своё место в дереве, workspace, как в agterm, — в конец. Сессия, которую ещё можно вернуть отменой, возвращается живой, а уже открытая только выбирается. Workspace сначала забирает свои сессии, которые ещё можно вернуть отменой; если он открыт, в него добавляются только недостающие сессии. Если все сессии закрытого workspace уже открыты, вместо него выбирается одна из них. Список заканчивается пунктом «Очистить меню», как Clear Menu у agterm (`recent clear`). Ctrl+Shift+Z (`undo_close`) работает, только пока видна полоса отмены; иначе, как в agterm, клавиша уходит в терминал, а в поле ввода интерфейса остаётся его собственной отменой.
- **Окна.** Список один на всё приложение, в него пишут все окна. `recent open` возвращает запись в окно из `--window`, оно должно быть открыто (иначе `window not open — window.select it first`), иначе в переднее; как в agterm, окно проверяется раньше записи. `recent list` и `recent clear` — на всё приложение: цель или `--window`, присланные по каналу, отклоняются с `<cmd> takes no target or --window`. Префикс id, подходящий к нескольким записям, отклоняется, как у любой цели: `ambiguous recent item prefix '…' → …`. Как в agterm, сначала выбирается окно, где есть сама сессия (открытая или ещё в окне отмены), затем окно с её workspace; окно при этом не поднимается. Сессии, которые есть в другом окне, под тем же id не пересоздаются. Если какая-то сессия записи никуда не попала, запись остаётся в списке; `complete` в ответе говорит, ушла ли она из списка. Если ничего не вернулось — ошибка `could not reopen <id>`. Если список не удалось записать, `recent clear` отвечает `could not clear recent items`, а список остаётся таким, как в файле. Из палитры и по Ctrl+Alt+Shift+T — в своё окно по тому же правилу, а если запись ушла в другое окно, оно выходит вперёд. Отмена закрытия в течение 3 секунд у каждого окна своя.

## Темы и настройки

- **Заголовок окна (первый срез 5.8).** Общая нативная рамка показывает read-only имена workspace/сессии/пользовательского окна: workspace выбранной сессии и detail её main/split по фокусу. Normal показывает контекст вместо detail; compact — контекст после identity/host. Действуют прежние переключатели «Интерфейса» и режим toolbar, без изменения defaults. Hidden оставляет штатную верхнюю рамку плюс drag-полосу 3 DIP в обычном окне (всего 7 px при 96 DPI), 3 DIP в maximized. Normal/compact сохраняют системные кнопки окна. Прежние действия toolbar/popovers остаются на странице под меню; команды и сочетания доступны прежними путями. Fullscreen сохраняет product menu reveal.

```
agshellctl theme list                              # «default ghostty» и установленные темы, действующая отмечена *
agshellctl theme set "Gruvbox Dark"                # тема; тёмная, если задана, сохраняется
agshellctl theme set --dark "Dracula"              # тёмная тема: терминал переключается вместе с режимом Windows (без темы светлой станет Builtin Light)
agshellctl theme set --dark none                   # перестать следовать режиму Windows
agshellctl theme set                               # без темы: цвета Ghostty («default ghostty»), тёмная тоже сбрасывается
```

- **Темы** в формате Ghostty, как у agterm. Встроены около 800 тем из [iTerm2-Color-Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes) и своя тема `agshell`, с которой AgShell начинает на новой установке. Как в agterm, можно остаться и без темы: «default ghostty» — свои цвета терминала (Ghostty); её нет в выборе, пока терминал следует режиму Windows, потому что паре нужны две темы. Если в `settings.json` тема не записана, это и есть «default ghostty». Свои темы кладутся файлами в папку `themes` папки конфигурации (`%APPDATA%\agshell\config\themes`); тема с тем же именем заменяет встроенную. Если тема не загружается (файла нет, путь относительный), терминал остаётся в цветах Ghostty, как у самого Ghostty, а в проблемах ghostty.conf появляется сообщение его словами: `theme "X" not found, tried path "…"`. Как в agterm, список отсортирован по алфавиту без учёта регистра, а `theme set` принимает имя точно так, как его печатает `theme list`: `dracula` — не `Dracula`; пробелы и табы по краям отбрасываются, переводы строк — нет.
- **`theme.list` и `theme.set` по каналу**, как у agterm: `theme.list` возвращает `themes` (имена, без «default ghostty»), `theme` (единственная тема; нет поля — «default ghostty»), `sync` и, пока терминал следует режиму Windows, `light` и `dark` — тогда `theme` нет, состояние в этих трёх полях. `theme.set` принимает `name` (или `light`, его синоним) и `dark` (`none` — перестать следовать) и всегда отвечает полным состоянием, без `themes`. Неизвестное имя — `unknown theme: ИМЯ`; имя вместе с `--light` — `theme.set takes either a name or --light, not both`. По каналу это сразу запись: превью, как в палитре, нет.
- **Цвета окна** берутся из темы: фон боковой панели — это фон терминала, затемнённый или осветлённый настройкой, выделенная строка — цвет выделения темы. Светлая или тёмная схема окна и строки заголовка определяется по яркости фона; шеврон workspace, как треугольник AppKit в agterm, системного серого цвета, светлый или тёмный по яркости боковой панели с учётом её подкраски. Как в agterm, цветом акцента Windows («Параметры → Персонализация → Цвета»), а не темы, окрашены выбранная строка палитр и переключателя сессий, выделенная кнопка, строка под курсором и отмеченные маркеры в ask вида gui, переключатели и ползунки настроек, место вставки при перетаскивании в боковой панели и кольцо фокуса клавиатуры, и цвет меняется вместе с акцентом; кнопки-переключатели показывают состояние только залитым значком, выделенная ячейка дашборда обведена цветом текста темы; значки в строке заголовка и внизу боковой панели тоже цвета текста темы; выделенная деструктивная кнопка ask вида gui — системного красного цвета с белым текстом, как в agterm; в ask вида terminal поле в тонкой рамке без фона, а строка под курсором инвертирована (под маркером и подписью цвет текста, на них — цвет фона); у недоступного пункта палитры заголовок цвета неактивного текста Windows 11.
- **«Выбрать тему…»** в палитре действий (`select_theme`) открывается на текущей теме и показывает тему при перемещении по списку (как в agterm, через 70 мс после последнего шага, чтобы зажатая стрелка не перекрашивала терминал на каждой теме). В списке есть строка «default ghostty» (по алфавиту, как в agterm), текущая тема помечена `current`. Enter сохраняет её, Esc возвращает прежнюю. Если терминал следует режиму Windows, меняется тема того режима, который включён сейчас.
- **Окно настроек** открывается из меню «AgShell ▸ Настройки…» или по Ctrl+,: как у agterm, одно окно на приложение, 540×680, каждый раз на вкладке «Общие»; Ctrl+W его закрывает. Вкладки: Сочетания меню работают и при фокусе в Настройках: «Свернуть» сворачивает Настройки, «Выйти» завершает приложение, а действия keymap с аккордом меню относятся к активному основному окну. Стандартный аккорд закрытия сессии закрывает Настройки; свои команды и leader/monitor bindings там не запускаются, как в agterm. После возврата фокуса состояние клавиш Windows сверяет ownership сочетаний: клавиша, отпущенная в другом приложении, больше не поглощает первый новый символ или сочетание; действительно удерживаемая сохраняет ownership между окнами AgShell.
  - **Общие:** язык интерфейса (как в Windows, русский или английский); «Мышь» — скорость прокрутки, вставка правой кнопкой, куда открывать ссылки (Ctrl+клик: браузер или поверх сессии), сворачивает ли клик строку workspace (как в agterm, через интервал двойного клика, так что двойной клик только переименовывает); «Сессии» — где открывается новая сессия (домашний каталог, каталог текущей сессии вместе с её шеллом, выбранный каталог), куда она добавляется, как сессии возвращаются (свежими шеллами, с программами, живыми; применяется после перезапуска), подтверждение закрытия, возврат закрытого, вид «Помеченных» и можно ли программам писать в буфер обмена.
  - **Оформление:** шрифт терминала и его размер (8–32), форма и мигание курсора (как в agterm, «по умолчанию» ничего не задаёт: решают DECSCUSR и DECSET 12 программы; явный выбор мигания держится против DECSET 12), тема текущего режима Windows и, пока тема следует за Windows, тема другого режима; дальше вид панели инструментов, непрозрачность фона 0–100%, размытие фона, оттенок боковой панели («Нет», «Светлее N», «Темнее N»), размеры шрифта боковой панели и палитр с переключателем, приглушение неактивной панели и фона. Ниже 100% непрозрачности сквозь окно видна системная подложка Windows 11 (Mica, с размытием — Acrylic); силу размытия, как у agterm, Windows не даёт, поэтому размытие — переключатель, выключенный при 100%. Без размытия окно agterm показывает то, что под ним; Windows без системной подложки рисует под страницей чёрное, поэтому вместо этого Mica — тон обоев. Как в agterm, строка заголовка — часть прозрачной поверхности, а окно в полноэкранном режиме непрозрачно, сохранённая прозрачность не меняется. Нужна Windows 11 22H2 или новее.
  - **Интерфейс:** какие элементы строки заголовка и кнопки боковой панели показывать (по два в ряд, как в agterm), прятать ли боковую панель в неактивных окнах и размер quick terminal: по умолчанию (90 %, но не больше 1100×700) или 40–90% экрана.
  - **Уведомления:** toast, счётчики на строках и, как значок Dock у agterm, их сумма по открытым окнам на кнопке панели задач (наложение, до 99; тот же переключатель скрывает и его, так как Windows не рисует число на значке неупакованного приложения), мигание кнопки на панели задач (по умолчанию не мигает, как Dock в agterm), звук toast-а (без звука — по умолчанию, как в agterm; стандартный, сообщение, почта, напоминание, SMS; выбранный звук сразу проигрывается) и колокольчик внимания в заголовке.
  - **Статусы агентов:**
    - цвет и форма каждого статуса в одной строке;
    - какая клавиша гасит `blocked` и `completed`: любая, только Enter (тогда `blocked` гасят и Esc с Ctrl+C) или никакая;
    - звук при `blocked` из `C:\Windows\Media` (выбранный сразу проигрывается);
    - автопереход, как в agterm. Когда пользователь столько-то секунд ничего не нажимал и не выбирал, окно переходит к сессии, которая дольше всех ждёт ответа (`blocked`). Если текущая сессия сама `blocked` (или `active` при выключенном флажке «уходить с работающей сессии»), окно остаётся на ней. С сессии, к которой уже переводило, а пользователь с неё ушёл, второй раз не тянет, пока она снова не станет `blocked`. Пока открыта палитра, список в заголовке, дашборд, pick или ask либо идёт переименование, автопереход ждёт; прыжок, наступивший в это время, пропадает до следующего нажатия или смены статусов.
  - **Клавиши:** раскладка клавиатуры, папка конфигурации (`configDirectory`, как в agterm; её путь виден всегда): «Выбрать…» переносит чтение `keymap.conf`, `hooks.conf`, `ghostty.conf` и `remotes.conf` в другую папку (например, в dotfiles) и сразу их перечитывает, в пустой папке появятся заготовки, «Вернуть по умолчанию» возвращает прежнюю; путь папки своих тем; дальше «Диагностика» (проблемы `keymap.conf`) и «Хуки» (проблемы `hooks.conf`), у каждого «Перечитать», которая перечитывает только этот файл. Как в agterm, файлы открываются из меню и палитры («Открыть keymap.conf», «Открыть hooks.conf»), а не отсюда.
  - Подписи — тексты agterm (Windows вместо macOS, панель задач вместо Dock), русский интерфейс их переводит. Выбор «в своём каталоге» для новых сессий ставится сразу, с «не задан», пока каталог не выбран. Выключение «Следовать теме системы» оставляет тему, что на экране (в тёмном режиме темой становится тёмная). Ползунок непрозрачности показывает значение, пока его тянут, а сохраняет через 0,3 с после остановки или при отпускании; при выключенных эффектах прозрачности Windows ползунки остаются доступны, а сохранённое применится, когда эффекты включат. Явная смена того, что настройки пишут в конфиг терминала (шрифт, размер, тема, следование Windows, форма и мигание курсора, переход непрозрачности через 100%, скорость прокрутки, вставка правым кликом), или папки конфигурации сбрасывает у всех сессий размер, заданный Ctrl+=/Ctrl+-, как в agterm.
- **Хранение:** настройки лежат в `%APPDATA%\agshell\settings.json` отдельно от дерева сессий. Как в agterm, в файл пишутся только изменённые поля, ключи по алфавиту; поле, возвращённое к значению по умолчанию, удаляется. Файл, который не прочитать, даёт временные значения по умолчанию, но запись блокируется до успешного чтения после перезапуска. Неразборчивый файл сохраняется в уникальный `settings.json.corrupt-<время>-<id>` до записи умолчаний; отказ backup также блокирует запись. Неудачная запись попадает в журнал и сопровождается уведомлением, если уведомления разрешены; следующее изменение повторяет запись. `restore mode`, `theme set`, `browser links` и `sidebar flagged-layout` при отказе сохранения возвращают ошибку и оставляют прежние значения. Значения берутся как записаны: размер шрифта терминала и скорость прокрутки как есть, размер quick terminal не из списка означает «по умолчанию». Имена, которые писал AgShell 0.1 (`activeStatusColor`, `notificationSound`, …), один раз читаются в имена agterm (`activeStatusColorHex`, `notificationSoundName`, …).
- **Лог:** как agterm пишет в системный журнал macOS, AgShell пишет в журнал событий Windows, поставщик AgShell, с категорией и уровнем agterm: error, warning и notice — в журнал `AgShell/Operational`, info и debug — в `AgShell/Debug`. Журнал Debug выключен, пока его не включит администратор (`wevtutil sl AgShell/Debug /e:true`), как macOS хранит info и debug только по запросу. Читать — в «Просмотре событий» ▸ «Журналы приложений и служб» ▸ AgShell (журнал Debug виден после «Вид» ▸ «Отобразить аналитический и отладочный журналы») или командой `Get-WinEvent -LogName AgShell/Operational` (для `AgShell/Debug` — с `-Oldest`); сообщение — `[категория] текст`, категория ещё и первое поле события. Хранит журналы Windows, по умолчанию по 1 МБ, затирая старые записи. Поставщика нужно один раз зарегистрировать, на это нужны права администратора: это делает установщик, а для копии без установщика — «Справка» ▸ «Зарегистрировать журнал событий…» (регистрируется папка, чей `AgShell.EventLog.dll` даёт тексты; после переноса папки — повторить). Регистрация даёт службе Windows Event Log право чтения только этой DLL, чтобы Windows могла расшифровать события установки на пользователя; остальные права файла и наследование сохраняются, права папок не меняются. Пока регистрации нет, error, warning и notice идут в журнал «Приложение» под источником AgShell, а info и debug пропадают. Снять регистрацию — `wevtutil um AgShell.man` рядом с `agshell.exe`; удаление установленной копии снимает её само. Живые демоны пишут лог, как zmx в agterm, все уровни начиная с debug: каждый демон — в `%TEMP%\agshell-ПОЛЬЗОВАТЕЛЬ[-ХЕШ]-live\logs\<его канал>.log`, а окно и `agshellctl live proxy`, которые к ним подключаются, — в `live.log` рядом, как `zmx.log`. Как у zmx, демон следит за рабочим каталогом шелла по последнему OSC 7 в терминале или OSC 9;9, которым каталог сообщает интеграция шеллов AgShell (`set cwd=… path=…`; путь пустой, если каталог на другой машине, например сообщён изнутри ssh); `live list` его не показывает, как и у agterm. Больше 2 МБ — такой файл начинается заново. zmx свои логи не удаляет, они лежат в `/tmp`; у нас каждый запуск окна удаляет записанные до последнего запуска Windows.

## Строка меню

Как у agterm, у окна есть строка меню: под заголовком Windows, в цветах темы. Меню открываются щелчком. Сами меню системные, тёмные или светлые вместе с темой, как меню macOS вместе с оформлением; открытое меню не забирает клавиатуру у поля, которое сейчас редактируется. Стрелки, Enter и Esc работают в открытом меню, влево и вправо переходят к соседнему меню, а наведение на другой заголовок открывает его. Alt и F10 меню не открывают: это клавиши терминала, а у меню agterm нет клавиш доступа. Пункт доступен тогда же, когда можно выполнить его действие из палитры или по клавишам, рядом показано его сочетание из keymap.conf (если оно из одного аккорда).

У «Настроек…», «Выйти из AgShell» и «Свернуть» сочетания постоянные, как у стандартных пунктов меню macOS у agterm: Ctrl+, (⌘,), Ctrl+Shift+Q (⌘Q) и Ctrl+Shift+M (⌘M; Ctrl+Q и Ctrl+M принадлежат терминалу). Как в agterm, Ctrl+Shift+Q и Ctrl+Shift+M уступают `map` из keymap.conf, занявшему тот же аккорд (подпись в меню тогда пропадает), а Ctrl+, — нет.

- **AgShell:** «О программе AgShell», «Настройки…» (Ctrl+,), «Сбросить живые сессии…» (только в режиме live), «Выйти из AgShell» (Ctrl+Shift+Q).
- **Файл:** окна («Новое окно», «Открыть окно» — список всех окон с галочкой у открытых, «Переименовать окно…», «Удалить окно»), workspace (создать, переименовать, удалить), сессии («Новая сессия», «Открыть каталог…», «Подключиться к сессии на другой машине…», «Недавно закрытые» — сессии и workspace под своими заголовками, со временем закрытия, и «Очистить меню», «Вернуть последнее закрытое», «Переименовать сессию», «Дублировать сессию», «Показать в проводнике», «Закрыть сессию», «Вернуть закрытое», «Сбросить статус»), открыть и перечитать keymap.conf, hooks.conf и ghostty.conf, «Закрыть окно».
- **Правка:** «Вырезать», «Копировать», «Вставить», «Удалить», «Выделить всё» — для поля, которое редактируется, иначе для терминала (в терминале вырезать и удалить нельзя); «Эмодзи и символы» открывает панель эмодзи Windows.
- **Вид:** размер шрифта и «Выбрать тему…»; боковая панель (скрыть или показать, развернуть и свернуть workspace, свернуть текущий); помеченные сессии; фокус workspace (фокус и его снятие, добавить в фокус, фильтр, снять фокус со всех); сплиты, обмен панелей, scratch, overlay, «Найти…», quick terminal, zoom терминала; «Полноэкранный режим» (F11).
- **Навигация:** палитры сессий, действий и своих команд, ждущие внимания, дашборд; предыдущая и следующая сессия, сессия, ждущая внимания, первая и последняя сессия, предыдущий и следующий workspace, предыдущее и следующее окно; фокус на левую (верхнюю) и правую (нижнюю) панель.
- **Окно:** «Свернуть» (Ctrl+Shift+M), «Развернуть» (развернуть или вернуть размер), «Все окна — на передний план» и список открытых окон, текущее с галочкой.
- **Справка:** «Документация для разработчиков…», установка agshellctl, хуков статуса агентов и скилла и «Зарегистрировать журнал событий…» (см. «Лог» выше).

В полноэкранном режиме строки меню нет, как в macOS: она появляется поверх окна, когда указатель доходит до верхнего края экрана, и прячется, когда он уходит.

## Горячие клавиши, свои команды и хуки событий

```
agshellctl keymap reload                      # перечитать только keymap.conf, напечатать число проблем
agshellctl keymap list                        # действующие сочетания, свои команды, global-hotkey, ошибки
agshellctl keymap run "Имя" [--target S]      # выполнить свою команду для сессии
agshellctl hooks reload | list                # то же для hooks.conf; list показывает счётчики запусков и сбоев
agshellctl config reload                      # перечитать ghostty.conf, напечатать число проблем
```

Оба файла лежат в папке конфигурации, как в agterm отдельно от состояния: `%APPDATA%\agshell\config` (при `AGSHELL_STATE_DIR` — его подпапка `config`; папка, выбранная в настройках, главнее). Файлы, которые прежняя версия держала в `%APPDATA%\agshell`, при запуске один раз переезжают туда; файл, который уже есть в папке конфигурации, остаётся. При первом запуске там появляются заготовки с примерами в комментариях. Сохранённый файл применяется сразу; если в нём есть ошибки, приходит уведомление. Из палитры действий файлы открываются командами «Открыть keymap.conf» и «Открыть hooks.conf»: в редакторе из `VISUAL`/`EDITOR` поверх сессии (пустая `VISUAL` уступает `EDITOR`, как в agterm), иначе в Блокноте. Как в agterm, при заданном редакторе без сессии или когда слот сессии занят программой или страницей ничего не открывается, а при скрытом — звучит сигнал.

**ghostty.conf** — как у agterm, конфиг Ghostty для AgShell рядом с `keymap.conf`: ключи в синтаксисе Ghostty для терминалов (`ключ = значение`, комментарии `#`, пустое значение сбрасывает ключ, более поздняя строка побеждает, `config-file = путь` подключает файл, `?путь` — файл, которого может не быть). Терминалы AgShell — xterm.js, поэтому действуют только эти ключи, а любой другой считается проблемой: `copy-on-select = true|false|clipboard` (true — выделенное мышью уходит в буфер выделения; clipboard — ещё и в буфер обмена), `clipboard-read = ask|allow|deny`, `clipboard-write = ask|allow|deny` (настройка «Программы могут записывать в буфер обмена», если её меняли, побеждает, как настройки agterm побеждают файл), `mouse-hide-while-typing`, `title` (постоянный заголовок вместо тех, что задают программы), `cursor-click-to-move` (Alt+клик двигает курсор; по умолчанию выключено, как в agterm), `desktop-notifications` (false отбрасывает уведомления, которые программы шлют через OSC 9 и 777), `window-padding-x` и `window-padding-y` (одно число или два через запятую; по умолчанию 8 и 6), `scrollback-limit` (байты, как у Ghostty; примерно 1000 байт на строку, по умолчанию 10 МБ), `theme` (как у Ghostty: имя темы, полный путь вроде `C:\themes\mine`, `~\` или `~/` — домашняя папка, или `light:ИМЯ,dark:ИМЯ`, переключаемые вместе с режимом Windows; действует, пока в настройках нет темы, то есть стоит «default ghostty», — как в agterm, где файл загружается раньше настроек). Стартовый файл — одни комментарии. При заданном `VISUAL`/`EDITOR` файл перечитывается при закрытии editor overlay, только если содержимое изменилось; сохранение при открытом редакторе не применяет его. С Блокнотом или внешними правками применяйте изменения через `config reload` или «Перечитать ghostty.conf» в палитре; о проблемах, как у agterm, приходит уведомление с их числом: «Проблем в конфиге ghostty: N — см. Просмотр событий, затем «Перечитать ghostty.conf»» (каждая проблема — в журнале событий, как у agterm в Console), `config reload` печатает их число.

Для остальных поддерживаемых скалярных ключей сначала читаются прямые строки, затем включения в ширину: включённое значение перекрывает прямое даже при более ранней директиве включения. Пустое `config-file =` очищает список ожидающих включений. Неверное значение диагностируется и оставляет последнее верное; пустое скалярное значение возвращает умолчание.

Для `font-family`, `font-size`, `cursor-style` и `background-opacity` порядок как в agterm: прямые строки ghostty.conf, затем настройки, затем включения `config-file` (в ширину). Незаданный размер или форма курсора наследует файл; явный выбор, даже умолчание 13 или block, перекрывает прямое скалярное значение и переживает перезапуск. Семейства шрифтов накапливаются как список подстановки: семейства файла идут перед выбранным в настройках; пустое `font-family =` очищает список. `cursor-style` принимает block, bar, underline и block_hollow. Если размера нигде нет, он равен 13. Вычисленные значения применяются без копирования в settings.json; перечитывание вычисляет их заново и сбрасывает зум сессий.

`background-opacity` — непрозрачность рендерера (0–1), отдельно от непрозрачности окна в настройках. Без настройки окна или при 100% окно под ним остаётся непрозрачным, а файл управляет рендерером. Настройка окна ниже 100% делает рендерер прозрачным, оттенок рисует окно; включённый файл может перекрыть и это значение рендерера. Как в agterm, ползунок окна на 100% очищает сохранённую настройку; вручную сохранённая в JSON единица сохраняется при записи. Существующие явные настройки остаются; миграция настроек для этих ключей не требуется.

**keymap.conf**, формат agterm:

```
map ctrl+shift+l  toggle_split                       # переназначить действие
map ctrl+a>ctrl+n --repeat  next_session             # лидер-последовательность; --repeat: повтор последнего сочетания в течение 0,5 с
command "Open in VS Code"  ctrl+alt+o  code "{AGSHELL_SESSION_PWD}"
command "Build"  ctrl+a>b --error-hud [--error-position top-right] [--error-pane left|right]  build.cmd
global-hotkey ctrl+alt+space                         # системное сочетание: показывает и прячет quick terminal
```

- **Сочетания** пишутся как `ctrl` (`control`), `alt` (`opt`, `option`), `shift`, `super` (`win`, `cmd`, `command`, клавиша Windows) и клавиша через `+`; модификаторы могут стоять и после клавиши. Клавиши: буквы, цифры, `` `-=[]\;',./ ``, `tab`, `space`, `enter`, `backspace`, `delete`, `home`, `end`, `page_up`, `page_down`, стрелки `left right up down`, `f1`–`f20`, `kp_0`, `kp_add`, `kp_subtract`. Клавиша считается по физическому положению, так что раскладка не важна. Альтернативы перечисляются через `|`, шаги последовательности через `>`. Как в agterm, `map СОЧЕТАНИЕ [--repeat] ДЕЙСТВИЕ`: первая альтернатива из одного сочетания может быть без модификатора (кроме голой стрелки), остальным нужен модификатор на первой клавише, и каждая, нарушившая правило, отбрасывается отдельно с пометкой в `keymap list`. В строке `command` первое слово, которое читается как сочетания, но без модификатора, оставляет команду только в палитрах, а само слово остаётся частью строки оболочки. `#` после пробела вне кавычек начинает комментарий.
- **Конфликты** разрешаются как в agterm. Сначала определяется одна клавиша меню каждого действия; неизменённая стандартная клавиша побеждает переназначение, два переназначения на одну клавишу теряют оба и возвращаются к стандартным. Остальные альтернативы проходят общую проверку с командами: клавиша меню затеняет начало последовательности; конфликты между разными целями удаляют обе стороны за один проход независимо от порядка строк. Внутри одной цели остаётся короткий prefix. Если действие потеряло все альтернативы, его стандартная клавиша возвращается, пока её никто не занял. Для одного действия последняя строка `map` главнее. Явное прежнее использование новых стандартных сочетаний horizontal split, dashboard, attach remote и overlay сохраняется, если новое действие не переназначено явно.
- **Диагностика:** `keymap list --json` разделяет `actions[].chord` (одна клавиша меню) и `alternates` (остальные сочетания/последовательности); `overridden` сравнивает только клавишу меню со стандартной. `menu` показывает уже применённые пункты с `menu`, `title`, `chord`, `selector` (идентификатор диспетчеризации AgShell) и `enabled: false` у недоступного пункта. После перечитывания меню может обновиться чуть позже модели. Обычный вывод также показывает `menu:` и `(disabled)`. `keymap list/reload` действуют на приложение и игнорируют target/window в протоколе.
- **Последовательности и повтор:** leader ждёт следующую клавишу 1,5 с. `--repeat` сохраняет prefix, пока последняя клавиша удерживается, и ещё 0,5 с после её отпускания: можно нажимать последнюю клавишу любой repeat-команды с тем же prefix. Обычные custom/monitor-команды не запускаются повторно от удержания. Esc отменяет незавершённый leader и поглощается; после repeat он закрывает окно повтора и проходит терминалу. Поле ввода сбрасывает leader/repeat и сохраняет свои клавиши; custom из него не запускается. Перечитывание сбрасывает автомат, меню и уход из приложения закрывают repeat; переход между окнами AgShell сохраняет его.
- **Windows-клавиша:** Win — независимый модификатор, а не псевдоним Ctrl. Системные сочетания может забирать Windows. Глобальная клавиша регистрируется с проверкой занятости и следует физической позиции на US, русской и Dvorak; смена раскладки учитывается перед клавишей. Настройка раскладки терминала подтверждает фактическое переключение и возвращает прежнюю раскладку после отключения.
- **Свои команды** выполняются через `cmd.exe /c` без окна, в каталоге панели, из которой вызваны (у сплита — его собственном, иначе основной панели); он же — `{AGSHELL_SESSION_PWD}`. Горячая клавиша берёт терминал с фактическим фокусом, включая scratch и выделение overlay; overlay передаёт роль покрытой панели. Палитра, поповер и API берут main либо сфокусированный split и его выделение. Палитра/поповер ждут при zoom, dashboard, pick или ask; горячие клавиши сохраняют отдельный путь. Detached stdin/stdout и stderr без захвата идут в NUL. С `--error-hud` stderr пишется во временный файл: последние 16 КиБ фиксируются при выходе процесса, файл удаляется без остановки фоновых писателей. При недоступном захвате команда всё равно запускается со stderr в NUL. В строке подставляются токены `{AGSHELL_SESSION_ID}`, `{AGSHELL_SESSION_NAME}`, `{AGSHELL_SESSION_PWD}`, `{AGSHELL_SESSION_HOST}` (ssh-адрес машины удалённой строки, пусто для своей сессии), `{AGSHELL_WORKSPACE_ID}`, `{AGSHELL_WORKSPACE_NAME}`, `{AGSHELL_WINDOW_ID}`, `{AGSHELL_WINDOW_NAME}`, `{AGSHELL_PANE}`, `{AGSHELL_PANE_ID}`, `{AGSHELL_SELECTION}` (выделенный текст), `{AGSHELL_PIPE}`; те же значения доступны и как переменные окружения. Токены подставляются за один проход: значение с `{...}` внутри, например выделение, остаётся как есть; неизвестный `{...}` тоже. Как в agterm, без сессии (в опустевшем окне) команда, где в любом виде упомянуты `AGSHELL_SESSION`, `AGSHELL_WORKSPACE` или `AGSHELL_SELECTION`, ничего не делает: пустой каталог мог бы направить её в корень диска; команда только с каналом, окном или панелью выполняется. `agshellctl keymap run ИМЯ` требует сессию (на неизвестное имя — `no custom command named ИМЯ`), а на команду, которая не запустилась, отвечает `ИМЯ did not start: …`. `agshellctl` есть в `PATH`. Если команда завершилась с ненулевым кодом, приходит уведомление, а с `--error-hud` ещё и HUD на 10 секунд, как в agterm: «имя: exit N» (или ошибка запуска), под ним — последняя непустая строка stderr без escape-последовательностей, всё обрезано до 256 символов. `--error-pane left` рисует его над левой панелью всегда, `right` — пока сплит на экране, иначе над всей сессией. Overlay с программой этот HUD не вытесняет.
- **Палитра**: Ctrl+Shift+O открывает список своих команд (и пустой, если их нет), в палитре действий они помечены `custom`. Рядом с действиями показаны все их текущие сочетания (шаги leader через `>`, альтернативы рядом), а у своих команд, как в agterm, сочетания так, как они записаны в keymap.conf (без отброшенных альтернатив, через `|`); так же их показывают поповер команд в заголовке и `keymap list`.
- **Copy/paste, Ctrl+Tab и Ctrl+1/Ctrl+2** не переназначаются: как в agterm, Ctrl+1 и Ctrl+2 переводят фокус на левую и правую панель и никогда не уходят в терминал; `map` или `command` с Ctrl+Tab или Ctrl+1/Ctrl+2 отклоняется как зарезервированное сочетание. Как в agterm, Esc в открытом переключателе Ctrl+Tab закрывает его без переключения; с зажатым Ctrl это сочетание Windows Ctrl+Esc, и пока переключатель открыт, а окно на переднем плане, AgShell забирает его себе, так что «Пуск» не открывается.

**hooks.conf**:

```
on status          C:\scripts\on-status.cmd
on session.closed  echo %AGSHELL_SESSION_ID% >> %TEMP%\agshell-closed.log
```

- **Виды событий** — те же, что у `events`: `status`, `notify`, `session.created`, `session.closed`, `session.selected`, `pane.split`, `pane.scratch`, `pane.focused`, `tree.changed`, `app.launched`, `remote.opened`, `remote.closed`. `tree.changed` приходит не чаще раза в 100 мс и сообщает только, что дерево изменилось.
- **Запуск:** строка выполняется через `cmd.exe /c` без окна. Событие приходит одной строкой JSON на stdin. Заданы переменные `AGSHELL_EVENT_KIND`, `AGSHELL_EVENT_STATUS`, `AGSHELL_EVENT_HOST`, `AGSHELL_SESSION_ID`, `AGSHELL_WORKSPACE_ID`, `AGSHELL_WINDOW_ID`, `AGSHELL_PIPE` (пустые, если у события такого нет), `agshellctl` есть в `PATH`.
- **Очередь:** у каждой строки своя очередь, события обрабатываются по одному. Слот освобождается после выхода процесса хука и закрытия его stdin; вывод направлен в NUL, потомок с унаследованным stdin не мешает отмене записи. `hooks.list` и `hooks.reload` отклоняют target или `--window` до выполнения. Дополнительные счётчики `runs`/`failures` сохраняются при перечитывании неизменившихся хуков. Если в очереди больше 256 событий, самые старые выбрасываются. О сбое хука приходит одно уведомление, следующее — только после успешного запуска.

## Боковая панель

```
agshellctl sidebar [visibility] show|hide|toggle      # visibility — подкоманда по умолчанию, как в agterm
agshellctl sidebar width 300                         # в пунктах, в пределах перетаскивания (160–560), как в agterm; печатает итоговую ширину. Сохранённая ширина вне пределов зажимается при запуске
agshellctl sidebar expand                            # развернуть все workspace, в том числе скрытые фильтром
agshellctl sidebar collapse                          # свернуть все, кроме текущего
```

Как в agterm, в плоском списке помеченных `expand` и `collapse` ничего не делают. Полноэкранный режим — `toggle_fullscreen` (F11).

## Кодировка

`agshellctl` пишет в UTF-8, а при выходе возвращает консоли прежнюю кодовую страницу. Чтобы PowerShell 5.1 правильно сохранял кириллицу в переменную, выполните перед этим `[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)`.
